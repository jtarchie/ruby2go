# Decision 411

**Rule:** In gem code a local that stores nil into an element is typed `Array[T?]` and its `Array[T]` value converted where assigned; a counted Range loop needs an Integer end (`1..Float::INFINITY` runs through `rbRangeEach`); and a gem's untyped `x.each(&block)` called without a block answers a lazy Enumerator over x's each.

**Bundled-gem backfill, second batch: prime's sieve** (2026-10-29). *See also decisions 233, 372, 410.*

`library/prime` went from 21 to 37 of 68 passing (decision 410 left it at 21). Each item was a wrong answer, not a missing feature: prime's `EratosthenesSieve` only runs past the 26 primes it caches, so the first batch's smoke tests passed while every spec that walks further failed.

- **`segment = range.step(2).to_a; segment[i] = nil`.** A gem method's locals with a nil element write (`nilElemLocals`, a syntactic pre-scan as decision 372's `growthLocals` is) are typed `Array[T?]` through `promotedType`, as if annotated, so the value converts at the assignment (`rbAs`) and the writes are static. ponytail: the conversion copies, so an alias of the assigned Array no longer sees the writes; a fresh value (`to_a`, `map`, a literal) is what this serves. A program's own local still needs its `#: Array[T?]`.
- **`(1..Float::INFINITY).each`.** The counted-loop fast path took any Range literal with both ends, but a Float end is stored as the Range's `inf` flag with `e` unset, so the loop ran zero times and the sieve found no composites (`compact!` then answered nil, MRI's own answer when nothing is removed, and `concat(nil)` raised). The fast path now needs an Integer end (`integerNode`); anything else keeps `rbRangeEach`, which honors the flags.
- **A lazy Enumerator for an untyped forward without a block.** Decision 410 made `x.each(&block)` with no block call x's each without one; for an untyped x that built the eager Enumerator, which collects every value first and never returned over prime's infinite generator. It is now `rbEnumOf` over a sequence that pulls one value at a time, as MRI's Enumerator does (a one-value each; another arity keeps the eager form).
- **Known gap:** the same forward on a *typed* receiver without a block evaluates to nil (decision 233's value for a gem iterator call), not an Enumerator; before decision 410 it called a nil block.
- **Proof:** `testdata/run/gem_lenient.rb`'s `sieve` and `upto_inf`; `library/prime`.

*See also decision 417.*
