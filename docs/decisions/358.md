# Decision 358

**Rule:** In an inference round, a call's untyped result whose method has parameters not yet typed from use does not widen the local it is assigned to; a user Struct with no member types, every `new` of it in its file passing each member positionally, takes its member types from its calls.

**Bottom until converged** (amends 146, 179; 2026-10-24). *See also decisions 146, 179, 355.* Two of spinel's benchmarks ran slower than MRI (`bm_send_rubyfunc_block` 0.4x, `bm_structaset` 0.6x) because everything in their loops was untyped:

- **A parameter typed through its own result.** `total = 0; total = obj.ruby_func(total + i)`: in round 1 `x` is untyped, so `ruby_func` returns untyped, so `total` widens to untyped, so `total + i` is untyped and no call ever types `x`. Spinel's fixpoint starts every slot at bottom, so an unknown result drops out of the join. Here: `inferRet` marks a method `roundRet` when, in a round, its return is untyped and one of its parameters is pending and untyped (or its body failed for that reason); a call to it gives an expr marked `provisional`, and `noteReassign` leaves the local's join alone for a provisional value. The round still compiles (the value is cast into the local's type), records `x: Integer`, and the next round types `ruby_func` as `Integer -> Integer`. A provisional value only skips a local's join in a round; the final compile joins what the typed method really returns, so a wrong guess is an ordinary "assigned both" error or union there. A parameter an earlier round left untyped (`inference.none`) is not awaited again: `def f(x) = x > 0 ? x : send(:g, x)` returns untyped even with `x: Integer`, so the local would widen and narrow on alternate rounds until `maxInferRounds`.
- **Struct members from `new`.** `TheClass = Struct.new(:v0, :v1, :v2, :levar)` with no `#:` had untyped members (decision 179's warning). When the Struct is in user code, has no `keyword_init: true`, and every reference to its constant in its file is a call receiver, at least one a `new` with exactly one plain argument per member and none a `new` with fewer, more, a splat, keywords or a block (`fullNews`), its generated `initialize`, `attr_reader`s and writers carry no signature: decision 146 types `initialize`'s parameters from the `new` calls, the ivars from those, and the readers from the ivars. The writers are `attrWriter`, so one no call types is untyped silently and does not widen its ivar. Members are required (no trailing `= nil`), which `fullNews` guarantees for that file. Member types written per line or as a tuple always win. Otherwise (a subclass, the class stored or passed, a short `new`) the members stay untyped with the warning. Data is not covered: its `with` copy takes the signature too.
- **Measured** (this Mac, wall): `bm_send_rubyfunc_block` 4.25 → 0.09 s (MRI 1.79), `bm_structaset` 0.75 → 0.11 s (MRI 0.46; spinel 0.015, its rest is calls through the class interface), `bm_structaref` 0.03 → 0.02 s.
- **Cost:** TestCompileCost unchanged (1,942, 7,624 compiled functions); examples 123 and 124 (`gen -trace`) unchanged at 9,607 / 13,561 functions and 334 / 454 dispatchers.
- **Not covered:** a short `new` of such a Struct from another file (`fullNews` reads the defining file only) fails to compile at that call where it used to run untyped (ponytail in `valueclass.go`).
- **Spinel benchmarks:** also `bm_rbtree` now compiles (== MRI), and `bm_linked_list`'s list helpers are typed.
- **Proof:** `infer_test.rb` `CycleTest`; `objects.txtar` `struct_members_from_new`, `struct_member_lines_kept` (per-line `#:` member types win over inference), `struct_short_new_untyped`, `param_typed_through_own_result`.

*See also decision 383* (the same bottom for ivars and for a method's return join in a round).
