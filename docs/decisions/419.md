# Decision 419

**Rule:** `sig/gems/prime/prime.rbs` corrects prime's shipped `each` members, which declare `{ (Integer) -> void } -> void` where the implementation reads the block's value and answers `break last_value`: the block is optional and returns untyped, and each's value is untyped.

**Bundled-gem backfill, ninth batch: prime's own signature** (2026-10-30). *See also decisions 306, 417, 418.*

Decision 418 left `Prime.each(1) { :value }` answering the generator, not nil. The cause was not the compiler: prime 0.1.4 ships `sig/prime.rbs`, and decision 306 types a gem's methods by it. It declares `Prime.each`, `Prime#each` and `PseudoPrimeGenerator#each` as `(...) { (Integer) -> void } -> void`, while prime.rb's `PseudoPrimeGenerator#each` does `last_value = yield prime` and `break last_value if prime > @ubound`, and returns `self.dup` without a block. With a void block the method compiled as a Go iterator, whose call answers its receiver (decision 172).

- **The fix is a vendored sig** (decision 306's precedence: the program's `sig/`, then `sig/gems/<gem>/`, then the gem's own, per member): `?{ (Integer) -> untyped } -> untyped` for the three each members. The rest of the shipped sig still types prime. No compiler change: reading a shipped sig as written is the rule, and a wrong one is corrected where rugaroo keeps its own.
- **Upstream:** the same three-line change (or overloads, six lines) to ruby/prime's `sig/prime.rbs` would make the vendored file unnecessary; not proposed without the user's go-ahead (CLAUDE.md, outward-facing).
- **`library/prime` is 48 of 68, none failing or erroring** (46 with 2 failing and 2 erroring). Two `should_receive` examples move from error to skip: their `mock('generator')` is now passed where the sig types a `PseudoPrimeGenerator`, a compile-time rejection of the same mspec partial mock (decision 416's limit).
- **Design limits left in `library/prime`, all in spec code:** `{ |p| break p }` in a block whose call's value is used (9, decision 241), blocks on untyped receivers (7, decision 172), `Prime.instance(1)`'s wrong argument count, a compile error rather than MRI's run-time ArgumentError (1, recorded by decision 421), and mspec mocks (3).

**Proof:** `TestPrimeVendoredSig` (compiles `require "prime"` as cmd/rubyspec does, runs it: `7`, `nil`, `[2, 3, 5, 7]`; fails without the vendored file), `library/prime`.

*See also decision 421.*
