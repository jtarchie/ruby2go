# Decision 352

**Rule:** A String the compiler knows is binary (`.b`, `force_encoding` of a literal BINARY, `binread`) calls byte-wise `__bin_*` twins; the flavor is compile-time only and is lost at any boundary it cannot follow.

**Binary-flavored Strings at compile time** (#83; amends 136 and 324; 2026-10-23). *See also decisions 136, 324.* Decision 136 keeps no encoding tag on a String, so `"é".b`, whose bytes are valid UTF-8, read as one character where MRI reads two (`size`, `[]`, `inspect`, `=~` with a byte pattern). A run-time tag stays rejected (a String is a named Go `string`); the compiler carries the flavor instead.
- **Producers.** A prelude method marked `# @binary` returns a binary String: `String#b`, `File.binread`/`IO.binread`, `read(n)` (`__read_1` of IO, File, StringIO), `readpartial`, `read_nonblock`, `Digest` `digest`, `Marshal.dump`, `SecureRandom.random_bytes`, `Random#bytes`, `Zlib` `deflate`/`gzip`, and `force_encoding` whose argument is a literal `"BINARY"`/`"ASCII-8BIT"` (any case) or `Encoding::BINARY`/`Encoding::ASCII_8BIT` (`literalOverload` picks `__force_encoding_binary`). `# @binary self` returns one when its receiver is: `dup`, `+@`, `-@`, `freeze`, `byteslice`, `*`, and the String-returning twins below. `bin + x` is binary when x is binary or an ASCII-only literal, as MRI's (other mixes are text here, where MRI may raise).
- **Flow.** The flag is on the compiled expression (`expr.bin`) and on locals: a local is binary when every write the first passes saw held a binary String (`localInfo.bin`/`text`), and each binary write read from another local stays binary only while that local is (`binDeps`, checked when pass 2 reads it), so a loop that later stores text into the source local turns both back to text. A `case` subject keeps it. `s.force_encoding(enc)` of anything but a literal BINARY makes the locals `s` was read from text in every read (MRI retags `s` in place); `s.force_encoding("BINARY")` as a direct statement of the method or block body makes its own scope's local `s` binary from the first pass on (under an `if` or a loop it may not run, so it does nothing: `noteBinStmt`); and `read(nil)` is not binary (MRI's is the external encoding). The MatchData of a binary match carries the flag too (`binCarrier`): its `[]`, `pre_match`, `post_match`, `string` and `to_s` are binary, and `begin`/`end`/`offset` count bytes (`MatchData.bin`, set by the twins and `rbMatchSetBin`). It is lost at a method parameter or return, an ivar, an Array/Hash element, a block parameter, and a `String?` receiver: there the String behaves as decision 136 says, and RBS signatures are unchanged.
- **Twins.** A call on a binary String, once overload resolution (decision 12) has picked the method or its `__<name>_<suffix>` twin, takes `__bin_<name>` (`overloadBase` spelling) or `__bin_<name>_<suffix>` when the String class defines it; otherwise the ordinary method runs. Defined: `size`, `length`, `[]` (Integer, `_2`, `_range`), `chars`, `each_char` (block and `_enum`), `ord`, `reverse`, `index`, `rindex` (byte offsets), `encoding` (ASCII-8BIT), `valid_encoding?` (true), `inspect` (`rbDump`'s byte form, `"\xC3\xA9"`), `=~`, `match`, `match?`, `scan` (and `_groups`, `_any`, `_block`), `split` (`""` and `_regexp`), `[]` and `index`/`rindex` with a Regexp (`_regexp`), `sub`/`gsub` (`_regexp`, `_block`), `tr`, `delete`, `count`. `# @binary block` marks a twin whose block's String parameters are binary too (`bin.gsub(/./) { |m| m.ord }`; `genClosure` binds them with `binParams`). A Regexp's `=~`, `match`, `match?` and `===` with a binary argument take the Regexp twins, so `when /re/n` on a binary subject does too. `p bin` with one argument is Kernel's `__bin_p`. In a method that reads `$~`, `bin =~ re` sets it through `rbMatchSetBin` (a byte index) and `bin.gsub(re) { }` runs `rbReSubBin` with binary block params. `tr`, `delete` and `count` twins read their character lists as bytes too. Whether a Regexp is fixed to UTF-8 is computed once when it is built (`Regexp#u8`, `rbRegexpUTF8`, skipping escaped backslashes). Twin matching reads each byte past ASCII as the character of its value (`rbFindLocBin`, decision 324's Latin-1 view, forced even on valid UTF-8; an all-ASCII subject matches as usual), and `=~` returns a byte index. A Regexp fixed to UTF-8 (a non-ASCII character, `\u`, or a `\x` escape past 0x7F in its source, without /n) on a binary subject with a byte past ASCII raises MRI's `Encoding::CompatibilityError` ("incompatible encoding regexp match (UTF-8 regexp with BINARY (ASCII-8BIT) string)"; `rbHighBytes`).
- **Regexp escapes.** Without /n, a run of `\xHH` escapes past 0x7F is the UTF-8 it spells: `/\xc3\xa9/` matches "é" (Go read `\xC3` as U+00C3, so it never matched), and a run that is not valid UTF-8 (`/\xff/`) is a compile error, MRI's SyntaxError "invalid multibyte escape" (`multibyteEscapes`; static literals only). A file whose magic comment makes its source binary (`# encoding: binary`), where MRI takes `/\xff/` as a byte, is not told apart: none of the vendored or brew gems with such a comment has a `\x` escape past 0x7F in a regexp (checked 2026-10-23).
- **Cost.** None for programs without binary Strings: the twins are prelude methods the pruner drops when nothing calls them (decision 49). Measured (TestCompileCost, compiled functions): 05_word_count 1,941 → 1,941, 64_observable 7,618 → 7,623, 116_cuba_web 29,766 → 29,781 (the String helpers now call the byte helpers the twins share: `rbStrAt`/`rbStrSub`/`rbStrRange`, `rbTr`, `rbScanLocs`, `rbSplitLocs`, `rbReplaceLocs`); unchanged after the producers, `p`, `+` and the regexp escapes. Computing `Regexp#u8` at construction (instead of rescanning the source on each binary match) adds one function to every program with a Regexp: 1,942 / 7,624 / 29,782.
- **Differs from MRI:** a binary value through a method parameter, ivar or collection reads as text again (a String that is not valid UTF-8 still reads as bytes, decision 324); a mixed local (`s = x.b` then `s = "é"`) is text in all its reads; `s.force_encoding("BINARY")` inside an `if` or a loop, or on another scope's local, does not make `s` binary (assign its result instead); `/i` on binary data does not fold bytes past ASCII in MRI but folds their Latin-1 letters here; `"é".byteslice(0)` is binary here and UTF-8 in MRI; a `\xHH` Regexp's `encoding` is still US-ASCII where MRI says UTF-8.
