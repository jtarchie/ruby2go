# Decision 268

**Core container corrections: Array#<=>, Hash#merge/to_h, Range#include?/==** (#101; amends 5, 165, 236; 2026-10-14).
- `Array#<=>` returns the sign of the length difference after a
 common prefix (-1/0/1). It still raises `ArgumentError` where MRI
 answers nil for incomparable elements: the signature is `Integer`,
 and `rbCmp` and sort rely on it (an `Integer?` would force nil
 handling on every `a <=> b` and slow sorts).
- `Hash#merge` (typed, block form and the dynamic view path) starts
 from `dup`, so `default` and `default_proc` survive, as MRI's
 `rb_hash_dup`. The view protocol gains `_dup` (an 8th Hash accessor).
- `Hash#to_h` is self, as MRI's and as the view path already was. A
 subclass's embedded Hash cannot tell it is one, so `to_h` there
 returns the embedded Hash, not MRI's plain copy (decision 165: not
 yet).
- `Range#include?`/`member?` iterate String ranges with `rbStrUpto`, as
 `rb_str_include_range_p` (`("a".."z").include?("bb")` is false;
 endless/beginless raise `TypeError`). Everything else stays
 `cover?`, which matches MRI for numbers and Time (Date-like
 `succ` types still use `cover?`).
- `Range#==` compares ends with `==` and handles other instantiations
 through the untyped view, so `(1..2) == (1.0..2.0)` is true. `eql?`
 still uses `eql?` on the ends.
- Not done: multi-argument `Hash#merge`/`update`.
