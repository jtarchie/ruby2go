# Decision 383

**Rule:** In an inference round, a method with a parameter not yet typed from use leaves its untyped returns out of its return join while a typed one remains, until the rounds converge with that parameter still untyped; a round's provisional value neither declares nor widens an ivar; a user class body's unannotated `@x = <scalar literal>` types the class object's ivar when no method's write does.

**Bottom until converged, for ivars** (amends 146, 307, 322, 358; 2026-10-26; #121). *See also decisions 146, 307, 322, 358.* An ivar typed only through a call whose parameter it types stayed untyped:

```ruby
@root = nil
@root = meld(@root, node)   # meld(a, b): `return b if a.nil?` ... `a`
```

Round 1 types nothing (`a` and `b` both pending). Round 2 knows `b: Node`, but meld's returns join `b`'s Node with the untyped `a`, so meld returns untyped, `@root` is declared untyped, `a` is only ever passed untyped, and decision 358's `none` stops awaiting `a`: `@root`, `a` and every call through them stayed dynamic. Decision 307's `lift` drops an untyped branch from an `if`'s value in a round; the method's own return join had no such rule.

- **Return join.** In a round (`c.round`), when a method has a pending parameter that is still untyped, `inferRet` leaves the untyped (`holdsAny`) returns out of its join if a typed one remains (`roundBottomReturns`). Round 2 types meld `Node`, `@root` becomes `Node?`, the call records `a: Node?`, round 3 types meld honestly. The final compile joins every return as before, so a wrong guess is an ordinary error or union there.
- **Unjustified drops stop.** A drop is a guess that the parameter will be typed. When the rounds converge (nothing else changed) and a parameter whose method's returns were dropped is still untyped, the guess never came true: it goes in `inference.noDrop`, the round counts as changed, and later rounds join that method honestly. Without this, liquid's `Utils.slice_collection(collection, from, to)` returned its `[]` literal's `Array[String]` in rounds, which typed `For#render_segment`'s `segment` from it; the final compile passed it an untyped Array of Hashes, the conversion raised, and the benchmark printed "Liquid error: internal". A first version that stopped a drop after two rounds of an untyped parameter was too eager: `@a = left(@b, x); @b = right(@a)` needs one more round for `@b` to come back typed.
- **Ivars.** As decision 358 does for locals, a round's provisional value (a call's untyped result whose parameters are still awaited) neither declares an ivar nor widens one: discovery leaves an undeclared ivar to its other writes (or to nil-only, untyped), and an ivar already declared takes the value as cast. Ablation: the return join alone types every shape in the tests; the ivar rule is the issue's 358 analog and moves no measured count (kept so a provisional write that comes before a typed one does not declare the ivar untyped, first write wins).
- **Class-body literals** (amends 322). spinel's `bm_getivar_module` (`module TheModule; @levar = 1; def self.get_value_loop ... @levar`) failed with "instance variable @levar has no known type": discovery dry-runs methods only, and decision 322 types a class-body write only when annotated. In a user file, an unannotated class-body `@x = 1` (Integer, Float, String, Symbol, true/false literal) now types the class object's `@x` after discovery, if no method's write has (`classBodyLits`): a `def self.set(v) = @x = v` still decides the type, as before. Gem files are unchanged (a gem's class-object ivar may hold anything later). bm_getivar_module == MRI, 1.62G instructions (MRI 10.4G).
- **Not covered:** an ivar typed through an identity call (`@a = keep(@a)` with `def keep(t) = t` and `@a = x` from a pending `x`): `t` is in `none` after round 1 and its method has no typed return to keep, so 358's rule (do not await a `none` parameter again) holds. A post-fixpoint retry that re-awaits `none` parameters would cover it at the price of extra rounds for every gem program with an untyped parameter (ponytail).
- **spinel's `bm_poly_cells`** still fails ("cannot assign Array[Integer] | Integer | String to @value, which is String"): an ivar reassigned another type is a compile error by design (`objects.txtar` `ivar_reassigned_other_type`, first write declares). Typing `@value` as the union of its writes (decision 150) is a separate decision.
- **Measured** (against d2a4ffb): `benchmarks/pairing_heap.rb` generates byte-identical Go, 5 `rbDyn` sites as before. Those 5 are not an ivar cycle: `NodeVisitor#visit_node(node)` is typed `Node[Integer, Integer]?`, but its local `node = stack.pop` with `stack << node.subheaps` widens to untyped in the gem (the same body in user code compiles typed): decision 307's "call-result narrowing" leftover, a follow-up. kramdown (`gen -trace`): identical, 982 dynamic-call warnings, 796 sites. liquid: 451 / 387 both (the five that the first, unguarded version removed were the unsound `segment` guess above); `Condition#initialize`'s `left`/`right` now take a union where they were untyped, 14,352 → 14,353 functions, output == MRI, instructions within noise (median 1.95G → 1.94G, paired, GOMAXPROCS=1). TestCompileCost unchanged: 2,014 / 7,730 / 30,289 compiled functions.
- **Proof:** `infer_test.rb` `IvarCycleTest` (the meld heap, an accumulator `@total = combine(@total, x)`, a two-ivar cycle `@a = left(@b, x); @b = right(@a)`, a module's class-body `@levar = 3`) against MRI; `TestIvarCyclesTyped` (the same classes compile with no dynamic call or untyped warning; all four were untyped or failed before); `TestNilLinksTyped`; `TestPairingHeapGemTyped`; the full suite.

*See also decision 392: an untyped value read back out of storage no longer declares a gem ivar; its typed writes do.*
