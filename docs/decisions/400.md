# Decision 400

**Rule:** Integer `+`, `-`, `*`, `/` and `-@` (and the `rbIntChecked*` helpers) report an overflow by panicking an `rbIntOverflowed` value, which `rbWrapPanic` turns into rbIntOverflow's RangeError, and a Struct writer's `__frozen_flag?` is the Go constant `false` in a program that never names `freeze`.

**Call overhead from spinel's benchmark suite** (amends 35, 387; 2026-10-27). *See also decisions 151 (Go panics as Ruby exceptions), 221 (frozen flag), 348, 372, 381.* Four rows of spinel's suite trailed spinel by about 3x on small methods: `bm_keyword_args` (0.018s vs 0.006s), `bm_inline` (0.098s vs 0.033s), `bm_structaset` (0.047s vs 0.017s), `bm_life` (0.088s vs 0.030s). Reading the generated Go, its `-gcflags=-m=2` inlining report and the disassembly:
- **Not keyword arguments.** `add(left:, right:)` already compiles to `rb_Add(left, right Integer)`: positional, no Hash. The cost was Go not inlining it.
- **The overflow check's call ate the inlining budget.** Go inlines a function whose cost is at most 80; any call to a function it does not inline costs 57 of that. `Integer#+`'s slow path was `rbIntOverflow(self, "+", other)` (go:noinline, to keep `+` itself inlinable), so `+` cost 79 and any method around one `+` (`rb_Add`, 83) was a real call: the caller's loop variables spilled to the stack around it. A `panic` costs 1. `+`, `-`, `/`, `-@` and `rbIntCheckedplus/minus/neg` now `panic(rbIntOverflowed{a, b, op})`, a three-field value; `+` costs 26, so `rb_Add` (30) and `Counter#increment` (49) inline. `rbWrapPanic` (which every `rescue`, the top level, threads, fibers, `Timeout` and the backtrace capture already run on a recovered value, as decision 151 did for Go's divide-by-zero and the regexp panics) builds the same RangeError, same message; `rbWrapPanic` records the frames as it converts (`rbCaptureBacktrace`, a no-op when nothing reads a backtrace), while the overflow's frames are still on the stack: a rescue that does not match re-raises the RangeError, so an outer `e.backtrace` and `RUGAROO_BACKTRACE` still start at `Integer#+` (the first version built a fresh exception there and lost those frames). Every other `rbIntOverflow` caller is a large function and keeps the call. The hot path is unchanged: the compare and the branch to a cold block.
- **`Integer#*` panics too** (#141, amended 2026-10-27). Its slow path was `rbIntMul`, a call returning the product for operands past 32 bits that may still fit, so it could not simply become a panic: the first version kept it (cost 78), and computing every product with `bits.Mul64` and `if` sign fixups (cost 51) cost 2.5% more instructions on `bm_inline` and was slower in wall clock. Now `*` (and `rbIntCheckedmul`) computes `r := self * other` and, only when an operand is past 32 bits, checks it exactly: the signed high word of the 128-bit product, `bits.Mul64`'s unsigned one minus `self>>63&other` and `other>>63&self` (no branches), must equal `r>>63`, else `panic(rbIntOverflowed{self, other, "*"})`. `bits.Mul64` is one `UMULH`, not a call, so nothing rejoins the hot path; `*` costs 60 and `rbIntMul` is gone. A method of one `*` inlines (`def sq(a) = a * a`: 82 → 64); one `*` and one `+` stays a call (110 → 92). Shapes measured (instructions / cycles, M; old → this): `bm_matmul` 249 → 205 / 38.3 → 36.8, `bm_inline` 1,250 → 1,210 / 190 → 183, `bm_life` 1,082 → 1,064, `bm_point_in_polygon` 1,496 → 1,515 (+1.3%) / 385 → 383 and under `--nil-check=runtime` 429 → 441 (+2.9%) / 146 → 132. The added instructions there are `NOOP`s: Go emits an inline mark for each inlined call and reuses an instruction on the caller's line when one is at hand; the old fall-through `JMP` was one, the new layout has none, so `first + 2 * k` retires two `NOOP`s per iteration that cost no cycles. Two other shapes lost: the fast path first (`if fits { return self * other }`, cost 61) laid the slow path out as the fall-through (`bm_point_in_polygon` runtime +5.6%, `bm_inline` +3.2% instructions), and the unguarded check (`bits.Mul64` on every product, cost 52, so `def dbl(a, b) = a * b + 1` inlines at exactly 80) cut `bm_matmul` further (184M, 32 cycles) but `bm_inline` ran 3.6% more cycles than before in two runs of 7 and 11, as the first version did, so it was dropped again. The overflow test (`TestIntOverflowValuePanic`) covers `*` past 64 bits, `MinInt * -1` both ways (where a division check `r/b != a` misses: Go's `MinInt / -1` is `MinInt`), and a product past 32 bits that fits; the formula was checked against `math/big` on the corners and 2M random pairs. `Vec2#length_sq` (two `*` and a `+`) stays over budget.

- **A Struct writer's raise was in its body.** `raise FrozenError, "can't modify frozen #{self.class}: #{inspect}" if __frozen_flag?` cost 253: the message's concatenation and its `to_s`/`inspect` calls count against the budget although `__frozen_flag?` is always false when the program never names `freeze` (decision 221: `rbObjFrozenFlag` returns nil). Go's inliner charges nothing for the untaken branch of an `if` on a constant, so `frozenFlagConst` (`expr_rewrite.go`) writes `__frozen_flag?` inside a Struct subclass as `Boolean(false)` in that case; the writer costs 13 and inlines. With `freeze` anywhere in the program, the check is unchanged. The decision is made at code generation, when every file is loaded, not when the Struct's members are collected (a later `require_relative`'d file may name `freeze`).
- **Measured** (instructions retired, M, macOS arm64, GOMAXPROCS=1, median of 5, old/new alternating; main at 1259c637 → this; spinel in brackets; hello world is 18M for rugaroo, 14M for spinel): bm_keyword_args 168 → 42 (−75%) [16], bm_inline 1,379 → 1,249 (−9.4%) [475], bm_structaset 147 → 106 (−28%) [61], bm_life 1,094 → 1,079 (−1.4%) [478]. Wall: bm_keyword_args 24.5 → 16.4 ms [14.1], structaset about half. `benchmarks/*.rb`: every row within ±1% except hash −2.4% and json +2.2% (−1.0% and −1.9% on two reruns: GC noise; wall 168.5 vs 168.7 ms); every row prints the same. `TestCompileCost` compiled functions: 2,055 → 2,058, 7,965 → 7,968, 30,312 → 30,315.
- **Not fixed, by cause.** `bm_inline`'s `length_sq` and `dot` stay calls: two checked multiplies and an add are over Go's budget, where C's `static inline` has none; per-program PGO would lift it (an opt-in, see the PGO experiment). `bm_life` is the value-block protocol: `OFFSETS.sum { OFFSETS.count { cell_get(...) == 1 } }` calls `Enumerable___SumBlock_onArray` (cost 531) and `CountBlock_onArray` (137), each element an indirect closure call. Pasting the block bodies into index loops by hand took it from 1,079M to 658M instructions and 88 to 57 ms (spinel 38 ms), filed as #140 (decision 387's counted loops, for blocks that return a value). Emitting `H = 40` as a Go `const` (spinel folds `y % 40` to a multiply) was tried by hand: more instructions, no wall-clock change on its own; it waits for #140.
- **Proof:** `TestIntOverflowValuePanic` (`rugaroo_test.go`: overflows of `+`, `-@`, `/` and `*` inside small methods, rescued with their message and backtrace line, through `ensure` and through a `rescue` that does not match, and uncaught at the top level with exit 1; also under `RUGAROO_INT_OVERFLOW=wrap`, where the file's `# int_overflow: raise` uses the checked helpers), `TestStructWriterFrozenConst` (the flag folds only without `freeze`); the struct writer's FrozenError stays covered by `object_test.rb`.
