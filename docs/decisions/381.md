# Decision 381

**Rule:** A file's `# int_overflow: mode` line governs only the Integer arithmetic written in that file, whichever file it is (the main file or one it `require_relative`s); every other file uses `--int-overflow` (default `raise`).

**Per-file overflow mode** (amends 372; 2026-10-26; #117). *See also decision 35.* Decision 372 read the comment from the files handed to the compile only and let the last one found replace the flag for the whole program, so a `require_relative`'d file's comment was ignored, two files with different modes were not reported, and a helper that wants `wrap` for a hash function turned the main program's checks off. MRI ignores the comment, so how far it reaches is rugaroo's choice; per file is how Ruby's own `# frozen_string_literal:` works, and it removes the conflict: two files with different modes are each compiled in their own.
- **Where the mode is read.** `parseFile` records a user or gem file's comment on the `File` (an unknown mode is a compile error naming the file); `fctx.intMode` is that, else the flag. Everything 372 made depend on promote mode asks it: loop-growth locals (`growthLocals`), `Integer#**` returning a Bignum and folding a constant power, and an Integer literal past 64 bits being a Bignum. So a Bignum is born only in a promote file; one that crosses into another file through a typed Integer parameter converts as 372 describes (`rbBignumToInt`, RangeError when it does not fit). The Bignum prelude loads when the flag or any file says promote.
- **Wrap per call site.** `wrap` used to be one prelude constant (`rbIntWrap`) the methods test, which is global. The constant still follows the flag, so the default build and a whole-program `--int-overflow=wrap` build are the same machine code as before. Where a file's mode disagrees with the flag on wrapping, `intOpCode` writes Integer `+`, `-`, `*` and `-@` on a typed Integer receiver itself: plain Go arithmetic in a wrap file, the checked `rbIntChecked*` helpers (the methods' own checks, copied) in a raise or promote file of a wrap program.
- **What stays program-wide.** The prelude and gems are compiled in the flag's mode, as are arithmetic on untyped values (`rbNumOp`) and Integer methods other than those four operators (`succ`, `abs`, `**` outside promote), as 372 already limited wrap to the four.
- **Measured.** The default build is the same code: `intOpCode` returns early unless a file's mode differs from the flag's on wrapping. `TestCompileCost` compiled functions unchanged.
- **Proof:** example 129 (a wrap file's FNV hash, a promote file's factorials, a default main file; equal to MRI in all three `--int-overflow` lanes), `numbers.txtar`'s `int_overflow_bad_mode`.
