# Decision 414

**Rule:** Without a boot snapshot a gem's autoload loads where it registers; gem code's element writes of another class widen an Array ivar's element, and a gem local's `Array.new(n, x)`, to what they hold, and branches whose same-class containers do not join give that container of untyped unless the untyped side is a literal; a core method's Float truncation applies only to a parameter declared Integer; `x.to_enum(:m, args)` is `x.m(args)` when m answers its own Enumerator, and to_enum also takes a method's alias, its rest param and a 2-4 value block; a tail `yield` in a block whose callee takes its value is a used value; a class with `to_ary` destructures through it; alias Methods are equal.

**Bundled-gem backfill, fourth batch: matrix's decompositions and enumerators** (2026-10-30). *See also decisions 175, 181, 236, 241, 323, 412.*

`library/matrix` (all subdirectories) went from 206 to 319 of 360 passing (`matrix` 274/302, `lup_decomposition` 18/19, `eigenvalue_decomposition` 11/13, `vector` 16/17). Each item is a general gap matrix exposed:

- **Autoload without a boot.** cmd/rubyspec compiles in-memory suites, so nothing boots (decision 409), and a gem autoload loaded only what boot resolved (decision 175): `autoload :LUPDecomposition, "matrix/lup_decomposition"` left the constant undefined. With no boot it now loads where it registers, as a require (`booted`).
- **A widened param that unfolds a branch.** `solve(b)` reassigns `b`, which widens it (decision 241); the first run had folded `b.is_a? Matrix` dead with b typed Vector, so the widened rerun met a live branch whose locals pass 1 never hoisted (`undefined: m`). The rerun now happens whenever a param widened, not only when the run raised.
- **`super` in `initialize_copy`** is Object's no-op, as `initialize_dup`'s is (decision 232); the shallow copy is already done.
- **`transpose` of untyped rows** (`@rows.transpose`): an `@self Array[X]` sibling and the untyped view's `transpose` (decision 236), both through `rbTransposeAny`; a non-Array row is MRI's TypeError.
- **Float truncation only for a declared Integer.** Decision 181's NUM2LONG truncation also hit `[]=`'s element `E` bound to Integer, so `a = Array.new(2, 0); a[0] = 1.5` stored 1 silently. Now user code gets the compile error (`testdata/errors/numbers.txtar`), and gem code widens (next item).
- **Element writes widen a gem's Array ivar.** eigenvalue_decomposition's `@d = Array.new(n, 0)` then `@d[i] = Math.sqrt(x)` or an untyped value: discovery makes `@d`'s element untyped at the depth the `[]` reads reach (`@v[i][j] = 0.5` widens the rows). Discovery is checked by value type, since pass 0 accepts a Float where an Integer is expected (pass 2 rejects it).
- **Container joins in gem code.** Decision 323's `untypedContainerJoin` gave an untyped container the typed sibling's elements; it now does so only when the untyped side is an Array or Hash literal (`cond ? dir.children : []`, brew's `[nil, []]`), recorded per branch (`tail.lits`). A computed one (`Array.new(n) { @v[j][i] }` beside `Array.new(n) { Complex(...) }`) keeps untyped, and two same-class containers that do not join otherwise (`Array[Integer?]`, `Array[Complex]`) are that container of untyped instead of poisoning the method.
- **`x.to_enum(:each, :diagonal)`** with an explicit receiver is `x.each(:diagonal)` without a block when `each`'s body answers its own Enumerator (`enumsItself`); any other method keeps to_enum's dynamic dispatch. `to_enum` inside a method whose block takes 2-4 values yields Tuples, as MRI packs them (`each_with_index`'s `e, row, col`).
- **`Array.new(n) { |i| yield i }`.** A tail `yield` in a block whose callee takes the block's value (`blockValueTaken`: map, select, Array.new, ...) is a used value, so the method's block returns a value instead of void; `Matrix.build` had answered a Matrix of nils.
- **`row = Array.new(size, 0)`** in gem code is seeded open as a literal is (decision 193): matrix's diagonal then stores `values[j]`, untyped, and Rationals reach those rows later through `@rows`, so an untyped write makes it `Array[untyped]` (`filled`) and the fresh value converts where it is assigned. A program's own `Array.new(n, 0)` keeps its element type.
- **`return row, col` from a block** of a gem method unwinds as one value does (decision 247): `[row, col]`.
- **Destructuring through `to_ary`.** `v, d, v_inv = eigensystem` was a compile error for a class defining `to_ary`; it now splits what `to_ary` answers.
- **An untyped Enumerator's `each`** (`each(:strict_upper).all?(&:zero?)` with each answering an Enumerator or self): `rbEachAny` iterates it.
- **Alias Methods are equal**, as MRI compares the definition: a def's Method key is its position, not its name (`Matrix.method(:I) == Matrix.method(:identity)`, `det`/`determinant`); attr methods, which share their call, keep the name.
- **Numeric's long names** `real`, `imaginary`, `conjugate`, `rectangular` on Integer, Float and Rational (the short `imag`/`conj`/`rect` were there; `real` was missing).
- **`Matrix.instance_method(:collect) == instance_method(:map)`** failed `go build`: an UnboundMethod bound to its definition called a method with an optional block without the block's Go parameter; it now passes nil, before a rest's.
- **`r.column(0)` on an untyped Matrix.** A method with an optional block got a dynamic wrapper only when some dynamic call passed a block; it now gets one when called without, taking nil (decision 243's optional block).
- **A gem's `a, b, c = obj` through to_ary** of an interface class's Array (`v, d, v_inv = eigensystem`): each target its element, nil past the end, since a `*MatrixI` is not a receiver later calls take.
- **The widened-param rerun** runs when the body type-tests the param (`is_a?`, `kind_of?`, `instance_of?`, `case`), the fold that can hide a branch; rerunning after every widening lost pairing_heap's types (`TestPairingHeapGemTyped`).
- **ruby/spec's `x.should.unitary?`** form (any predicate) is answered by cmd/rubyspec's `SpecExpectation#method_missing`, as mspec's.
- **Cost:** TestCompileCost compiled functions 2058→2060, 7923→7925, 30333→30375 (generic instantiations of the untyped Enumerator case and the new numeric methods).
- **Design limits left in `library/matrix`:** `bignum_value` (no Bignum by default, decision 35; 4 examples); `Float#round(digits)` with a non-literal digits ≤ 0, whose class depends on the value; blocks on untyped receivers and splats of a union in spec code (user code stays strict, decision 172); the spec's `be_close_to_matrix` matcher object; `Method#call` with a block.
- **Known gaps:** a typed Array reached through untyped (eigenvalue_decomposition's rows, `Array.new(n, 0)` inside a block returning untyped) still holds only its element class, so storing a Float into it is decision 20's TypeError; `eigenvector_matrix` hits it. rbConv's Integer-into-Float widening also applies to each element of a converted copy, so such a copy prints `0.0` for MRI's `0`.
- **Proof:** `testdata/test/enumerator_test.rb`'s `SheetTest`; `testdata/run/gem_lenient.rb`'s `Mx`; `testdata/errors/numbers.txtar`'s `float_into_integer_element`; `TestGemAutoloadWithoutBoot`; `library/matrix`.
