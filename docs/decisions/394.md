# Decision 394

**Rule:** In an inference round, an attr writer's write of its still-untyped parameter neither declares nor widens the ivar, so typed callers' `obj.x += n` type the parameter through the ivar's other writes; a non-nil value initialize's statements store (directly or through a self call that is a statement) makes no later method's read a read-first nil.

**Ivars typed through their attr writers** (#137 follow-up; amends 146, 148, 307, 383; 2026-10-26). *See also decisions 146, 148, 307, 383, 392.* liquid's `ResourceLimits` keeps its counters in ivars `reset` sets from `initialize` and the render loop bumps through `attr_accessor` writers:

```ruby
attr_accessor :render_length, :render_score, :assign_score
def initialize(limits) = ...; reset
def reset = @render_length = @render_score = @assign_score = 0
# BlockBody#render
context.resource_limits.render_score += @nodelist.length
```

The writer's parameter is typed from its calls (decision 146), but the only typed call passes `reader + n`, the reader returns the ivar, and the ivar was declared from the writer's own write of its untyped parameter: a cycle with no way in. Every `+=` and `>` on the counters went through the dispatcher.

- **Writer parameter, bottom until converged** (the decision 383 rule for ivars, applied to a parameter). In a round (`c.round`), an attr writer's `@x = x` while `x` is still pending and untyped is a provisional value (`awaitedWriterParam`): it neither declares the ivar (discovery leaves it to the ivar's other writes, here `reset`'s `0`) nor widens it. The reader then returns Integer, the caller's `Integer + Integer` records `x: Integer`, and the next round's writer is typed. The guess lives only in rounds: the final compile writes the parameter as typed from its callers, and a dynamic call reaches the writer through its Dyn wrapper's cast, as every inferred gem parameter already is (decisions 169, 225). A parameter still untyped when the rounds converge (no typed caller: liquid's `assign_score=`, called only on an untyped `context`), or one whose callers join to untyped (decision 244), never justified the guess: `stopUnjustifiedDrops` puts it in `noDrop` and later rounds write it honestly. The second case is new for 383's return drops too (they checked only "no type at all").
- **Why not the unsound version.** Decision 392's first draft typed these ivars by deferring every untyped write, which also typed liquid's `Cycle#@name` from an untyped method return that is really a `VariableLookup`. Here only a writer's own parameter defers, and only while inference may still type it from typed callers; an untyped return still declares.
- **Construction writes first.** Decision 148 declares an ivar `T?` when discovery reads it before any write. Discovery dry-runs `initialize` first and the rest in source order, so the attr reader `render_score` (line 3) read the ivar before `reset` (line 19) wrote it: `Integer?`, a `Ref` allocation per `+=`. A read is no read-first nil when initialize's statements (or a self call that is one of them, `reset`, transitively) set the ivar to a non-nil value (a literal other than nil, a constant's `new`, through `@a = @b = 0` chains) and the reading method is not one initialize can run (any self call it or those methods make, through the superclasses' initialize) (`initWritesOf`). `@tree = opts[:tree]` in kramdown's `reset_env` may store nil, so it does not count; kramdown's generated Go is byte-identical.
- **Chained writes.** `@a = @b = 0` with `@b` untyped typed `@a` from `@b`'s untyped field. An ivar write whose value is an immediate literal (Integer, Float, Symbol, true, false) has the literal's type when the ivar is untyped (`immediateLit`), as MRI's value is the literal.
- **kramdown's `@options`** (`Parser::Base#@options = Options.merge(options)`, 57 dynamic-call lines naming `@options`). The gem ships no `sig/`; `merge` returns `defaults.dup`, and `defaults` is built from the `Kramdown::Options` module's class-body `@options = {}` / `@defaults = nil`, which a gem module leaves untyped (decisions 172, 383). The vendored sig (`sig/gems/kramdown/kramdown.rbs`, decision 160) declares those two (`self.@options: Hash[Symbol, Kramdown::Options::Definition]`, `self.@defaults: Hash[Symbol, untyped]?`), and inference does the rest: `merge` returns `Hash[Symbol, untyped]`, so do the parsers' and converters' `@options`. Typing them made `Document#to_*`'s dynamic `Converter.const_get(name).convert(@root, @options)` pass a typed Hash, which as a dyn use (decision 331) untyped `Parser::Html::ElementConverter.convert`'s `el` (+43 `rbDyn`); the sig also gives that method its type, which every caller under MRI satisfies (`(Kramdown::Element root, ?Kramdown::Element el)`). Typing a gem module's class-body `{}` from its uses would be the general fix (ponytail: decision 15's refine for class-object ivars of gem modules).
