# Decision 387

**Rule:** The prelude's `Integer#times`, `#upto`, `#downto` and an Integer Range literal's `each` compile to plain Go `for` loops, a statement `Array#[]=` stores in place at the site when the index is in bounds and the Array not frozen, `T? == T` for Integer, Float, Symbol and String (decision 399) compares without boxing, `Array#==` of two Integer Arrays is `slices.Equal`, and a Struct writer checks the object's frozen flag rather than calling `frozen?` (`RUGAROO_NO_COUNTED_LOOP=1` turns the loops and the store off).

**Loops from spinel's benchmark suite** (amends 348; 2026-10-26). *See also decisions 4, 7, 221, 348, 377, 389, 391* (guarded shift/pop, inline push), *399* (String? == String). spinel's own suite (BENCHMARKS.md) had rows where rugaroo was 4.7 to 17 times slower than spinel. Reading the generated Go and its disassembly for eight of them:
- **A loop body Go would not inline.** `4000.times { |j| a[i] = a[i] + j % u }` ranged over `Integer#times`'s iterator. Go inlines the iterator, but the body closure only when it fits the inliner's budget (80); this one cost 300, so every element was an indirect call of the body plus range-over-func's state checks. Decision 348 measured the protocol at ~1.3 ns per element on a small body and declined a general yield inliner; a body past the budget is the case it did not see. `countedLoopHead` (`internal/compiler/counted_loop.go`) emits the loop itself for the prelude's `times` (`for i := range Integer(n)`, which copies, so a block that assigns its param is fine), `upto`/`downto` (receiver and limit evaluated once, before the loop; `i >= from` stops the wrap past MaxInt, as the iterator's own check did) and `(a..b).each`/`(a...b).each` on an Integer Range literal (its bounds read into locals: Go reloaded the struct's fields each iteration). `break`, `next` and `redo` mean the same in a Go `for` as in a range over a func. Not lowered: a block that assigns its param (upto/downto/each, where the param is the counter), a Range value (its endless and exclusive flags are run-time), any other iterator.
- **`Array#[]=` over the inliner's budget.** Its slow path (negative index, growth, the frozen check's FrozenError) made it cost 340; with the in-bounds case first and the rest moved to `rbArrayIdxSet` it still costs 94, as a generic call alone costs about 70. `inlineIdxSet` (`internal/compiler/inline_idxset.go`, a Go-AST pass in `formatGo` after the prune) rewrites each statement `Array_Op_idxSet[T](a, i, v)` to `if a, i, v := ...; uint64(i) < uint64(len(a.s)) && !a.frozen.Load() { a.s[i] = v } else { Array_Op_idxSet[T](a, i, v) }`; the init keeps the arguments' order, and an untyped constant argument gets its parameter's type. It applies only when `Array_Op_idxSet` is the prelude's own body (its slow path calls `rbArrayIdxSet`): a program that defines its own `Array#[]=` has every store call it, as MRI does (`testdata/run/array_idxset_override.rb`; the first version skipped the override for in-bounds stores).
- **`flags[i] == 1` boxed both sides.** An `Integer?` receiver's `==` went through `rbEq[any]`: two conversions to `any`, an unbox switch, an interface lookup. `plainOptEq` sends Integer?, Float? and Symbol? compared with a value of the same class, whose `==` is the prelude's, to `rbOptEq` (`p != nil && *p == v`).
- **`Array#==` boxed each element** through `rbEq`. Two `[]Integer`s now compare with `slices.Equal`, unless the program redefines `Integer#==` (`emitProgram` flips `rbIntEqGo`).
- **A Struct writer called `Kernel#frozen?`** (the receiver boxed to `any`, then a type assertion to `rbFreezable`) on every `obj.x = v`. It now calls `Struct#__frozen_flag?`, the object's own flag, which is constant false in a program that never names `freeze` (decision 221) and MRI's check besides: MRI's writer calls `rb_check_frozen`, not a `frozen?` override.
- **Tried and dropped.** Testing `+`/`-` overflow by the sign of `(a^r)&(b^r)` (two instructions fewer than comparing) made `bm_nested_loop` 4.7 times slower: Go proves `x + 1` from the comparison form, not from this one.
- **Cost.** `TestCompileCost` compiled functions: 05_word_count 2,014 to 2,014, 64_observable 7,916 to 7,918, 116_cuba_web 30,366 to 30,354.
- **Measured** (instructions retired, GOMAXPROCS=1, median of 3; spinel in brackets): bm_loops_times 2,077M to 579M (320M), bm_range_each 30,884M to 11,523M (5,516M), bm_sieve 1,251M to 369M (211M), bm_structaset 716M to 146M (60M), bm_life 2,177M to 1,094M (478M), bm_so_lists 6,017M to 4,383M (282M); bm_partial_sums 2,644M and bm_nested_loop 179M unchanged (316M, 14M). `benchmarks/`: within noise except collections 1,541M to 1,392M and exceptions 1,386M to 1,276M.
- **Not fixed, by cause.** bm_partial_sums spends 2,050M of its 2,644M in `Float#**`: `rbFloatPow` is correctly rounded (MRI's libm pow is, Go's `math.Pow` is not) by double-double series, ~820 instructions a call; a table-driven log/exp with a rounding test, falling back to the series, would keep the result (done: decision 390, 2,644M to 938M). bm_so_lists's `li3 = Array.new` stays `Array[any]`: `li2.push(li3.pop)` pushes an `Integer?` into an `Array[Integer]`, which only flow typing (the loop runs while `li3` is not empty) can prove non-nil; typed by hand it runs in 2,392M, the rest in `shift`/`pop` allocating each `E?` they return. bm_nested_loop is six counted `while` loops around `x = x + 1`; Go emits about 7 instructions per iteration, the C compiler under spinel folds the loops.
- **Found on the way:** `x = a[-1]; a.pop; a.push(5); p x` prints 5 (MRI 3), and `h[:k] = a[0]; a[0] = 9` changes `h[:k]`: `Array#[]` answers a pointer into the Array's storage, which a kept `E?` goes on seeing (pre-existing).
- **Proof:** `control_test.rb` `ControlCountedLoopTest` (empty and negative counts, exclusive ranges, `break`/`next`, a `break` out of a `case` inside the loop (a labeled Go break, whose label sits below the loop's temps), a block assigning its param, closures keeping their own element, bounds at MaxInt and MinInt, receiver and limit evaluated once) and `array_test.rb` `ArrayIndexStoreTest` (negative, growing, frozen and out-of-range stores, an Integer into a Float Array, nil into an `Integer?` Array, `T? == T`, Integer Array `==`), against MRI; the struct writer's FrozenError in `object_test.rb`.
