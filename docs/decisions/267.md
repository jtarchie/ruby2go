# Decision 267

**Rule:** `each_cons` streams over `each`; `minmax` is one pass with MRI's tie order; Lazy also has `grep`, `chunk_while`, `slice_when` and kin.

**Enumerable and Lazy: streaming each_cons, one-pass minmax, more lazy steps** (#101; 2026-10-14).
- `Enumerable#each_cons(n) { }` slides a window over `each` instead of
 calling `to_a`, so endless ranges and generators stop on `break`
 like `each_slice`. It still returns void: iterator methods cannot
 return `self` (decision 4).
- `Enumerable#minmax` is one pass over `each` with MRI's pair ordering
 (enum.c `minmax_i`): a side-effecting `each` runs once, and ties
 keep the earlier element.
- `Enumerator::Lazy` gains `find_all`, `grep`, `grep_v` (block form via
 `__grep_block`/`__grep_v_block`), `collect_concat`, `chunk_while`
 and `slice_when`: they stay lazy and return a Lazy on infinite
 sources, and `collect` is labelled "collect". Steps are named as in
 MRI (`grep(2..5)`) through `__relabel`. The chunking steps' inspect
 shows `:chunk_while` where MRI prints a Generator address.
- Eager `Enumerable#grep`/`grep_v` accept a block through the same
 twins (it was a compile error).
- Proof: `enumerator_test.rb` StreamingTest and LazyMoreTest.
