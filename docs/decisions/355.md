# Decision 355

**Rule:** An unannotated recursive method's return type is the join of its non-recursive return paths, then iterated with the recursive calls typed as that join until it stops changing.

**Recursive returns are inferred** (amends 36; 2026-10-23). *See also decisions 36, 146.* spinel's `bm_binary_trees.rb` (copied unmodified to `benchmarks/binary_trees.rb`) failed with "method make_tree is recursive; annotate its return type": decision 36 inferred a return by a dry run of the body, and a call to the method being inferred had no type yet. User code must run on MRI unchanged, and the benchmark has no annotations.
- **How** (`inferRecursive`, `signatures.go`). A dry run that meets a call to the method it is inferring (direct or through another unannotated method: `even?`/`odd?`) marks it `recursed` and fails as before. `inferRet` then runs the body again with `dropFailing`: every statement, at every nesting level, that does not compile is left out, and the returns it half-recorded with it, so the recursive call's unknown value drops out of the join, as spinel's inference does. The join of what survives is the candidate (`make_tree`: `Node`, from `return Node.new(nil, nil)`; `fact`'s ternary: `Integer`). The body is then compiled normally with the method's return set to the candidate, and the join of its returns replaces it until two runs agree (at most 4; `maybe(n + 1) || n` with a `nil` base goes `nil` → `Integer?`). The last run's returns feed the usual join and its errors. Each run first clears the inferred returns of methods that had none when the fixpoint began: in a cycle of three (`a` → `b` → `c` → `a`), `c` typed itself against `a`'s first candidate and kept a stale `nil`.
- **Errors.** No path returning a typed value without recursing (`def spin(n) = spin(n + 1)`) is "method spin is recursive and no path returns a typed value without recursing; annotate its return type"; a join that does not settle in 4 runs names the last type. In an inference round (decision 146) a failure is `untyped` as before, so callers still record their arguments. Gem code keeps its untyped inner call (bindata's `superclass.dsl_parser`). Known limit: a real type error in a statement the first run drops (after the recursive call) shows up as "no path returns a typed value" when no other path is typed, not as itself.
- **Cost.** Only methods that recurse take the extra runs (three dry runs of their body instead of one); a program without recursion runs nothing new. TestCompileCost compiled functions unchanged against main: 05_word_count 1,942, 64_observable 7,624, 116_cuba_web 29,782.
- **binary_trees** now compiles with no dynamic call: `make_tree` returns `Node`, `check_tree` `Integer`, and Node's `left`/`right`, written from `Node.new(nil, nil)` and `Node.new(make_tree(d), make_tree(d))`, are `Node?` (decision 146's join). `RUNS=5 scripts/benchmark binary_trees`: MRI 0.081 s, rb2go 0.012 s (6.8x).
- **Proof:** `testdata/test/infer_test.rb` `RecTest#test_recursive_returns` (direct, ternary, mutual, a three-method cycle, `nil` base with `||`, a recursive tree builder and counter), `testdata/errors/objects.txtar` `inferred_return_recursive` (no typed base path), `TestSpinelBenchmarksTyped` (rb2go_test.go: no `rbDyn` and no dynamic-call warning in either spinel benchmark).
