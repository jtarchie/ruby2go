# Decision 402

**Rule:** A call of the prelude's `Array#count { }`, `Array#sum { }` (Integer or Float values) or `Array.new(n) { }` with a literal block, reached first in its statement's evaluation, compiles to an index loop before the statement with the block's body pasted in, unless the block rescues, assigns its parameter or a program redefines the method (`RUGAROO_NO_COUNTED_LOOP=1` turns it off).

**Value blocks as loops** (amends 387; 2026-10-27; #140). *See also decisions 4, 241, 348, 372, 377, 387, 401.* Decision 387 lowered `times`/`upto`/`downto`/Range `each`, whose blocks return nothing. A block whose value is used is a Go closure the prelude's helper (`Enumerable___CountBlock_onArray`, `Enumerable___SumBlock_onArray`, `Array_Meta___New1`) calls per element; Go inlines it only under its budget of 80, so spinel's `bm_life` (`OFFSETS.sum { |iy| OFFSETS.count { |ix| cell_get(...) == 1 } }` inside `Array.new(SIZE) { |i| ... }`) paid an indirect call per neighbour with the loop state spilled around it: 1,082M instructions against spinel's 478M.

- **Where.** `inlineBlockLoops` (`internal/compiler/inline_blockloop.go`) is a Go-AST pass in `formatGo`, after `specializeSelf` names the `_onArray` helpers and beside decision 387's `inlineIdxSet`. Working on the generated Go, not in codegen, reuses everything codegen already settled: the block's typed value, `next v` and a bare `next` (the closure's `return`, nil already coerced to the block's type), a `break` out of a call statement (decision 241's `rbBreak` panic, recovered around the statement either way), and the helper's own Go instantiation (its type arguments say whether a sum is Integer or Float).
- **The loop.** count and sum: `a := recv; for i := 0; ; i++ { if i >= len(a.s) { break }; x := a.s[i]; body }`, the length re-read each step as `Array#each` and MRI's `rb_ary_count`/`ary_sum` do, so a block that appends, pops or clears the receiver sees the same elements (no mutation analysis). count adds one per true value (the block's Boolean); sum makes the prelude's own calls, `t = t.Op_plus(v)` (the checked `+`, so every `--int-overflow` lane and a redefined `Integer#+` behave as before) or `rbSummer{floating: true}.addFloat` (MRI's Kahan-Babuska, NaN and infinity rules) with `Float(s.f + s.c)`; any other value type keeps the helper. `Array.new(n) { }` calls the helper without a block (its negative-size and size-limit checks, then n zero slots) and sets each slot: the block cannot see the Array, so filling it equals MRI's growing it.
- **The body.** The closure's statements move into the loop. When its only return is its last statement the value feeds the accumulator directly; otherwise a `var v T` takes each `return e` as `v = e; goto next` (the body wrapped in its own block so the goto jumps over no declaration), returns ending an if/else chain at the end fall through without a jump, and returns inside nested closures stay theirs. Its param is bound per iteration only when the body reads it (by the parser's object, so a nested closure's same-named param is not a read).
- **Not lowered.** A closure with a `defer` (a `rescue` in the block: it would run at the enclosing function's exit), a named result or bare return, a param the block assigns (decision 387's exclusion; for `Array.new` the param is the slot index), a label another closure of the same function also uses, `&blk`/`&:sym` blocks (their closures are not literals at the call), a Float/Integer union sum, a call nested in another lowered call's receiver or arguments, a param the parser did not resolve.
- **Which calls.** A statement's own evaluation order decides: `return C`, `x := C`, `x = C`, `C`, an if/switch head without init and a range expression are scanned left to right through operands, conversions, composite literals and call arguments to the first lowerable call; anything with an effect before it (another call, a possible panic such as an index or a division, the right side of `&&`/`||`) stops the scan, as the hoisted loop must not overtake it. So `assert_equal 3, xs.count { }` and `puts xs.sum { }` lower; `"#{a.to_s} #{xs.count { }}"` (a call before it) does not.
- **Overrides.** A helper counts as the prelude's only when its body still makes the prelude's call (`Each`, `addFloat`, `Array_Meta___Zeros`), as `preludeIdxSet` checks; a program's own `Array#count`/`#sum` taking a block is a different function and every call runs it (`testdata/run/array_count_override.rb`). A program's own `Array#each` no longer reaches count/sum through the loop: MRI's C count and sum do not call `each` either.
- **Backtraces.** As with decision 387's loops, `RUGAROO_BACKTRACE` shows no `Enumerable#count` or block frame for a lowered call: the code is the caller's.
- **Not done (#140's later list).** `map`, `select`, `each_with_index`, `inject`: each needs its own result shape and measurement before it is kept (decision 348 measured the general block protocol at ~1.3 ns per element); `Hash#count`, Range receivers and the Integer-then-Float promotion of an untyped sum also keep the helper.
- **Measured** (instructions retired, macOS arm64, GOMAXPROCS=1 GOGC=off, old and new alternating, median of 5): bm_life 1,082M to 615M (#140's hand edit reached 658M; spinel 478M); bm_matmul 248M, bm_nqueens 192M, bm_sudoku 85M unchanged (`--nil-check=runtime`); `benchmarks/`: objects 254M to 243M, collections 939M to 929M, strings 162M to 159M, splay 51M to 50M, the other 14 rows within ±0.5%. Every output equal to the old binary's.
- **Cost.** `TestCompileCost` compiled functions unchanged (05_word_count 2,052, 64_observable 7,956, 116_cuba_web 30,255; the closures were already counted functions and the helpers stay generic, uninstantiated when no call remains).
- **Proof:** `array_test.rb` `ArrayBlockLoopTest` (empty receivers, `next`/bare `next` values, numbered and `it` params, a block that pops, appends or clears the receiver, `[0.1] * 10`, `[1e100, 1.0, -1e100]`, infinities and NaN, `break` out of a count and an `Array.new` statement, inner `times` loops keeping their own `next`/`break`, nested `Array.new`, closures capturing the slot index, a negative size, a block with `rescue`, the nested sum-of-counts) and `number_test.rb` `test_wrap_sum_low_bits` (the wrap lane's low bits of an overflowing sum; raise and promote raise RangeError there, as before), against MRI; example 134.
