# Decision 286

**An unannotated `initialize` inherits its parent's signature only through a pass-through `super`** (#100;
amends 146; 2026-10-15).
- Decision 146 lets an unannotated override with the same parameter shape inherit the parent's signature.
 For `initialize` the shape says nothing: `ImmediateEventPromise#initialize(default_executor)` calls
 `super Event.new(self, default_executor)` under `AbstractPromise#initialize(future)`, so typing the
 parent (decision 285) typed the child's executor as a future, and `brew info wget` failed at run time
 ("no implicit conversion of Concurrent::FixedThreadPool into ...AbstractEventFuture").
- Now an `initialize` inherits only when every `super` in it is a zsuper or passes only locals (each maybe
 splatted, `super(*)` included): ThenPromise's `super delayed, blockers_count, ...` still inherits
 (decision 256). Otherwise its parameters are typed as any def's (decision 146). Other methods are unchanged:
 an override's arguments mean the parent's by Liskov; a constructor's do not.
- Proof: `infer_test.rb` (`InitInheritTest`; before, a compile error "Ev where String is expected").
