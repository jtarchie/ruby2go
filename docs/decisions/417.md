# Decision 417

**Rule:** A dynamic call without a block of a block method no dynamic call passes one takes its decision-12 zero-argument twin (`public_send(:all?)`), a gem's iterator whose value is used and whose block breaks is nil when broken and its receiver otherwise (the break a `goto` past the receiver's assignment), and cmd/rubyspec counts an example whose result a thread's exception report pushed onto its own line.

**Bundled-gem backfill, seventh batch: the coverage recheck** (2026-10-30). *See also decisions 12, 172, 233, 241, 410, 411, 414, 416.*

Rechecking decision 416's numbers per spec directory, and running each gem's remaining failures one spec file at a time against the whole directory, found three root causes, a harness miscount, and failures 416 had not written down.

- **`public_send(name)` of an Enumerable predicate** (`x.should.all?` in mspec.rb's SpecExpectation forwards any `?` name to the actual value; plain user code with a computed name does the same): `all?`/`any?`/`none?`/`one?` take a required block, and a block method gets no Dyn wrapper unless some dynamic call passes a block (decision 243), so the wrapper was missing and the call raised NoMethodError. `dynEntry` now falls back to the method's `__name_0` twin, the block-less form a typed call already takes, and the wrapper routes other argument counts to their twins (`all?(Integer)` to `__all_q_1`). `core/enumerable` 160 → 166. Compiled functions are unchanged (TestCompileCost).
- **`return false if r.times do ... break if x == m ... end`** (prime's `miller_rabin_test`, behind `Integer#prime?` above the trial-division range): a gem's iterator in value position was a compile error, so `prime?` raised NotImplementedError. Its value is now a variable declared above the loop: the receiver when the loop runs to its end, nil when a valueless `break` leaves it, as MRI's. The break is a `goto` past the receiver's assignment, since Go has no for-else; a break inside a `begin` wrapper reissues it in the outer function (`reissue`), so the jump stays in one Go function. The same now holds for a gem method whose last expression is such a loop (it returned the receiver when broken). User code is unchanged: the value of an iterator call is still a compile error there (decision 172's `each` value aside).
- **drb counted 0 examples.** DRb's server thread prints `#<Thread> terminated with exception` to stderr between the test name and its ` = 0.00 s = E` result, so the -v line no longer matched. A result alone on a line counts. `library/drb` is 2 examples, 2 errors (IO.select over sockets, decision 416's limit), not the "0 examples" 416's run showed.
- **`core/env` moved 10 examples from skip to error with the same cause.** 416 loads a directory's own spec_helper; `core/env/spec_helper.rb` defines `be_locale_env` with `String.__send__(:define_method, ...)` on a `Class.new` matcher, which spec code cannot compile (decision 51). Before 416 the name was simply undefined, a compile-time skip; now SpecExpectation's `method_missing` makes it a run-time NoMethodError. Pass count unchanged (75).

**Whole-directory typing.** cmd/rubyspec compiles a directory's spec files into one program, so a gem method's parameter types join across every file's calls. Four failures pass when their spec file runs alone and fail only in the directory: matrix's `Matrix[1..2]` TypeError and `Matrix.new` being private (both true per file, as decision 416 says), and prime's `#rewind` (3) and `succ` alias of `next`. Prime's comes from one gap: with `each`'s generator parameter widened, a block-less `Prime.each` answers decision 411's Enumerator over the yields instead of running the method's own `return self.dup unless block_given?`, so `rewind` does not reach the generator's. **Open gap, fix shape known, cost unmeasured:** compile a block-less twin of a gem iterator whose no-block branch is not `to_enum`; next batch, gated on TestCompileCost.

**Left in each gem's `library/` directory:**

Open gaps: EigenvalueDecomposition's `V` comes out singular, so `to_a` and `**` with a non-integer power raise ErrNotRegular (2); `Matrix.rows(rows, false)` does not alias the caller's rows, since the typed `Array[Integer]` rows convert to `Array[untyped]` by copy at the gem boundary (1); the two whole-directory failures above.
- **prime** (42 of 68): design limit: mspec's `should_receive` (2, decision 416). Open gaps: whole-directory rewind/alias (4, above); `each`'s `break last_value` out of `loop` as the method's value is nil, not the last block value, since prime's each compiles as a void iterator (decision 410; 2, plus the skipped "returns the last evaluated expression").
