# Decision 299

**ruby/spec numbers, ranges and times: MRI's result class from the argument** (#102; amends 112, 140; 2026-10-17).
- `Float#round`/`floor`/`ceil` with a literal digits ≤ 0 (`x.round(-2)`, `x.floor(0)`) is an Integer, as MRI's:
 the compiler picks `__round_int`/`__floor_int`/`__ceil_int`, a literal overload like BigDecimal's (decision
 112). A computed digits ≤ 0 still raises (the call is typed Float). Digits outside a C int raise MRI's
 `RangeError` (`integer 2147483648 too big to convert to 'int'`).
- `Range#step(Float)` yields Floats whatever the bounds' class, and without a block it is an
 `ArithmeticSequence[Float]` (`(1..2).step(0.5).to_a` is `[1.0, 1.5, 2.0]`), where decision 140 made it a type
 error. An iterator call now takes a twin for its argument's class (`__step_float`) as other calls do, and a
 blockless call takes `__<name>_enum_<class>` when one exists. Float stepping counts the exclusive end as MRI's
 `ruby_float_step_size`; a numeric range with a negative Integer step walks backward (Ruby 3.4).
- `Range#bsearch` over Floats searches their bits as ordered int64s (MRI's `double_as_int64`); a beginless
 Integer range probes downward. Find-any mode (a block answering a number) is not supported: the block is
 typed `bool`.
- `Time.at(sec, subsec, unit, in:)` takes MRI's arguments (the zone was the second positional); `Time.now` and
 `Time.new` take `in:`; a fixed-offset Time's `zone` is nil (`String?`, as MRI's RBS). Float seconds keep
 their exact value floored to a nanosecond (`Time.at(100) + -1.3` has usec 699999).
- Proof: `range_test.rb` (`RangeFloatStepTest`, `RangeIncludeSuccTest`), `number_test.rb`
 (`NumberFloatDigitsTest`), `stdlib_test.rb` (`StdlibTimeSubsecTest`).
