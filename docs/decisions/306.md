# Decision 306

**Rule:** A gem's shipped `sig/` is read leniently (program sig, then vendored, then shipped, per member); an unparsable file is skipped with a warning.

**A gem's own shipped `sig/` is read, leniently** (amends 160, 305; 2026-10-18). Decision 160 read only `sig/gems/<gem>/` (vendored) and a `sig/` beside the program; a gem that ships RBS (pairing_heap, ffi, rbs, prism, webrick) had its types ignored.
- **Where:** for each gem lib dir whose base is `lib` (`boot.FindGems`' `full_require_paths`, or a traced build's `-I` dirs), `../sig` is walked for `*.rbs`, skipping `_`-prefixed dirs as RBS's FileFinder does. Precedence, first seen wins per member (`addSig`): the program's `sig/` > vendored `sig/gems/<gem>/` > the gem's own, so a vendored file can patch a shipped sig.
- **Lenient:** a shipped file `rbs.ParseFile` rejects is skipped whole with a gem warning (shown under `RUGAROO_GEM_WARNINGS=1`, decision 205), never a compile error; the program's and vendored sigs stay strict.
- **Generics erased (shim):** a shipped `class C[Elem, Priority]` that no earlier sig or core class gives params would make C a generic struct class, which is not compiled yet (#104; `model.go` errors). Its params are dropped, and each member whose type names one of them (a method in any overload, block included; an attr, ivar or constant) is dropped too, so inference types it exactly as with no sig; members with no type variable (`size: Integer`, `empty?: bool`) stay. A gem warning names the class (`eraseGemGenerics`, `// ponytail:` until #104 lands). Reading the variables as `untyped` instead was tried first and rejected: it overrode inference (`elem` String → any, new dynamic `<=`/`>=` on the priority), against minimize-untyped. *(See also decision 312: the shim now applies only to a class whose superclass is a core `@go_type`; generic struct classes keep their params.)*
- **RBS grammar:** `alias new old` in a class decl (`MethodAliases`): `old`'s sig also types `new` when `new` has none, following alias chains in the same decl. Header type params match brackets by depth (`[E, P < Comparable[P]] < Heap[E, P]` kept its superclass only by accident before: it was dropped). Also read now: members continued across lines (an open bracket, a leading or trailing `|`), `%a{...}` annotations (dropped), `def x: ...` and `| ...` arms (nothing to add), a method type with no `()` (`-> T`, `{ ... } -> T`), method type-param bounds (`[P < Pointer]`, dropped), a keyword parameter's variable name (`name: T name`), and class aliases (`class A = B`, which open no body). Of the 220 `.rbs` files under the installed gems, 54 failed to parse before, 12 after: intersection types `A & B` (prism, rbs: 7), single-quoted string literals (rbs: 3), a backquoted parameter name and a named proc parameter (1 each). *(See also decision 315: those four forms now parse, 0 of 220 rejected.)*
- **Measured** (example 120, pairing_heap 3.1.2's sig, whose unparenthesised `-> [A] | [nil, nil]` folds into one union return and whose `Comparable[Priority]` bound is dropped): output equals MRI; `rbDyn` references 84 → 84, the gem's dynamic-call warnings identical to no sig; generated funcs 597 → 597. What the sig still types is what has no type variable: `MinPriorityQueue#initialize: () -> void` drops the block parameter inference had given it. Almost all of the shipped sig names Elem/Priority, so its value waits on #104. TestCompileCost unchanged (05_word_count 1,339, 64_observable 27,086, 116_cuba_web 28,233 compiled funcs).
- **Proof:** `testdata/boot/sigdemo` (a second gem dir in `TestBootAutoload`: its `sig/sigdemo.rbs` types `Meter#total` as Integer and `push` through `alias push add`; `sig/broken.rbs` only warns), `TestSigsShipped`, `internal/rbs` `TestParseFileNestedBoundAndMethodAlias`, example 120.

*See also decision 419.*
