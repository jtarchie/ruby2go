# Decision 214

**Rule:** A module's own method dispatches through a generic `rbSend_<Mod>_<Name>` switch over includers; `Enumerable_Self` declares only `Each`.

**A module's own method dispatches through a generic type switch;
the constraint declares only what Go iteration needs** (#96 phase 3b
step 3, amends 208, 212). `dispatchable` admits a non-universal
module's own method when its free func can take the constraint as
`Self` (no `Self` in signature or constraint, decision 208), it is not
`each` or an iterator, no other module that includes this one
self-calls the name, and every includer's own override is its own
plain method with the same signature read in the module's parameter
names (`alignedArgs`: `include Enumerable #[E]` names each class
parameter once; `Hash`'s `#[[K, V]]` would not, but Hash overrides
none of them). The dispatcher is generic over the module's
parameters, `rbSend_Enumerable_First[E comparable](self
Enumerable_Self[any, E], n Integer)`, its arms name includers at
those parameters (`case *Array[E]: return Array_First[E](v, n)`,
verified Go accepts parameterized arms), the default is the module
body with the constraint as `Self`; with no overrider the call is
that default directly. A call site binds the parameters from the
receiver's include environment (`moduleCallArgs`). `Enumerable_Self`
went from eight names to `Each`; `includerCalls` and
`emitModuleInterface` skip dispatched names, so neither an includer
nor a generic primitive carries a forwarder for them, and
`dispatchableAll` asks `includerCalls` so a struct's own method is
dropped only when no constraint above needs it. Arms are the
concrete pointer type, never the class interface, which every
subclass would also satisfy (minitest's `SummaryReporter` answered
`StatisticsReporter#report`); a primitive overriding a universal name
(`Monitor#exit`) is an arm calling its direct Go method, and a
generic primitive overriding one makes the name non-dispatchable.
