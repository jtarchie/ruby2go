# Decision 302

**Rule:** Block-taking Array/Hash names on untyped receivers go through view helpers (`rbViewBlockCall`), not per-shape Dyn wrappers; literal blocks auto-splat.

**Block-taking Array and Hash names on an untyped receiver go through the view; literal blocks auto-splat**
(amends 236, 209, 243; 2026-10-17).
- **Why:** profiling `brew info wget` (693k Go lines) put 54% of its 366k compiled functions in generic
 instantiations. Decision 236 had moved the blockless whole-container names to one body, but the block-taking
 ones (`select`, `inject`, `sort_by`, `each_with_object`, `all?`, ...) stayed per-shape `DynX` wrappers, and the
 iteration names (`each`, `cycle`, `each_slice`, `first`, `sum`, ...) stayed `_DynGen0` cases. Each body names an
 `Enumerable_X[*Array[E], E]`, so Go compiled the wrapper and its chain once per element type: 393 Array shapes
 (245 tuple or interface, which share no GC shape) and 88 Hash shapes. Making them free funcs would not help, as
 decisions 86/211 already did that for the methods themselves; the per-shape cost is the dynamic layer.
- **What:** `seqNames` and `hashViewNames` map each name to the view helper that answers it. `rbViewBlockCall`
 takes 34 Array names, `rbViewPredicate` `all?`/`any?`/`none?`/`one?` (block, `===` pattern, or truthiness),
 `rbViewSum` `sum` (`Integer#+` for bignum safety, `+` dispatch otherwise); `rbHashViewBlockCall` 24 Hash names,
 `rbHashViewPredicate` the four predicates. The predicates and `sum` are separate functions so only programs that
 call them dynamically keep the `===` and `+` dispatchers. Hash gets one more one-line accessor, `_pair_at`
 (a protocol name), so the view yields the same `Tuple2[K, V]` the wrappers did. Blocks get raw elements, as the
 wrappers passed them; a block's result is unboxed before it is tested (an `Integer?` element's nil pointer was
 truthy). `rbViewCall` now pops the block too: `sort`/`max`/`min` compare with it, `count`/`index`/`rindex` test
 with it, `uniq` keys by it (the block used to count as an argument and raise ArgumentError).
- **Behaviour fixed on the way:** the wrappers tested block results with `rbAs[Boolean]` (a truthy non-Boolean
 raised TypeError) and blockless `none?`/`one?`/`any?` raised LocalJumpError; `each` and friends returned the last
 block value instead of the receiver. All now follow MRI.
- **Auto-splat:** a literal block of two or more parameters called with untyped values (`genDynBlockCall`,
 `dynBlockValue`, `bindFromRest` over `untyped`) splats a lone Array or tuple argument (`rbAutoSplat`), as MRI does
 for a proc: `h.each { |k, v| }` through a computed send bound the pair to `k` and nil to `v`.
- **Not changed:** blocks on an untyped receiver in a literal call still compile through decision 224's Hash/Array
 switch, not the dispatchers; the view serves computed sends, `public_send`, forwarded blocks and every other
 dispatcher route. Not covered by the view: the pinned `<=>`/`to_json`, gem-defined Hash methods
 (ActiveSupport's `_deep_transform_*`), and blockless Enumerator forms (still LocalJumpError).
- **Measured** (`brew info wget`, same machine, `-c=4 -dwarf=false`): Array half alone, compiled functions
 366k → 279k, archive 885 → 660 MB, build 144 → 107 s wall; output equal to MRI for `info wget`/`jq`/`git` and
 `--json=v2 wget`. Small programs flat (`TestCompileCost`: word_count 1,339 → 1,339, 64_observable
 29,432 → 28,977, 116_cuba_web 28,631 → 28,641). Runtime: the view replaces typed closures with `any` calls only
 on paths that were already untyped (the wrappers boxed every block argument and result), so no typed path pays.
- **Proof:** `testdata/boot` (`lib/demo/views.rb`: every name through `public_send` on Integer, `String?`, tuple
 and `Integer?` Arrays and on Hashes, mutation, errors, frozen). *See also 304* (the element-level names join the view).
