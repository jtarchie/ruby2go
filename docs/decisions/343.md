# Decision 343

**Rule:** A rescue skips backtrace capture (`rbKeepPCs` false) unless the pruned program calls `rbBacktrace` or `RUGAROO_BACKTRACE` is set.

**A rescue captures the stack only when something can read it** (amends 106; 2026-10-23). *See also decision 106.* Decision 106 records the Go program counters in every rescue that binds (`=> e`), about a microsecond each, for `Exception#backtrace` to read later. Most programs never read one: in `benchmarks/exceptions.rb` the capture was 18% of the run. After pruning, the compiler (`keepPCs` in `format.go`) looks for a call of `rbBacktrace` outside `rbPrintUncaught`; with none, it rewrites the prelude's `const rbKeepPCs = true` to false, and `rbCaptureBacktrace` returns at once unless `RUGAROO_BACKTRACE` is set (the uncaught report's full form, which then captures in every rescue as before, so a debugging run sees the same frames). `Exception#backtrace`, `full_message` and minitest's error report all reach `rbBacktrace`, so programs using them are unchanged. The rescue still calls `rbCaptureBacktrace`, as codegen runs before pruning; the call is the whole cost left. With `RUGAROO_NO_PRUNE` the constant stays true.
