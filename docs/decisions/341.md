# Decision 341

**`File.delete` of a directory, FileUtils return values, `cp_r` keywords** (#109 follow-up; amends 336; 2026-10-23). *See also decisions 62, 241, 336.* Each checked against MRI 4.0 first; `testdata/test/fileutils_test.rb` (`ReturnValueTest`, `DeleteDirectoryTest`, `CpRKeywordsTest`) compares them, and `testdata/run/file_delete_directory.rb` covers the one case that needs the compiler's scan.
- **`File.delete`/`unlink` call `unlink(2)`** (`syscall.Unlink`), not `os.Remove`, which falls back to `rmdir` and removed an empty directory. The errno is the platform's: `Errno::EPERM` on macOS, `EISDIR` on Linux, message `... @ apply2files - <path>`. `FileUtils.rm` raises the same; `rm_f` swallows it. `rbSysErr` now checks `EPERM` before `fs.ErrPermission` (Go files `EPERM` under it, so it came out as `EACCES`) when `Errno::EPERM` is loaded, and passes the ` @ fn - path` suffix to `rbKillErrnoHook` for `apply2files` only (`Process.kill`'s EPERM/ESRCH stay the bare strerror). `Errno::EPERM` loads (decision 241) when a program names it, and now also when it calls `File.delete`/`File.unlink`/`FileUtils.rm`/`FileUtils.remove` by constant (`unlinksPath` in `requireScan.visit`), since a program that only rescues `SystemCallError` would otherwise get an `IOError`; the cost is two exception classes in such programs.
- **Return values, as MRI's.** A path list comes back as strings: `mkdir`, `mkdir_p`/`makedirs`/`mkpath`, `rm`/`rm_f`/`rm_r`/`rm_rf`/`remove`/`rmtree`/`safe_unlink`, `rmdir`, `touch`, `chmod`, `chmod_R`, `chown`, `chown_R`. Under `noop:` they return nil, except `mkdir_p`/`mkpath`, which still return the list. `cp`/`cp_r`/`copy` give nil for one source and the source Array *as given* (Pathnames kept) for an Array; `mv`/`move`/`ln`/`link`/`ln_s`/`symlink`/`ln_sf` give `0` for one source and the Array as given for an Array. `copy_file`, `install` (one source) stay nil. `remove_entry` gives what the root's removal gave: 1 for a file or symlink (`File.unlink`), 0 for a directory (`Dir.rmdir`), nil for a missing path under `force`; it now takes `force` positionally as MRI does. `remove_file` gives 1, `remove_dir` 0, `remove_entry_secure` nil. `cd`/`chdir` return the block's value, or 0 without a block. Added the aliases the list above needs (`makedirs`, `copy`, `move`, `remove`, `rmtree`, `safe_unlink`, `link`, `symlink`, `getwd`, `remove_file`, `remove_dir`, `cd`, `chdir`); `ln` takes a list.
- **`cp_r(remove_destination:, dereference_root:)`.** `remove_destination` unlinks a file or symlink standing where an entry goes before copying it (a directory is left and merged into, as MRI: `File.unlink ... if File.file? || File.symlink?`); the verbose line gains ` --remove-destination`. `dereference_root` (default true) copies `File.realpath(src)`, so a symlink given as the source becomes a real copy and a missing one raises MRI's `rb_check_realpath_internal` error; false relinks the root (`File.symlink(File.readlink(src), dest)`), a missing source raising `rb_file_s_lstat`. Symlinks inside the tree are relinked either way. A directory entry is made with `Dir.mkdir` semantics (reuse a directory, else fail), so a file in the way is `EEXIST` and a missing parent `ENOENT`; `MkdirAll` made both pass silently.
- **Not done.** `install` and `copy_file` with a list; `copy_entry`; the `secure:` behaviour of `rm_r`/`remove_entry_secure`; the error text of a failed `cp_r` mkdir (`rb_sysopen - src`, MRI says `dir_s_mkdir - dest`); a cross-device `mv` returns 0 (MRI returns the copy/remove result). The brew override, which cannot run here, may call these with a nil-typed result; re-run `brew` before relying on it.
