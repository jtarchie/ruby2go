# Decision 371

**Rule:** govet `nilness` runs on the repo and on generated programs, where a nil guard on a value codegen proved non-nil is a codegen bug (only `nil == nil` is excluded); `govulncheck ./...` is a documented manual check; `nilaway` was audited once and is not a standing check.

#115. `nilness` (impossible or always-true nil comparisons, nil
dereferences) is off in golangci-lint's default `govet` set; it is now
on in `.golangci.yml` and `.golangci.generated.yml`. It reported
nothing in the repo or in `prelude/go` (`--build-tags rb2go_prelude`).
In the examples' generated Go it found NoMethodError guards
(`if x == nil { panic(rbNoMethod(...)) }`) on a value already known
non-nil, each a narrowing codegen missed:
- `h.nil? || h.zero?` in a condition: the right operand now gets what
 the left's falsity proves (`elseNarrowing`), as `&&`'s right gets its
 left's truth; and `elseNarrowing` now finds a local assigned in an
 earlier branch or loop body (`narrowLocal`), as `readLocal` does;
- `s.strip.empty? || s.strip == ":"`: the left always runs, so a local
 it called a guarded method on is non-nil on the right (decision 357's
 `callNarrowing`, applied between operands, in conditions and in
 value-producing `&&`/`||`);
- `@src.pos += @src.matched_size`: the reader's guard proves the pinned
 receiver non-nil for the writer (also `recv.x ||= v`);
- `item = Element.new(...)` into a leaf class's `C?` local (a nil-able
 `*C`, decision 360) leaves it `C` until its next write, unless a
 block writes it (`narrowLeafAssign`, the same limit as decision 283);
- both of those, and `callNarrowing`, gave up when any block in the
 method wrote a local of the same name. A block before the name's
 first assignment outside blocks (and not a parameter) writes a
 block-local of its own, by Ruby's scoping, so only later blocks
 count now (`blockWritesLocal`; kramdown's `item = stack.pop` after an
 `each { ... item = stack.pop ... }`).
Proof: `testdata/test/control_test.rb` `test_narrowing_between_operands`
compiles with no "possibly-nil" warning; every example lints clean.
One shape stays excluded in `.golangci.generated.yml`: `nil == nil`
(both sides proven nil), Ruby that tests a local it just set to nil
(`name = nil; name ||= "x"`). The Go is the program as written; folding
it would take constant propagation. The generated config also lifts
golangci-lint's 3-per-message cap, which had hidden most of these.

`govulncheck ./...` is in the CLAUDE.md commands. It needs network
access to the vulnerability database, so the suite does not run it.
First run (2026-10-24, go1.27.3): no vulnerabilities found.

`nilaway ./internal/... ./cmd/...` reported 280 potential nil panics.
Four were real, all Go runtime panics that `compile` turned into
"internal error" instead of a compile error:
- a constant written inside a block in a class body
 (`class A; x = 1; [1].each { Y = x }; end`) was never collected, so
 `genBodyConst` read a nil `*Const`. It is now the same
 "unsupported syntax: ConstantWriteNode" as the top-level case;
- a `Struct.new(...) do undef_method :a= end` block removed a
 generated accessor, and the hide-the-generated-def loop
 (`valueclass.go`) dereferenced the missing method. It now skips it,
 and the program gets rb2go's ordinary "undefined method" error;
- `protected def self.x` dereferenced a missing instance method `x`
 (the def went to the singleton). MRI's `protected(:x)` looks up the
 instance method, so it is now the same "undefined method 'x' for
 class 'A'" MRI raises when no class in the chain defines one;
- `pruneConsts` dropped an unread top-level gem constant from
 `c.consts` but not from `c.topConstNames`, so Object's constant
 table would read the deleted entry. Latent: no vendored gem has such
 a constant.
The other 276 were false alarms nilaway cannot see past, roughly: 129
guarded (a length, nil or `ok` check it does not connect; 25 trace to
one `firstArg` in `genEvalSwitch`), 79 structural invariants (a nil
interface matches no `case *T:` arm, a map ranged by its own keys),
43 closed-world map lookups (`c.classes["Object"]`), 16 in test code,
6 nil slices only ranged or sliced to zero, 5 nil returns after
`errorf`, which never returns. About 1.4% real is too
noisy for a standing check, and golangci-lint runs nilaway only as a
custom plugin build; rerun it by hand after large compiler changes.
