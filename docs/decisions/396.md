# Decision 396

**Rule:** `Integer?` and `Float?` are Go `rbOpt[T]` (`struct{ v T; ok bool }`, zero is nil), held by value; generic code keeps `V?` as `*V`, and where a generic `V?` with `V = Integer/Float` meets typed code the call copies it into an `rbOpt` (`Array#[]` and `Hash#[]` build one directly), so no element read aliases its Array.

**Integer? and Float? by value** (#133; amends 349; 2026-10-26; DRAFT, number is a placeholder). *See also decisions 20, 342, 349, 359, 360, 378, 387, 393.* `Array#[]` returned `&self.s[i]`, a pointer into the Array's storage, so `x = a[-1]; a.pop; a.push(5); p x` printed 5 (MRI 3), and spinel's `bm_fannkuch` looped forever and `bm_stark_field` printed wrong numbers under `--nil-check=runtime` (the swap `t = a[i]; a[i] = a[j]; a[j] = t`). Copying (`v := s[i]; return &v`) fixed it but heap-allocated wherever the element left a method (`bm_life` +67% instructions). Decision 349 declined an unboxed `Integer?` for lack of a target; this bug is one.
- **Representation.** `goType` of `Integer?`/`Float?` (`valOpt`) is `rbOpt[T]` (`leafOptType`). `derefOpt` is `.v`; nil tests go through `optIsNil`/`optNotNil` (`!x.ok`/`x.ok`) at every site that compared a `T?` with nil (conditions, `&.`, `||=`, `nil?`, patterns, `nilGuard`, `nilSpaceship`, the safe-call and `nilClassCall` temps); a nil into one is `rbOpt[T]{}` (`coerceToOpt`, `coerce` for a nil relabeled by an annotation, and `valOptNils` for a nil argument whose type parameter a later block binds, `reduce(nil) { }`); a `T` into one is `rbSome`; to untyped `.rbAny()`; from untyped `rbOptOf`; an ivar write from untyped `rbIvarAssignVal`; under `--nil-check=runtime` `rbNilArgO`; a gem's lenient `T?` where `T` is wanted `rbMustO`; `T? == T` `rbOptEqV` (decision 387's plain path); `cmpNil`'s Op_cmp adapter tests `.ok`.
- **Generic boundary.** Go generics cannot pick a representation per type argument, so generic code keeps `V?` as `*V`. `boxedValOpt` finds a signature's `X?` whose `X` is a type variable bound to Integer/Float, as `boxedLeafOpt` does for leaves: a result is `rbOptFromPtr(...)` (the copy this decision exists for), an argument `rbOptToPtr(...)`, a block returning `U?` is wrapped to Go's `*U`. `Array#[]` and `Hash#[]` skip the pointer: `rbArrAt`/`rbHashAt` build the `rbOpt` directly, one bounds test, which is why the element-read loops got faster, not just correct. Shapes handled: `E?`, `Array[E?]` (values_at), `[E?, E?]` (minmax), zip's `Array[[E, U?]]`, `[E, U?, V?]`, `Enumerator[[E, U?]]` (`rbZipViewEnumVal`), its block forms (`rbZipValSeq`, and `rbZipPairVal` in the fused loop, decision 389), `compact` of `Array[T?]`/`Lazy[T?]` (`rbCompactVal`, `rbLazyCompactVal`), multiple assignment and block-param splats of an `Array[Integer]` (`genericOpt`), `rbSend_` dispatchers (`flatCall`). Code holding an `rbOpt` as `any` (`rbUnbox`, `rbKeyUnbox`, `rbCmpBox`, `rbMBox`, `rbOptFrom`) opens it.
- **Prelude.** `%x{}` bodies and `prelude/go` helpers with an `Integer?`/`Float?` in their signature were rewritten (`return rbOpt[Integer]{}`, `rbSome(...)`, `x.ok`, `x.v`); Go helpers that still return `*Integer` (`rbGetbyte`, `rbMatchOffset`, `rbScanLen`, `rbComplexCmp`, `rbMatchSet`, `rbMatchPos`) are wrapped in `rbOptFromPtr` at the call.
- **Not covered.** Every other non-nil-holding `T?` (String, Symbol, Boolean, Array, Hash, Proc) is still a `*T` box, and `Array#[]` still hands out `&self.s[i]` for them: `a = ["x"]; s = a[-1]; a[-1] = "y"; p s` is still wrong (#133 stays open for them). The real rule is "every `T?` whose `T` does not hold nil itself is a value optional"; Integer/Float were the prototype's scope because they are where the hot loops are. Ponytails: a `Lazy[[E, U?]]` (zip on a lazy enumerator) and a zip of mixed `U?`/`V?` keep the box and fail to build; `Bignum?` keeps the box.
- **Measured** (instructions retired, M, GOMAXPROCS=1, median of 5, paired old/new runs against 495fe21): bm_life 1,095 → 1,095 (the copy fix was +67%), bm_loops_times 580 → 547, bm_sieve 370 → 361, bm_histogram 13,261 → 11,660, bm_reader_index 6,426 → 6,037, bm_stark_field 4,379 (wrong output) → 2,055 (== MRI), bm_fannkuch did not terminate → 21; repo benchmarks: collections 1,497 → 1,459, pairing_heap 793 → 758, regexp 3,140 → 3,093, binary_trees 59 → 58, blocks 376 → 391 (+3.9%: zip's pairs are `Tuple2[E, rbOpt[U]]`, 24 bytes where they were 16), the rest within ±0.6%.
- **Proof:** `ArrayElementCopyTest` in `testdata/test/array_test.rb` (the three #133 snippets, the swap, a Float) against MRI; spinel's benchmarks and `benchmarks/` == MRI.

*See also decision 397* (every other `T?` element read now copies, except `Array#[]` of a String, which keeps the slot for speed).
