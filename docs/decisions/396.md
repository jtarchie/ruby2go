# Decision 396

**Rule:** User code may `s.setbyte(i, b)` on a String local that decision 382's proof clears with the stricter rule that, before the last setbyte, the String is read only for non-String results (`getbyte`, `bytesize`, `==`, ...), and on an ivar inside `initialize` whose first mention is a top-level `@x = <fresh String>` and before whose last setbyte neither `self` nor the String escapes; the write rebinds through `rbStrSetbyte`, which copies into a buffer the builder owns on its first write and writes in place after, and anything outside the proof stays decision 58's compile error with the reason.

**In-place `setbyte` on an unaliased String** (amends 58, extends 382; 2026-10-26). *See also decisions 332, 382.* Three spinel benchmarks stopped at decision 58's "undefined method setbyte for String": bm_ruby_xor (`result = a.dup; result.setbyte(i, ...)` in a loop, then `result` returned) and bm_str_readonly_param / bm_handle_readonly_param (`@buf = "\0".b * len`, then `@buf.setbyte(...)` in `initialize`, then the String passed around read-only). The aliasing argument is 382's: when nothing else holds the String, writing a byte of it in place is indistinguishable from MRI's.

- **Locals.** The proof is `appendWhy` (382) with `strict` set whenever the scope calls `setbyte` on the local. The difference matters for Go memory safety, not just MRI semantics: `rbStrAppend` only writes past the end of every live String, so it is safe whatever the proof says, but setbyte writes *inside* bytes that any Go string over the same buffer also covers (`s[0, 3]`, `s.strip`, `s.dup`, `s + ""`, a lone `"#{s}"`, `s.split`, a MatchData over `s`, a Symbol from `s.to_sym` can all share them). So before the seal (the end of the outermost loop or block around the last setbyte or append) a strict local may only be the receiver of `scalarStrMethods` (methods returning no String: `size`, `bytesize`, `getbyte`, `bytes`, `==`, `<=>`, `include?`, `index`, `count`, `match?`, `to_i`, `ord`, ...; no block forms), an argument of `scalarArgCalls` (`==`, `include?`, `index`, `count`, ...) or of a receiverless `puts`/`print`, a condition, a dropped statement, or the method's value. Everything 382 allows beyond that (`[]`, `dup`, `strip`, `+`, interpolation) is a leak: "`s.[]` may share the String's bytes on line 4 before its last change". This over-rejects (`t = s.upcase` before a later setbyte is safe in MRI and here would be too if upcase always copied); a per-method "always copies in Go" table is the upgrade. `<<` and setbyte may mix on one local: both use its `rbBuf_` buffer, and append's past-the-end invariant still holds under the stricter proof.
- **Ivars, only in `initialize`.** `@x.setbyte` compiles when the method is a user class's `initialize`, `@x` is typed exactly `String`, and `ivarSetbyteWhy` clears it: the first top-level statement of the body that mentions `@x` is `@x = <fresh>` (382's `fresh`); every other write of `@x` there is fresh; and before the seal `@x` is read only as above, and nothing could reach `@x` through self: no `self`, no `super`, no `yield`, and no receiverless call other than `selfFreeCalls` (`puts`, `p`, `raise`, `format`, `loop`, `Integer`, ...): an implicit-self `dup`, `inspect`, `instance_variable_get`, `send` or user method would see the String. After `initialize` returns nothing writes `@x` in place again, so every other method reads it freely (bm_handle_readonly_param's `peek` aliases it with `b = @buf`). `@x.setbyte` anywhere else is "`@buf` is changed outside initialize". Not guarded: a subclass `initialize` that publishes `self` (to another thread, say) before calling `super` into this one; that is a race in MRI too.
- **Code.** `s.setbyte(i, v)` evaluates both arguments into `Integer` temporaries (`--nil-check=runtime` checks an `Integer?` such as `getbyte`'s, decision 393), then `s = rbStrSetbyte(&rbBuf_s, s, i, v)`; the expression's value is `v` unmasked, as MRI's. An ivar's buffer is `rbBufIv_x`, a `[]byte` declared at the top of `initialize`'s Go body by `hoistLocals` (`fctx.ivarBufs`), so each `new` gets its own. `rbStrSetbyte` checks the index first (MRI's `IndexError: index N out of string`, negative from the end), then, unless `s` is exactly the buffer (same data pointer and length), copies `s` into a new buffer of exactly its length (bm_str_readonly_param's is 16 MB; a later `<<` regrows it), and writes `byte(v)` (MRI's `v & 0xff`). The source of a `dup` is never written: the first write always copies. This steps outside `unsafe.String`'s contract (the bytes must not change afterwards), which `rbStrAppend` never does; it holds because the proof leaves `s` the only String over the buffer until the last write, and every later read of `s` follows the store through the rebinding `s = rbStrSetbyte(...)`.
- **Not in scope.** `[]=` of one byte or character, `setbyte` through a parameter, an Array element or an attribute (382's follow-up: a String that is a reference), and gem code, where `setbyte` still has no lenient form.
- **Measured** (M-series, GOMAXPROCS=1, `/usr/bin/time -l`, median of 5; rugaroo with `--nil-check=runtime`): bm_ruby_xor MRI 1.43 s / 17.3 G instructions, rugaroo 0.09 s / 1.34 G, spinel 0.08 s / 1.26 G; bm_str_readonly_param MRI 0.05 s / 356 M, rugaroo 0.01 s / 39 M, spinel <0.01 s / 24 M; bm_handle_readonly_param MRI 2.60 s / 30.6 G, rugaroo 0.05 s / 0.71 G, spinel 0.07 s / 1.27 G. All three print what MRI prints.
- **Cost.** Programs without a user `setbyte` generate the same Go (strict mode and `ivarBufs` are only set by one); `rbStrSetbyte` is pruned unless used.
- **Proof:** `StringSetbyteTest` and `SetbyteGrid` in `testdata/test/string_test.rb` (xor leaves its source, masking and the return value, IndexError messages, copy before the first write and slices after the last, mixing with `<<`, an ivar built in `initialize` per instance) against MRI with the trace oracle; `testdata/errors/strings.txtar` `setbyte_*` cases (a slice before the last write, interpolation, a parameter, an ivar outside `initialize`, a self call before the write, an ivar not first set fresh); example 133.
