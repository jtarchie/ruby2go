# Decision 360

**Rule:** A leaf class's `C?` is Go `*C` itself, nil its nil: no box, no `Ref` on the way in and no deref on the way out; where a generic signature's `V?` is bound to a leaf, the call opens Go's `**C` result with `rbFlat` and boxes an argument with `rbBoxPtr`.

**A leaf's nil is a nil pointer** (amends 359; 2026-10-24). *See also decisions 20, 355, 359.* After decision 359 a leaf `C` was `*C`, and `C?` stayed `**C`: every `Node?` slot written with a `Node` allocated a box (`Ref`), the cost decision 355 recorded and the one spinel avoids by folding nil into every object type. Now `goType(C?)` is `*C` (`leafOpt`), and:

- **Inside typed code** a leaf `C?` and `C` share a Go type: narrowing, `&.`, `||`, `is_a?`, patterns and the other deref sites take the pointer as it is (`derefOpt`), and a `C` into a `C?` slot is the pointer (`coerceToOpt`). Ruby's rule is unchanged: a `C?` where `C` is wanted is still decision 20's compile error until narrowed.
- **Untyped boundaries.** Boxing a leaf `C?` into `untyped` is `rbPtrAny` (a nil pointer is Ruby's nil, not a typed nil in an interface) wherever `Opt` was (`optAny`: `to_s`/`inspect`/`==` on a `C?`, `_Ivars`, constants, a Proc's `C?` result); converting `untyped` to `C?` is `rbOptPtr` (`optOf`); `instance_variable_set` on a `C?` ivar is `rbIvarAssignPtr`; `rbOptClassFrom` answers a type parameter bound to `C?` with the object itself.
- **Generic boundaries.** A generic method's `V?` with `V = C` is Go `*V = **C`, the box this decision removes elsewhere. `boxedLeafOpt` finds a signature's `X?` whose `X` holds a type variable bound to a leaf: the result is `rbFlat(...)` (as `flatOpt` already did for `E?` with `E = T?`), an argument `rbBoxPtr[C](...)`. `Array[C?]` and the like are `Array[*C]` on both sides, since the element type itself is `C?`.
- **Not covered:** instances of generic classes (pairing_heap's `Node[Integer, Integer]`) are not leaves yet. Treating them as leaves made `PairingHeap#merge_pairs` untyped through its `MergePairs` mixin (`meld`'s result read untyped in pass 1), and a dynamic call there typed `SimplePairingHeap::Node#next_sibling=` with `PairingHeap::Node` (decision 331 joins a dynamic call's arguments into every same-named method once one non-dynamic call reaches it), so the program raised TypeError. That needs its own look.
