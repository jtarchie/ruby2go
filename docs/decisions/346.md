# Decision 346

**Rule:** The JSON generator appends core values into one buffer without calling their `to_json`, as json 2.x does; `json/v2` and `jsontext` are not used.

**The JSON generator writes core values into one buffer; `encoding/json/v2` and `jsontext` weighed** (amends 25, 332; 2026-10-23). *See also decisions 25, 332.* `benchmarks/json.rb` was the one workload slower than MRI. A linux/arm64 profile split the main goroutine 61% generate, 36% parse; generate's time was the String each nested value's `to_json` returned and its parent copied in (`concatstrings`, `growslice`, `memmove`), plus the garbage that fed a GC taking a quarter of all samples.
- **The generator.** `rbJSONState` carries the document as a `[]byte`. `rbJSONValueTo` is the gem's `generate_json`: an exact String, Integer, Float, true/false/nil, Array or Hash is appended directly, without its `to_json`; anything else answers `to_json(state)` and its String is copied in. This is what json 2.x does (2.21, MRI 4.0, checked): a reopened `Integer#to_json` or `Hash#to_json` is not called by `JSON.generate` or by a container's `to_json`, while a subclass's is. A Hash or Array subclass promotes the embedded value's methods (decision 165), so the core check is `rbJSONTo(st, v) bool`, which answers false when `v` is not the receiver itself. `Array#to_json`/`Hash#to_json` called directly still return a String: they write past the buffer's end and take that slice out. A user `to_json` that rescues a nested error leaves a partial value in the buffer; the caller cuts the buffer back to where the call began.
- **`jsontext` and `json/v2`, measured and not adopted.** `json/v2`'s `Marshal`/`Unmarshal` are reflection over Go types: they cannot produce an insertion-ordered `Hash`, call `to_json` on a Ruby object, or format floats as the gem (`1250.0`, `1e+20`), and decision 82's no-reflect rule excludes them anyway. `jsontext` is the syntactic layer, without reflect. `jsontext.AppendQuote` escapes exactly the gem's default set (checked byte for byte against MRI for 0x00-0x7F, U+2028/9, non-BMP, `/`, `<>&'`), but in the new generator it measured the same as a 30-line hand escaper (2.16G vs 2.18G instructions, within noise; a micro-benchmark has it ~30% faster on 1 KB ASCII strings and ~10% slower on escape-heavy and multibyte ones), and it requires `go 1.27` in the generated module (`rb2go.GoVersion` is 1.25.0) and in the repo's `go.mod`: every user would need Go 1.27 for no measured gain. `jsontext.AppendFloat` uses ES6 number formatting, not the gem's fpconv. A `jsontext.Decoder` in place of decision 332's byte parser made the benchmark 10% slower (2.98G to 3.28G instructions): it reads through an `io.Reader` into its own buffer, so every string is a copy, where the byte parser slices the input, and it validates a state machine the byte parser does not need. Since Go 1.25, `encoding/json` v1 is implemented on v2, so a program already links `jsontext` through the error path's `json.Decoder`; switching that path to `jsontext` would save about 200 KB of binary and needs every `rbJSONDecodeErr` mapping redone against `jsontext.SyntacticError`, not done.
- **Measured** (darwin/arm64, `/usr/bin/time -l`, median of 9, on main 1e3c8ab): `benchmarks/json.rb` 2,950M to 2,127M instructions (-28%), wall 0.19-0.20 s to 0.14-0.15 s (MRI 0.17 s in the same session; MRI's own total is 1,317M instructions, 398M of it `ruby -e 'require "json"'`). `TestCompileCost` on the JSON examples, compiled functions: `19_json` 1,821 to 1,864, `25_resty` 7,848 to 7,902, `32_resty_reflective` 25,627 to 25,738 (the `rbJSONTo` method and the `*To` generic shapes per Array/Hash instantiation; programs without `require "json"` do not load this file). Binary: `19_json` +3 KB, the benchmark +2.5 KB.
- **Left.** Parse is now the larger half: `Hash_Op_idxSet` (a map plus a keys slice per object), boxing each value into `any`, and the GC those allocations drive. That is the Hash representation, not JSON. Float output still allocates a String per value (`rbJSONFloat`).
- **Proof:** `testdata/test/json_test.rb` (`test_generate_rescued_nested_error_leaves_nothing`, `test_pretty_generate_through_user_to_json`, `test_generate_calls_a_hash_subclass_to_json`, `test_generate_escapes_nested_strings`), with `rxjson_test.rb`'s `to_json` protocol cases unchanged.
