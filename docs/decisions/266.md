# Decision 266

**Rule:** Integer ops give MRI's exact result when it fits Go `int`; where MRI would make a Bignum they raise `RangeError`.

**Integer edges: exact where the result fits, RangeError where MRI makes a Bignum** (#101; amends 35; 2026-10-14).
- Where the true result fits Go `int`, rugaroo returns MRI's answer
 exactly: iteration up to and including MaxInt/MinInt terminates
 (`Range#each`/`reverse_each`, `upto`, `downto`, `step`,
 ArithmeticSequence, `bsearch`); shifts by any count give 0/-1/MRI's
 value (`-1 << 63` fits); `gcd` is computed unsigned.
- Where MRI makes a Bignum, rugaroo raises `RangeError`:
 `Range#size`/`count`/`sum`, `upto`/`downto`/`step` sizes (counts
 past MaxInt: `(MinInt..MaxInt).size` is 2**64), `gcd` past MaxInt,
 `x << n` or `x >> -n` past 64 bits (`x >> MinInt` is `RangeError`
 where MRI raises `NoMemoryError`), endless iteration passing MaxInt,
 `format("%d"/"%x", Float)` past ±2**63. NaN and Inf stay
 `FloatDomainError`.
- The loop helpers test the bound after the yield (`i == MaxInt`)
 instead of widening: one compare, no other runtime cost.
- Not fixed: `Range#step(n) { }` with a block still walks every
 element; `(MinInt..MaxInt).min(2)` iterates the whole range.
