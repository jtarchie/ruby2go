# Decision 397

**Rule:** A prelude method that returns an element as `T?` (`Array#[]`, `bsearch`, `rfind`, `assoc`/`rassoc`, `Hash#default`, `Lazy#zip`'s `U?`, multiple assignment's `rbSplatAt`/`rbTrailIdx`) returns a pointer to a copy, not into the container's storage, except `Array#[]` of a String, which keeps the slot; `rbOpt` stays Integer?/Float? only.

**Element reads copy for every `T?`** (#138, rest of #133; amends 396; 2026-10-27). *See also decisions 342, 349, 360, 378, 389, 396.* After decision 396, `Integer?`/`Float?` were by value, but every other `T?` whose `T` cannot hold nil itself is still a `*T` box, and `Array#[]` handed out `&self.s[i]`: `a = ["x"]; s = a[-1]; a[-1] = "y"; p s` printed "y" (MRI "x"). The same held for Symbol, true/false, and an Array or Hash element (`Array[Integer]?` is `**Array[Integer]`, a pointer to the slot, so `v = d[0]; d[0] = [9]` showed `[9]`), and for `bsearch`, `rfind`, `assoc`, `x, y = arr` (`rbSplatAt`/`rbTrailIdx`), `Hash#default` (`&self.defVal`, seen through a later `default=`) and `Lazy#zip` (`&other.s[i]`, the gap decision 389 closed for the eager zips).
- **Inventory.** `goType(TOpt)` gives a by-value or nil-holding form only to `valOpt` (Integer/Float, decision 396) and `leafOpt` (user/gem struct classes, 360/378); every other `T?` is `*T`. Array and Hash values are already Go pointers (`*Array[E]`), but their `T?` is still `**Array[E]`, so they aliased too. Already copies: `Hash#[]` (`rbHashLookup`'s `v, ok`, decision 342), `pop`/`shift`/`delete_at`, `Enumerable` min/max/find (a local per element), the eager zips (clones, 389). Left as they are: `rbHashSlot` (the fused `h[k] op= v` slot, consumed in place by the compiler), `Range#min`/`max`/`ArithmeticSequence#end` (`&self.b`/`&self.e`: a Range has no writers).
- **The fix is the copy, not a representation.** Each of those sites now copies the element into a local and returns its address (`x := self.s[i]; return &x`). `Array#[]` inlines (decision 342), so the copy lands in the caller's frame and stays on the stack unless the `T?` escapes; only an escaping result costs a heap allocation, the same cost a boundary copy would pay. Copying a `*Array`/`*Hash` element keeps MRI's sharing (the same object), and only the slot's reassignment stops showing through. String values are immutable Go strings (decisions 58, 136, 382), so no in-place String mutation relied on the alias.
- **String keeps the slot in `Array#[]`** (ponytail). Copying everywhere cost spinel's `bm_csv_process` +4.8% (+5.0% in 11 paired runs) and `bm_wordfreq` +3.2% (+2.5% in 11): `dept = fields[1]` becomes a Hash key and `result.push(words[idx])` an `Array[String?]` element, so the `*String` escapes and the copy is a 16-byte heap allocation per read (`moved to heap: x` at `bm_csv_process.rb:27`). No cheaper copy exists while `String?` is `*String`: the Hash's key path (`rbValueKey(any(k))`) leaks every key, so copying on insert would not stop the escape. `Array#[]` asks `rbSlotAlias[E]()` (one dictionary type test, inlined) and returns `&self.s[i]` for String; so `a = ["x"]; s = a[-1]; a[-1] = "y"; p s` and `x, y = arr` of Strings, and the methods written over `[]` (`first`, `last`, `at`, `dig`, `fetch`), still show a later write to the slot (`testdata/run/array_bug_string_slot.rb`, `# skip:`). Symbol has the same Go shape but no row paid for its copy, so it copies. The other copying sites copy Strings too: they are not on a hot path.
- **Not done: `rbOpt[String]`/`rbOpt[Symbol]`, and a nil `*Array`/`*Hash` for `Array?`/`Hash?`.** Both would remove the box, not just the alias, but each rewrites the prelude's `%x{}` bodies by hand as 396 did for Integer/Float (about 229 `String?`, 56 `Symbol?`/`bool?` and 56 `Array[..]?`/`Hash[..]?` signature sites), and `rbOpt[String]` is 24 bytes where zip's pairs paid +3.9% for 16 → 24 under 396. `rbOpt[String]` is the way to drop the String carve-out; its own cost (24-byte `Array[String?]` elements and Hash keys) is unmeasured.
- **Measured** (instructions retired, M, GOMAXPROCS=1, median of 5, paired runs alternating, main at 7192cc9 → this; spinel's template, json_parse, tree_walker, histogram and huffman with `--nil-check=runtime`): array 153 → 153, bignum 540 → 549 (+1.6%; +0.4% in a rerun of 9), binary_trees 58 → 57, blocks 390 → 391, collections 1,400 → 1,399 (minimum of 9: its runs are bimodal, ~1.4G or ~1.8G, on both binaries), exceptions 1,273 → 1,278, fib 156 → 156, format 1,665 → 1,665, hash 85 → 85, json 1,979 → 1,998 (+1.0%), kramdown 4,283 → 4,308 (+0.6%), liquid 1,855 → 1,861, math 52 → 52, objects 493 → 493, pairing_heap 811 → 768 (noise: +0.1% in a rerun of 9), regexp 3,107 → 3,095, splay 51 → 51, strings 310 → 309; bm_csv_process 5,762 → 5,765, bm_histogram 11,663 → 11,663, bm_huffman 276 → 279 (+1.0%), bm_json_parse 3,373 → 3,375, bm_template 8,988 → 8,987, bm_tree_walker 1,265 → 1,265, bm_wordfreq 52 → 51. All 25 print what MRI prints.
