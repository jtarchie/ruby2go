# Decision 318

**Rule:** `RUGAROO_UNTYPED_WHY` traces untyped roots through block params, multiple assignment and or-assignment (debug only).

**`RUGAROO_UNTYPED_WHY` traces through block parameters, multiple assignment and `||=`** (amends 283; 2026-10-19). The tracer named any untyped local that was not a plain `x = v` "local set by a non-plain write", which the 2026-10-19 research read as a compiler gap (17 of cuba's roots). Traced through, every one was a gem parameter no typed call reaches, an untyped ivar (`@app`, a Rack app by duck type), or `inject`'s memo from such a value: `blockParamWhy` names the block's call (an untyped receiver's root, `inject`'s untyped memo, or the yielding method), `noteAnyTargets` a multiple assignment's untyped value, and a first `x ||= v` its value. Debug-only (`fctx.blockWhy` is set only under the flag). The lever that label suggested, flow typing of such writes, has no cases to fix; what remains in gem programs is gem signatures (decision 160, `sig/gems`) and trace typing (memory `minimize-untyped`).
