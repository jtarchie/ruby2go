# Decision 376

**Rule:** `require "yaml"` (or `"psych"`) loads Psych's API with goccy/go-yaml as the parser and Psych's own YAML 1.1 rules for values; dump output is rugaroo's own emitter, which Psych reads back to the same value but does not match libyaml's text.

**YAML over go-yaml** (2026-10-26). Psych is a C extension around libyaml, so it cannot be compiled as user code. `libs.go` maps `yaml` and `psych` to `prelude/yaml.rb` (loaded only on a literal `require`, 155); it `require_relative`s `date` as Psych does. `github.com/goccy/go-yaml` v1.19.2 (MIT, no dependencies of its own) is the third Go module generated programs may import, wired as regexp2 (242) and purego (326): pinned in `GoMod`/`GoSum`, imported only when the YAML helpers survive pruning. Only its `parser`, `ast` and `token` packages are used.
- **Loading.** go-yaml's AST is walked in `prelude/go/yaml.go`; go-yaml's own scalar typing is ignored (it follows YAML 1.2: `yes` is a String there). A plain scalar goes through a port of `Psych::ScalarScanner#tokenize` (`yes/no/on/off`, `~`, `017` octal, `1_000`, `1:30` base 60, `:sym`, `.inf`, dates, times); a quoted one stays a String; tags `!!str`, `!!float`, `!!binary`, `!ruby/symbol` are honoured, and any other tag on a scalar (`!!int`, `!!null`, a local tag) tokenizes its text, quoted or not, as Psych's `deserialize` does. A mapping becomes `Hash[String, untyped]` or `Hash[Symbol, untyped]` when every key is one (as JSON, 25), else `Hash[untyped, untyped]`, in document order; later duplicate keys win; `<<` (plain or quoted, not `!!str`) merges a Hash or a list of Hashes, and anything else under it stays a `"<<"` pair, as Psych's rescue of `TypeError`. An explicit `---` with no node is a nil document; only a stream with no document gives `fallback`. The result is `untyped`.
- **Psych 4 safety.** `load` is `safe_load` with `Symbol` permitted; `safe_load` permits nothing but core scalars and collections. `permitted_classes`, `permitted_symbols`, `aliases`, `symbolize_names`, `freeze`, `fallback`, `filename`, `strict_integer` and `parse_symbols` are read. A class not permitted raises `Psych::DisallowedClass` (checked before the value, as Psych's class loader is asked first); an alias without `aliases: true` raises `Psych::AliasesNotEnabled`. `unsafe_load` and `load_stream` permit everything core; a `!ruby/object:` (or any other `!ruby/` class tag) raises `DisallowedClass` when restricted and `NotImplementedError` when not, since building an arbitrary object needs runtime reflection (82).
- **Dumping.** go-yaml's encoder was tried first: it takes only `string` keys in an ordered map and quotes by YAML 1.2, so `{1 => "a"}` and `"yes"` would not come back. `rbYAMLDump` is a small block-style emitter instead: Psych's `---` header, sequences under a key not indented, a String quoted when `tokenize` would read it as something else (or it has YAML syntax in it), `|`/`|-`/`|+` for multi-line text (indented 2 at the top level, as libyaml), a String of only line breaks double-quoted, a non-UTF-8 String as `!binary` base64, `:sym` or `!ruby/symbol`. `YAML.unsafe_load` in both rugaroo and MRI returns the dumped value unchanged on the tests' corpus. The text often equals libyaml's but is not held to it (the user's call: differences accepted), so tests compare loaded values, not dump text. Options to `dump` are ignored; a user object raises `NotImplementedError`.
- **Differs from Psych.** An integer scalar past 64 bits raises `RangeError` (as `JSON.parse`, 25), even under `--int-overflow=promote` (372; wiring it to Bignum is the follow-up). `Psych::SyntaxError` keeps Psych's class, `file`, `line`, `column` and message shape `(file): problem context at line L column C`, but the problem text and position are go-yaml's (minitest checks the class, not the message, as with 20). go-yaml rejects a collection as a mapping key (`[1, 2]: x`), which libyaml accepts. A `Date` carries no calendar start (`-Infj` in MRI's `inspect`). An anchor cannot be aliased inside its own node (a recursive structure raises `AnchorNotDefined`: the Hash's key type is picked only once its pairs are known). go-yaml drops a document after an empty one (`---\n--- 1`). No `Psych.parse`/`parse_stream` node tree, `load_stream` block form, `Psych::Set`, `!ruby/struct`/`!ruby/object` revival, or `YAML::Store`.
- **Proof:** example 128 (`examples/128_yaml`: config with anchors and merge keys, a Date behind `permitted_classes`, a dump round trip), `testdata/test/yaml_test.rb` (21 tests against MRI's Psych 5.4).
