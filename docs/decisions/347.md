# Decision 347

**Simple patterns match without RE2; a regex-to-Go compiler declined again** (amends 242, 332; 2026-10-23). *See also decisions 242, 332.* A profile (linux/arm64) of `benchmarks/regexp.rb` put 60% of its run in Go's `regexp` and none in regexp2: four trivial patterns (`/\d/` and `/[aeiou]/` in gsub, `/[\s\/?=]+/` in split, a scan) took most of it, at microseconds a line, because Go's regexp runs even a one-character class through its backtracker. kramdown spends 23% in RE2 and 11% in regexp2.
- **`rxFast`.** A translated pattern that is one ASCII character class, such a class with greedy `+`, or a case-sensitive ASCII literal, each optionally `\A`-anchored, matches with a 256-entry byte table or `strings.Index` (`rxtranslate.go`, so interpolated patterns get it too). `rxNew` decides once, only for a pattern with no Onigmo `^`/`\b` reading and no empty match (`prog` nil), so no group, assertion or empty-match rule applies. Exact on any subject: an ASCII byte of UTF-8 is a whole character, and an invalid byte is not in an ASCII class to RE2 either. Every `rxRegexp` entry point the prelude uses (`MatchString`, `FindStringIndex`, `FindStringSubmatchIndex`, `FindAllString(Submatch)Index`, `FindPrefixSubmatchIndex`) checks it first. **Proof:** `TestRxFastMatchesRE2` (internal/compiler: every taken pattern equals RE2 on random ASCII, multibyte and invalid-UTF-8 subjects; lazy `+?`, groups, case folding, non-ASCII, `\b`, `^` and empty-matching patterns are refused), `regexp_extended_test.rb` `RegexpFastPathTest` (gsub, scan, split, `=~`, `match?`, `index`, MatchData and StringScanner against MRI).
- **Anchored matches read the string up to 8,192 bytes** (`rxPrefixDirect`; decision 332 used 256). kramdown's paragraph scanners run on 2-4 KB rests, where RE2's reader costs about twice its string search.
- **Measured** (instructions retired): `regexp.rb` 5,072M to 2,940M (a hand-written Go port using `regexp` is 3,533M; MRI ~8,800M), kramdown 4,639M to 4,407M.
- **Not done, and why: a Ruby-regex-to-Go compiler** (the question decision 242's regexp2cg trial asked on 2026-10-21, asked again). After `rxFast`, regex work is ~23% of `regexp.rb` and ~35% of kramdown, so even an infinitely fast engine buys at most ~1.2x and ~1.5x. A backtracking code generator with Onigmo's semantics (lookaround, backreferences, atomic and possessive groups, `\G`, `\K`, case folding with multi-character folds, Unicode classes) is ~4-6k lines plus a corpus, and its build cost scales per pattern: regexp2cg's +0.4 s and +136 MB per 8 patterns would be ~+5 s and ~+1.8 GB for kramdown's ~109. A DFA (re2c / regex-automata style) cannot do backreferences or lookaround, so regexp2 would stay as a third engine. Also measured and declined: coregex (a pure-Go RE2-compatible engine; faster on long scans, 1.5-75x slower on short anchored subjects, and a new dependency). Lowering more constructs onto RE2 (a trailing atomic group to a plain group, a one-character lookbehind to a byte check) stays available pattern by pattern when one is hot.
