# Decision 362

**Rule:** An `@x` that a top-level statement writes is, where self is main (top-level statements and blocks of calls that keep self), a program local named `@x`, nil where nothing writes it; `self::X = v` in a class body declares that body's `X`; nil as the `self` of an Object free func is nil itself; `x.is_a?(D)` on an unrelated concrete class narrows `x` to `D`'s zero value.

**First batch of #114, the ruby/spec gaps against spinel** (2026-10-24). *See also decisions 14, 120, 331, 360, 361.* Each extracted spinel example is one top-level program, so four things MRI accepts there cost rugaroo the most examples:

- **Main's ivars** (537 rejects, "instance variables are only supported in struct classes and modules"). mspec's `before` blocks, inlined by the extractor, set `@array = [...]` at the top level. Main is one object for the whole program, so its ivars are exactly a program-scope local: `lowerMainIvars` (parse time, user and gem files) rewrites every `@x` read, write, op-write and target where self is main into a local named `@x` (Go `iv_x_m`), added to the program's locals with the block depth it is read at, so decision 14 types it from all its writes and blocks close over it. Not lowered: a `def` body (a top-level def is a private method on every object, its self is not always main: the error stays), a class/module body, and the block of a call that changes self (`instance_eval`, `class_eval`, `define_method`, `new`, `define`, ...). A read of an `@x` nothing writes is `nil`, and so is `defined?(@x)`; `defined?(@x)` of a written one is `"instance-variable"`. Ponytail: `defined?` answers that even before the first write runs, and a read some path reaches before the write is decision 14's `T?`; `instance_variable_get`/`instance_variables` on main do not see these, and two required files do not share them.
- **`self::X = v`** in a class or module body (209 rejects, "unknown namespace self") names the body's own constant, as `X = v` does (`declName`); reads already resolved self there (decision 120). At the top level self is main, which MRI rejects with TypeError, and rugaroo still reports it.
- **nil as an Object method's self** (209 wrong answers: `/\W/.match("a").should == nil`). A call on a `T?` whose method a reopened Object defines takes nil's arm with the typed nil `(*NilClass)(nil)`; passed to the free func's `self any` it is no longer nil (it printed `#<NilClass:0x0>`). `callCode` boxes it `rbNilAny` (decision 331) for the free-func and dispatcher forms; a direct Go method on the receiver keeps the pointer.
- **`is_a?` on an unrelated class.** A `String?` tested for `Regexp` (or `Array`) narrowed to a Go type assertion on a non-interface, which did not compile. The class part is static, so the branch never runs: `x` is narrowed to `D`'s zero value, `*new(T)`.
- **Proof:** `control_output.rb` (main's ivars), `object_test.rb` `test_self_constant_write`, `test_nil_receiver_self_is_nil`, `control_test.rb` `test_is_a_narrows_optional`.
- **Amended (2026-10-24, after rugaroo's own ruby/spec runner fell from 8,561 to 4,471 `core` passes):** mspec's `before`/`it` blocks are receiverless DSL calls whose blocks run on a shared context object, and an `@io` set in `before` and read in `it` became two block-local locals ("undefined local @io"). Now the lowering leaves the block of a receiverless call alone unless the call keeps main as self (`mainSelfCalls`: `loop`, `proc`, `lambda`, `catch`, `at_exit`, `tap`, ...), and lowers only names some top-level statement writes (a dry pass first): a write only inside a block would be that block's local, unseen by a read in another. Proof: `spec_test.rb` "ivars set in before".
