# Decision 408

**Rule:** A program's own module whose method overrides a superclass method of an includer with a signature no adapter fits is a compile error naming both methods, as a class's own override is, and ruby/spec runs a directory's files one at a time when the directory's one program produces no results.

**Module overrides and spec isolation** (2026-10-29). *See also decisions 249, 127.*

- **Module between a class and its parent.** `class A < BaseA; include M; end` where `M#foo` returns another type than `BaseA#foo` reached `go build` as `*A does not implement BaseAI (wrong type for method Foo)`. `relinkModuleOverrides` handled the case for gem modules only (adapters, decision 249). It now covers a program's own modules too: an override an adapter fits gets the adapter, and one none fits is `M#foo: () -> Integer overrides BaseA#foo: () -> Symbol, but its Integer result cannot stand in for Symbol; give it the parent's signature or another name`, the message a class's own override gets. Prelude modules are left alone. Proof: `module_override_mismatch` in `testdata/errors/objects.txtar`.
- **`cmd/rubyspec` isolates files.** The harness compiles a directory's spec files into one program, so one file that did not compile, build or run took every other file in its directory with it (`language` produced nothing: `super_spec.rb` plus `constants_spec.rb` hit the error above). When a directory's program ends fatal and holds more than one file, `runIsolating` runs the files one at a time, adds their results, and lists the files that still produced nothing (`FATAL file: reason`), each counted in "programs failed" and in the exit status. Proof: `TestMergeAndFailedFiles`; `language` went from no results to 2,507 examples, 975 passing.
