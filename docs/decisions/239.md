# Decision 239

**A `Thread` subclass starts on its own embedded `Thread`** (amends
202, 223). `class SubThread < Thread` embeds a `Thread` value (decision
202), and `SubThread.new { ... }` compiled to `NewSubThread()`: the
block dropped, the thread never started, `done` a nil channel, so
`join` waited forever (ruby/spec `core/thread`, hidden until decision
233's amendment let the directory build). Copying a started `Thread`
into the subclass cannot work: the goroutine writes `val` and `err` on
the original, and the struct holds `sync.Map` and atomics. Now
`rbThreadStart(t, run)` starts a thread in place (`rbThreadRun` is it
on a new `Thread`), and `Thread#initialize` (`(*untyped) ?{ () ->
untyped }`) calls it on `self`. `genGoTypeNew` takes a subclass whose
inherited `initialize` takes a block down the path a subclass with its
own `initialize` takes: the empty object, then `initialize` on it, which
reaches the embedded base. `super { ... }` into it passes its block
(`genContainerSuper` uses decision 223's `superBlock`, and calls a
non-generic base's Go method, not a free func). Without a block,
MRI's `ThreadError` ("must be called with a block"). `Thread.new` itself
is unchanged.
- **Not done (ponytail):** a zsuper's arguments are accepted and not
 passed to the block (a block taking them is a compile error);
 `Thread.current` inside the thread is the embedded `Thread`, not the
 subclass object.
- **Measured:** ruby/spec `core/thread` 55 → 57 pass.
- **Proof:** `object_test.rb` `GoTypeSubclassTest#test_thread_subclass_runs_its_block`.
