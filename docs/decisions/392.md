# Decision 392

**Rule:** In gem discovery, an untyped value read back out of a container (an element, a pop, a destructured field of a held Array) neither declares nor widens an ivar, so the ivar's typed writes declare it whatever the method order; a method's untyped return still declares it untyped.

**Stored values do not decide an ivar** (#137; amends 225, 330, 383, 384; 2026-10-26). *See also decisions 225, 330, 383, 384.* kramdown's `Parser::Kramdown` keeps its state in `@tree`, `@src`, `@block_ial`, `@stack` and `@text_type`, and round-trips it through storage: `reset_env(opts = {})` sets `@tree = opts[:tree]` from a `Hash[Symbol, untyped]`, `save_env` returns `[@src, @tree, @block_ial, @stack, @text_type]` and `restore_env(env)` splats it back (`@src, @tree, ... = *env`), and `parse_blocks`/`parse_spans` push `[@tree, @src, @block_ial]` on `@stack` and pop it back (`@tree, @src, @block_ial = *@stack.pop`). Decision 383's first write declares; the first write of `@tree` that discovery reached was the pop (line 160), untyped, so `@tree` was untyped although its only other writes (`@tree, @block_ial = el, nil`, `@tree, @text_type = el, text_type`) store an `Element`: 289 "why: ivar" dynamic calls. Decision 384 had found that typing `@stack` would not do it (it holds three shapes, one a bare Element from `Html::Parser#parse_raw_html`).

- **The rule.** During discovery, in gem code, an ivar write whose value is untyped and read out of storage does not declare the ivar: a stand-in (`untypedIvar`, `c.untypedIvars`) reads and writes as untyped and declares nothing. Storage (`storageRead`, `storageDestructure`): `r[k]`, `fetch`, `dig`, `pop`, `shift`, `first`, `last`, `delete` on an untyped value, an Array, a Hash, or an ivar discovery has not typed yet; or a multiple assignment's fields of a held Array (`a, b = env`, `*env`, `*@stack.pop`). A typed write anywhere in the class then declares the ivar, and the stored values convert where they land (decision 225's cast, nil to a pointer's nil). An ivar only storage wrote is declared untyped after discovery, as before.
- **Why storage and not every untyped value.** A container holds what the program put in it, and the program's typed writes of the same ivar are what it put in (the save/restore round trip). A method's untyped return is evidence of the opposite: its returns joined to more than one class. The first version deferred every untyped write and typed liquid's `Cycle#@name` `String` from `@name = @variables.to_s`, where `@name = Expression.parse($1)` is a `VariableLookup` for `{% cycle g: 'a', 'b' %}`: TypeError where MRI prints. That write still declares `@name` untyped. The rule stays a guess for storage that holds another class than the ivar's typed writes; such a value raises TypeError where it lands, as decision 225's cast already did whenever the typed write came first.
- **String edits.** A gem's String edit on an untyped ivar stores the edited value back (decision 330); in discovery that write-back no longer declares an undeclared ivar String: it stores what the ivar held (`Kramdown::Document#@warnings.concat(warnings)` typed `@warnings` String once the destructured write before it stopped declaring it).
- **A tuple reaching untyped opens its boxes.** `TupleN._ToAny` put a `T?` field's `*T` box (or a nil one) into the `Array[any]` as is, so `@stack.push([@tree, @src, @block_ial])` followed by a pop into the now-typed `Hash?` `@block_ial` raised "no implicit conversion of NilClass into Hash": each field goes through `rbUnbox`, as an Array's elements do.
- **Measured** (`RUGAROO_GEM_WARNINGS=1 RUGAROO_UNTYPED_WHY=1 rugaroo gen -trace benchmarks/kramdown.rb`): dynamic-call warnings 982 → 846, "why: ivar" 289 → 112, `rbDyn` sites 2,259 → 2,076, functions 9,934 → 9,935; `@tree` is `*Kramdown_Element` and `@block_ial` `Hash?`, nothing else moved. Instructions retired (GOMAXPROCS=1, paired, median of 5): kramdown 4.378G → 4.338G (-0.9%), output == MRI. liquid: 451 dynamic-call warnings before and after, generated structs identical, 1.955G → 1.956G (noise), output == MRI. TestCompileCost compiled functions unchanged: 05_word_count 2,032, 64_observable 7,948, 116_cuba_web 30,419.
- **What is left on kramdown's ivars:** `@options` (57 co-occurring sites; `Parser::Base#@options = Options.merge(options)`, an unannotated return) and `Element#children`'s `Array[untyped]` (decision 333, by design). The first version also typed liquid's `ResourceLimits` `@render_length`/`@render_score`/`@assign_score` (written through `attr_accessor` writers whose parameter is untyped), worth -4.5% on the liquid benchmark; that is a writer-parameter question, not storage, and is left for a follow-up.
