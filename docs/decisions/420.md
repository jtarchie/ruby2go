# Decision 420

**Rule:** A value stored into a typed container through the untyped view converts as rbConv does or raises TypeError, never through `to_int`/`to_str`; and in gem code the fresh Array that an `Array.new(n) { ... }` block with untyped elements returns is an `Array[untyped]`.

**Bundled-gem backfill, tenth batch: matrix's eigenvectors** (2026-10-30). *See also decisions 22, 183, 236, 302, 414, 417.*

`Matrix[[1, 2], [3, 4]].eigen.eigenvector_matrix` was `Matrix[[0, 0], [0, 0]]`, where MRI's is `[[-0.82…, -0.42…], [0.56…, -0.92…]]`: a wrong answer in a program, not only in the spec (decision 417 listed it as `ErrNotRegular` from `v_inv`). EigenvalueDecomposition seeds `@v = Array.new(@size) { Array.new(@size, 0) }` and its other branch assigns `a.to_a`, so `@v` is `Array[untyped]` and each row a typed `Array[Integer]`; hessenberg_to_real_schur then writes `@v[i][j] = <Float>` through the untyped view (decision 302).

- **The view's element store no longer calls `to_int`.** `_set`/`_append` convert with `rbAs[E](v, "element")`, whose last fallback, `rbImplicitConv`, called Float#to_int for an Integer element and stored 0 for 0.82. MRI's Array holds the value as it is, so an element store converts as rbConv does (an Integer into a Float element widens) or raises `no implicit conversion of Float into element (TypeError)`. `to_int`/`to_str` stay for argument positions, where MRI calls them.
- **A gem's untyped rows are built untyped.** When a gem's `Array.new(n) { ... }` block returns into untyped elements (its block's value is `untyped`), a fresh `Array.new(m, seed)` or Array literal it returns is converted to `Array[untyped]` (`untypedRow`): one copy per row at construction, of a value nothing else holds. Not every untyped slot: decision 348 keeps an untyped expected type from binding a call's type parameters, and a typed row stays typed wherever its values agree.
- **`library/matrix` 327 → 331 of 361** (EigenvalueDecomposition's `to_a` and `**` with a non-integer power, and the two others whose inverse went through `v_inv`). Compiled functions unchanged (TestCompileCost 2065, 7949, 30379).

**Design limits left in `library/matrix`:** `Matrix.rows(rows, false)` does not alias the caller's rows (1): the user's `Array[Integer]` rows convert to matrix's `Array[untyped]` ones by copy, decision 22's rule for Go's invariant instantiations; `Float#round(digits ≤ 0)` with a non-literal digits (1, decision 414); the spec_helper's `BeCloseToMatrixMatcher`, dropped because spec code assigns `@expected` from a value of no known type (2, decision 183); and the skipped examples' spec-code strictness and `bignum_value` (decisions 35, 172).

**Proof:** `testdata/run/gem_lenient/mx.rb`'s MxEigen (Float writes into rows seeded with 0, checked against MRI by `testdata/run/gem_lenient.rb`; a TypeError before the row fix, zeros before the store fix); `library/matrix`.
