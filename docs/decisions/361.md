# Decision 361

**Rule:** A program's own `$globals` are package variables typed by their first write (its `#: T`, else a literal); an Integer literal past 64 bits warns and raises `RangeError` where it runs; a local only ever `nil` is a `NilClass`; a parameter only its `= nil` default types is untyped.

**What spinel's ruby/spec harness needed** (amends 14, 35, 61, 183; 2026-10-24). *See also decisions 35, 61, 183.* To compare with spinel on ruby/spec, rb2go runs spinel's own harness (`tools/rubyspec/`): each `it` example becomes one standalone program with spinel's `mspec_lite.rb` prepended. Every extracted program failed to compile under rb2go, on four things MRI accepts:

- **Program globals.** `mspec_lite.rb` counts with `$spec_pass += 1`; decision 61 allowed only the builtin globals. Now every `$name` a non-prelude file writes (that is not a builtin or an English alias) is a package variable `rbGv_name` (`userGlobals`, after `methodClassVars`): typed by the first write in file order, from its `#: T` or a plain literal, as a class variable first assigned in a method is (`methodClassVars`, #52), else a compile error asking for the annotation. `$x = v`, `$x op= v`, `$x ||= v` and `$x &&= v` compile against it. A read of a global nothing writes stays a compile error. Ponytail: a read before the first write answers the type's zero value where MRI answers nil.
- **Integer literals past 64 bits** (`mspec_lite`'s never-called `bignum_value` is `0x1_0000_0000_0000_0000`) were a compile error. Now they warn and compile to `rbBigLiteral`, which raises the `RangeError` an overflowing operation raises (decision 35): code that never evaluates one runs.
- **A local only ever `nil`** (the extractor's `scratch_pad = nil` in an example that never uses it) was "cannot infer the type of x from nil". Now it is a `NilClass`, the typed nil pointer rb2go already has, so `x.inspect`, `x.nil?`, `x.to_a` are nil's own static calls.
- **A parameter typed only by its `= nil` default** (`raise_error(cls = nil, msg = nil)`, called only with untyped values) was `NilClass`, and its `msg.is_a?(Regexp) ? ... : ...` failed to compile. Nothing but the default typing it says nothing about its callers, so it is untyped with decision 183's warning, as a parameter no call types.
- **Proof:** `globals_test.rb`; `strings.txtar` `global_never_assigned`, `global_first_write_untyped`; `numbers.txtar` `bignum_literal` (now a warning). The `testdata/errors` cases for a nil-only local now compile and moved to `globals_test.rb`'s `test_only_nil_local`.

*See also decision 372* (under `--int-overflow=promote` a literal past 64 bits is a Bignum).
