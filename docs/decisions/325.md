# Decision 325

**macOS `brew install wget` recheck after 324: Mach-O is read for real** (#100; amends 12, 198, 323, 324; 2026-10-20). *See also decision 326* (patch 0030's fallback). Rerunning `macgen build`/`macrun` after decision 324 printed "Failed to read Mach-O binary" twice. The cause was older than 324: decision 323's run never parsed a Mach-O file. ruby-macho failed at once with an error brew swallows, so linkage checking saw no dylibs. Output still matched MRI because wget's arm64 bottles already carry `/opt/homebrew` install names, so relocation has nothing to change. Getting the parse to work exposed three gaps; with them fixed, stdout, stderr and exit status each equal MRI's again, and the installed wget runs, links and passes `codesign -v`.
- **A local bound once to a literal names a computed ivar.** ruby-macho's field readers are `define_method(name) { instance_variable_defined?("@#{name}") || instance_variable_set("@#{name}", ...); instance_variable_get("@#{name}") }`. Decision 198 bakes the captured `name` into the def as `name = :cpusubtype`, but no ivar `@cpusubtype` was declared, so the set raised NameError. `declareComputedIvars` (324) now also takes a local the body writes exactly once with a Symbol or String literal (`literalLocals`).
- **A class-picked overload converts generic arguments.** An untyped call's twin chosen by its first argument's class (decision 12; `dynClassOverloads`, `dynArityOverloads`) tested `args[0].(*Range[Integer])`. A gem's `start..stop` of untyped bounds is a `*Range[any]` and missed the test. A generic instantiation is now tested with `rbConv` (`dynClassTest`), so Integer bounds convert as they would for a typed parameter.
- **`String#slice(range)` on an untyped receiver.** The dynamic `slice` had no Range form. Its overload search (`__slice_` prefix) instead found `__slice_rest`, decision 233's helper for what `slice!` leaves behind, and returned the remainder (`"abcdef".slice(3..4)` gave `"abcf"`). The helper is renamed `__rest_of_slice`, and `__slice_range` is the real overload. Helper names must not start with a public method's `__<name>_` prefix.
- **No Fiddle function calls (brew patch 0030).** On macOS a system dylib exists only in dyld's shared cache, so `LinkageChecker#dylib_found_in_shared_cache?` calls `_dyld_shared_cache_contains_path` through Fiddle, which raises `Fiddle::DLError` in a compiled program (324). The patch rescues it and treats `/usr/lib/` and `/System/Library/` paths as cached. That gives the same answer for every bottle that links only system libraries from those directories. The fallback is the same kind as 324's Landlock one: #32 (Fiddle over purego) would remove both.
