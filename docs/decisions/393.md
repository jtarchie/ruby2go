# Decision 393

**Rule:** `--nil-check=compile|runtime` (or a file's `# nil_check: mode` line, for the code written in that file) picks what a `T?` where `T` is expected does: `compile` (the default) is decision 20's compile error; `runtime` compiles it to a check that raises on nil, MRI's own exception at a core operator's argument and `TypeError` "no implicit conversion of nil into T" at any other boundary.

**Opt-in run-time nil checks** (amends 20; 2026-10-26; #129). *See also decisions 20, 248, 359, 360, 372, 378, 381.* Decision 20 makes a program prove a `T?` is not nil before using it as a `T`. That catches nil bugs before the program runs, and it is why 18 of spinel's 74 benchmarks did not compile: `a[i]` and `h[k]` are `T?`, and the programs use them as values, as Ruby lets them. MRI and spinel check at run time. The compile error stays the default, since it is part of what rugaroo offers; `runtime` is the program's choice.

- **Selecting the mode,** as decisions 372 and 381 do for overflow: the CLI flag (`build`, `run`, `gen`, `test`) sets `RUGAROO_NIL_CHECK` (`envConfig.NilCheck`); a user or gem file's own `# nil_check: mode` line (`File.nilCheck`, read in `parseFile`) governs the code written in it, else the flag does (`fctx.nilRuntime`). The prelude never takes it: it has no such sites, and twin selection in it stays as it was. An unknown mode is a compile error naming the file. MRI ignores the comment, so the file stays runnable.
- **Where it applies.** Every site that raised decision 20's error: a `T?` coerced to a class (`coerceClass`), to a union without nil (`coerceToUnion`), an annotated ivar write `@x = v #: T` of a `T?` (`annotatedIvarValue`), and nested destructuring of a non-Array `T?`. Each compiles to `rbNilArg(p, msg, arg)` (a pointer `*T` box: nil raises, else `*p`) or `rbNilArgV(v, msg, arg)` (a leaf's `*C` or a non-leaf's interface `CI`, which hold nil themselves: decisions 360, 378). Gem code is untouched: it was already lenient (decisions 172, 248). Two call shapes look at the argument before its parameter does: overload twins (`overload`) pick by the unwrapped class, as gem code does, so `1 + float_or_nil` takes Integer's Float twin; and `numericTower` unwraps a numeric `T?` first (`nilNumArgs`), so the mix converts as MRI's coerce would.
- **The error.** `nilMessage` picks it from the call whose argument is coerced (`fctx.nilArg`: the method, its receiver's type and the parameter as declared), where the method is the prelude's: `<`, `>`, `<=`, `>=`, `between?` raise ArgumentError "comparison of C with nil failed"; Integer and Float arithmetic (`+ - * / % ** & | ^ fdiv div divmod modulo quo pow remainder`) TypeError "nil can't be coerced into C"; Integer's `<<`/`>>` "no implicit conversion of nil into Integer"; another declared Integer parameter (an index, `String#*`) "no implicit conversion from nil to integer"; a Float one "can't convert nil into Float"; anything else "no implicit conversion of nil into T" (String's `+`, `Array#+`). Each was checked against MRI 4.0 (`NilCheckTests`). It is a rule over the prelude's signatures, not MRI's C code, so a core method whose C conversion differs (`Integer.sqrt(nil)`: MRI's "of nil into Integer") can word it differently.
- **Equality answers, not raises.** `==`, `!=`, `eql?`, `equal?` and `===` with a `T?` argument already compiled (they take any value) and keep their twins off the unwrap path. `a <=> b` of a `T?` b on a prelude `<=>` answers nil when b is nil (`nilSpaceship`), as MRI's does; a program's own `<=>` gets the nil, also as in MRI.
- **Where MRI differs.** Elsewhere MRI carries the nil in and fails later, or never: a typed parameter of the program's own method (MRI raises NoMethodError inside it, or not at all), a union parameter (`show(nil)` where `x.to_s` gives `""`), an annotated ivar, an `Array[Integer]` element (`a[i] = b[j]` stores nil in MRI; here the Array cannot hold one), nested destructuring (MRI binds nils). rugaroo raises TypeError at the boundary: the value cannot be represented past it. The tests check only that these raise.
- **Not covered:** `x.method(:name)` on a `T?` stays a compile error (MRI raises NameError on nil; rare). Calling a method on a `T?` already raised NoMethodError on nil in both modes (decision 20).
- **Spinel's 18 nil-blocked programs** under `--nil-check=runtime`: 13 compile and print what MRI prints (fasta, histogram, huffman, jekyll_lite, json_parse, matmul, nqueens, reader_index, sinatra_mini, spectral_norm, sudoku, template, tree_walker; BENCHMARKS.md has their times, 12.9x MRI against spinel's 34.5x on those rows). handle_readonly_param, ruby_xor and str_readonly_param stop at `String#setbyte` (decision 58's immutable Strings). fannkuch (loops forever) and stark_field (wrong numbers) compile but hit #133: `Array#[]` answers a pointer into the Array's storage, so `t = q[i]; q[i] = q[j]; q[j] = t` reads `t` after the write and the swap does nothing; fannkuch's permutation then never advances. The default mode hid it, since every unguarded `t = a[i]` was rejected; with `Array#[]` copying its element both print what MRI prints. #133 measured that copy at +67% on `bm_life`, so it is left to #133's own design.
- **Found on the way:** `(1..x).to_a` with a nil `x` (an endless Range) loops until memory runs out in both modes; MRI raises RangeError.
- **Measured.** The default build is the same Go: `gen` of examples 05, 30, 64, 100, 116, 120, 126, 129 and 131 is byte-identical before and after. `TestCompileCost` compiled functions 2,032 / 7,948 / 30,419, unchanged.
- **Proof:** `testdata/test/nil_check_test.rb` (`# nil_check: runtime`: every core-operator error above with its class and message, equality answers, and the boundary raising for a pointer `Integer?`, a leaf `C?` and an interface `C?`, against MRI); `numbers.txtar`'s `nil_check_default_compile`, `nil_check_compile_comment` and `nil_check_bad_mode`; example 132.
