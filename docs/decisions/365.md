# Decision 365

**Rule:** A def's tail `yield` and tail core `each` are its value when some call of that name uses a value (else it stays a void Go iterator); a used core `each` answers its receiver; a user class may subclass Numeric, as an Object with Comparable; `String.new` and `pack` of a literal format without `U` are BINARY.

**Fourth batch of #114** (2026-10-24; the iterator values and Numeric subclasses were the user's call: "do what MRI does"). *Amends 4 and 142; see also decisions 172, 183, 241, 352.*

- **Iterator values, as MRI.** `r = xs.each { }`, `f(xs.each { })` and `xs.send(:each) { }` answer xs, as decision 172 already did for gem code, for the `eachReturnsSelf` names on core receivers (`coreEach`); in value position the call runs as the iterator statement on a pinned receiver (`coreEachValue`), and a typed slot (`#: Array[Integer]`) gets it in tail position. A def whose last statement is a yield or a core each is that value when it matters: `callValueUsed` scans the program's own files once for calls of each name whose value is used (not a statement; a def's or block's last statement counts as used), and only for such a name does a tail yield type the block's value (decision 183's `yieldValueUsed` with the tail) or a tail each answer the receiver. Where no call uses the value nothing observable changes, so a def that only yields stays a void Go iterator (decision 4) and costs nothing; a used one is a closure, as decision 4 already makes every value-returning block method. The six `testdata/errors` cases that pinned "the value of an iterator call cannot be used" for core iterators are removed; a user iterator's value used in value position is still that error.
- **User Numeric subclasses** (amends 142). `class X < Numeric` in user code (mspec's `MathSpecs::Float`) compiles as a class whose superclass is Object and which includes Comparable (`superclassOf`). Ponytail: such an object is not a Numeric to `is_a?`/`ancestors`, Numeric's defaults (`zero?`, `positive?`, coerce arithmetic) are absent, and Math functions still take Float (decision 20); the closed Numeric set of decision 142 is unchanged. The prelude still cannot subclass it.
- **BINARY producers** (decision 352): `String.new` with no argument (`__new_0`, `@binary`; `String.new(s)` stays s's) and `Array#pack` with a literal format that has no `U`, `u`, `m` or `M` directive (`__pack_binary`, `literalOverload`) are binary Strings, so their `encoding` is MRI's ASCII-8BIT. Ponytail: a computed format, and `unpack`'s Strings (Array elements, where decision 352's flavor is lost), stay text.
- **Exception constructors**: `NameError.new(msg, name)` keeps name as given, as a `self.__new_2` overload (decision 12), since the Go helpers construct `NewNameError(msg)`. Not done: `SignalException.new(signo, name)` (a setter for its message gave every exception class a forwarder, +129 functions in example 116), `receiver:` keywords, `SystemCallError.new(msg, errno)`'s errno-to-class mapping and `Errno::X.new(msg, location)`'s message.
- **Proof:** `method_test.rb` `TailValueTest`, `number_test.rb` `NumericSubclassTest`, `string_test.rb` `StringBinaryProducersTest`, `control_test.rb` `ExceptionArityTest`; spinel's harness `language/block_spec` (the `m(a) yield a end` fixture's 103 examples), `core/math` (27).
