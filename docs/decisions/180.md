# Decision 180

**Rule:** A def or lambda body broken by an untyped param returns `untyped` for that inference round; untyped-by-default lambdas; `$/` is `String?`.

ruby/spec phase C (#49).
- **Inference rounds survive bodies their parameters break.** A def or
 lambda whose still-untyped parameter makes its body fail in a round
 (`def take(e) = e.select { ... }`: a block on an untyped receiver)
 returns `untyped` for that round instead of aborting the caller, so
 `take([1, 2, 3])` still records its argument and the next round
 types `e` (decision 146). A lambda's literal stays a Proc value with
 its parameters' inference key.
- **A lambda no call types is untyped** (was a compile error), with a
 warning naming the annotation: its parameters are `untyped`, so its
 body's calls on them are dynamic, as a gem lambda's (decision 169).
- **`$/`** is the input record separator, `String?`, readable and
 assignable (decision 61's set grows): a Go variable, `"\n"` at start.
 `chomp` with no argument uses it ("\n" also takes "\r\n" and "\r",
 another String is `chomp(sep)`, nil returns the String). Other
 readers (`gets`, `each_line`) keep "\n" (ponytail: read `$/` there
 when a spec needs it).
- **Regexp twins** (decision 12's `__<name>_regexp`) for `index`,
 `rindex`, `byteindex`, `byterindex`, `partition` and `rpartition`;
 `rindex` tries each start on the rest of the String, so a lookbehind
 sees no text before it. `byteslice(range)`.
- **Proof:** `infer_test.rb` `test_block_on_a_parameter_its_call_types`,
 `string_test.rb` `StringRegexpTwinsTest`, `arrays.txtar`
 `block_arg_proc` (now a warning).
