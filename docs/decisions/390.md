# Decision 390

**Rule:** `xs.zip(ys) { }` and a statement `xs.zip(ys).each { }` on Arrays compile to an index loop over both Arrays with the block body inline, and `xs.zip(ys).m { |x, y| }` for a destructuring block and `m` one of `sum count any? all? none? map collect filter_map flat_map select filter reject` runs on an Enumerator over copies of both Arrays, so no Array of pairs is built (`RUGAROO_NO_ZIP_FUSE=1` turns both off); `xs.zip(ys, zs)` is `__zip_2`.

**zip fused into its block** (amends 348, 386; 2026-10-26; #136). *See also decisions 348, 377, 386, 387.* `nums.zip(nums.reverse).sum { |a, b| ... }` built 300,000 `Tuple2` pairs into a new Array (plus decision 348's slab of `U` values), then `sum` walked that Array: two passes, one of them only to materialize. The pairs themselves are Go struct values and cost nothing; the Array holding them and the second pass do.
- **What MRI reads, and when.** `rb_ary_zip` copies each argument once, before the first step (`take_items`: the first `len(self)` elements), and reads `self` at each step. With a block it builds no result and returns nil. Without one, every pair is built before any consumer runs, so a consumer's block that stores into either Array, or grows one, sees none of it. The fused forms keep both: `rbZipTake` is take_items (one `slices.Clone`), `__zip_block`/the block-form loop re-read `self`'s storage and length each step, and the chained forms (`__zip_each`, `__zip_view_enum`) clone `self` too. Each `y` points into the private copy, never into `ys`, so a block that keeps `y` (or the pair) keeps MRI's value: no per-element allocation and no aliasing of the user's Array (the hazard decision 387 found in `Array#[]`).
- **Block form.** `xs.zip(ys) { }` was a compile error ("zip does not take a block"). It is now `Array#__zip_block`, an iterator yielding `[E, U?]`; `resolveIter` takes a `__name_block` twin when the named method has no block and the twin is an iterator. Its value is nil in MRI, and like any iterator call here it is a statement.
- **Index loop.** `countedLoopHead` (decision 387) lowers `__zip_block` and `__zip_each` to an index loop, `pair := rbZipPair(xs, ys, i)` and the body inline rather than a closure Go may not inline: `__zip_block` tests `i >= len(self.s)` inside `for i := 0; ; i++` (a re-read the generated lint's `intrange` would otherwise rewrite away), `__zip_each` ranges over its clone. A statement `xs.zip(ys).each { }` is rewritten to `xs.__zip_each(ys) { }` (`zipEachBlock`): each's value is unused, and the pairs are the same. `break`, `next` and `redo` are a Go `for`'s.
- **Chained consumers.** `noteZipChain` marks the inner `zip` of `xs.zip(ys).m { |x, y| ... }` when the block takes two or more plain required params, the receiver is an Array whose `zip` is the prelude's, and `m` is a listed Enumerator method from the prelude (each returns what Array's does); `callTwin` then takes `__zip_view_enum`, an Enumerator over the two copies. Not marked: a single `|pair|` (the issue's condition; it would be correct too, since a pair is a value), a `zip` held in a variable, any other consumer, a non-Array receiver. Those still build the Array.
- **Three or more Arrays.** `xs.zip(ys, zs)` was an arity error; `Enumerable#__zip_2` (decision 12's arity twin) builds `[E, U?, V?]` triples. Not fused; four or more Arrays stay an error (they need a `TupleN` signature per arity).
- **Found on the way.** `out[0] = [7, 7]` into an Array of tuples did not build: decision 387's `inlineIdxSet` put the `Tuple2{...}` literal in an `if` header, where Go reads its brace as the body. `headSafe` parenthesizes a composite literal there.
- **Cost.** `TestCompileCost` compiled functions unchanged: 05_word_count 2,032, 64_observable 7,948, 116_cuba_web 30,419.
- **Measured** (instructions retired, GOMAXPROCS=1, paired, median of 5): `benchmarks/blocks.rb` 427M to 378M; its zip line alone (`nums.zip(nums.reverse).sum { |a, b| a * (b || 0) % 17 }` after building `nums`) 133M to 82M, against 63M for the same sum as a hand `while` loop; `collections.rb` generates identical Go (1,460M and 1,497M, noise). The block form of that line, and `.each` with a block, each run in ~10M over the fixed cost. Against `RUGAROO_NO_ZIP_FUSE=1`, `map`, `select` (keeping every pair) and `count` over the same 300,000 pairs: 530M to 434M. No benchmark in spinel's suite calls `zip`.
- **Proof:** example 131 (block form, `.each`, `count`, `map`, `sum`, three Arrays, with the generated Go linted); `enumerator_test.rb` `EnumZipFuseTest` against MRI: the block form reading `self` live (grown, shrunk) and `ys` once, kept pairs and kept `y`s unchanged by a later store, every listed consumer with a shorter second Array (nil fill), a consumer's block storing into and growing both Arrays, `break`/`next` in both loop forms, and three Arrays.
