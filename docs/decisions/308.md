# Decision 308

**Generic struct classes are monomorphized** (#104 phase 1; amends 44, 10, 210, 212; 2026-10-18). A class with `# @rbs generic T` (or a sig's `class Box[T]`) whose objects are Go structs used to be the link error "generic struct classes are not supported"; only `@go_type` classes could be generic.
- **Options weighed.** Go generics (`type Box[T comparable] struct`, as decision 165's Hash subclass) turn off decisions 210 and 212 for the class (a generic owner's bodies stay generic, its calls go through interface methods) and leave every call on a `T` value dynamic or constrained; erasure (one `Box` over `any`) makes every read a conversion and every `T` call dynamic. Monomorphization emits one ordinary struct class per closed instantiation the program names, so direct calls, type-switch dispatch and class-ID dispatch on untyped values all apply unchanged, and Go never sees a type parameter. The cost is one struct per instantiation, paid only by programs that use the class.
- **Template and instances.** The class as declared is a *template*: it is collected and linked like any class (its signatures resolve with `TVar`s) but never emitted, and its bodies are never generated (`isTemplate`; discovery, return inference, rounds and emit skip it). `instOf(template, args)` (`generic.go`) is an *instance*: a clone of the template's collected methods, ivars, includes and annotations, made before `nameGo`/`link`, whose signatures and ivar annotations resolve the template's parameter names to its arguments (`resolveNameType`). Every pass then treats it as an ordinary class. A type `Box[Integer]` anywhere (annotation, sig, a substituted signature) resolves to the instance (`classType`), so a call on it resolves on the instance's own methods, never by substituting into the template.
- **Naming.** The instance's Go name is `Box_G<fnv32a of its RBS key>` (`Box[Integer]`), with the key as a comment on its struct: deterministic across compiles (decision 88's build cache), and `_G` plus hex is not a name decision 3's camel-casing produces from a Ruby name (a clash with a user class literally so named gains `_` in `nameGo`, as any clash does). `TClass.String()` of an instance is its key, so messages say `Box[Integer]`.
- **Ruby identity.** Instances share the template's metaclass (`Box.class`, `.name`, `x.class == Box`) and Go class variable. Each instance keeps its own class ID, so decision 209's class-ID dispatch on an untyped receiver tells `Box[Integer]` from `Box[String]` apart; `rbAncestry` lists the template for each (so `is_a?`/`kind_of?`/`===` at run time answer as MRI), and `instance_of?` maps an ID to its template through a generated `rbRubyClassID` switch. A family marker, `Box_Any` (an interface every instance implements with an empty `_Box_Any()` method), is what an untyped `is_a?(Box)`, `Box === x` and `when Box` assert; such an arm keeps the value untyped, since it may be any instance.
- **`Box.new(args)`.** With an expected type that is an instance (`b = Box.new(nil) #: Box[Integer?]`, a parameter typed `Box[untyped]`), that instance; otherwise initialize's parameters bind the template's parameters from the arguments (probed with `genArgs`, as a generic method's call binds its own). An unbound parameter is the compile error "cannot infer type parameter T of Box.new" (phase 3 infers it from later use).
- **Invariance.** Instances are distinct classes: a `Box[Integer]` passed where a `Box[untyped]` is expected is a compile error, never a copy. `Box[untyped]` is the one erased instance, built only where the program names it.
- **Discovery is a restart.** Instances are created before link, so a compile that names one it lacks records its key (`opts.instances`), types it as the template meanwhile (the template's signatures substituted, as for `Array[E]`) and, at the end or at any error, returns `errNeedInstances`; `compile` runs again with it (at most 32 times). One pass finds every sibling instance; only nesting (`Stack[E]#top_box` naming `Box[E]`) costs another. An inference round that names one continues to the next round, which has it.
- **Polymorphic recursion** (`Box[T]#wrap` returning `Box[Array[T]]`) would need instances without end: an instance whose type arguments nest more than 8 deep is the compile error "instantiates Box without end (polymorphic recursion)".
- **Not yet:** generic inheritance (phase 2), `X.new` with no binding argument (phase 3), class methods on a generic class (still an error), `klass.new` on a generic class object held untyped (no class-object `new`: NoMethodError; ponytail), and an unannotated parameter of a template's method (its inferred uses join across instances).
- **Measured** (TestCompileCost, compiled funcs): 05_word_count 1,339 → 1,339, 64_observable 27,086 → 27,087 (`rbRubyClassID`), 116_cuba_web 28,233 → 28,233.
- **Proof:** `testdata/test/generic_class_test.rb` (`Box[T]`, `Stack[E]`, `Bag[E]` including `Enumerable #[E]`, `Pair[K, V]`, each at two or more instantiations; `.class`, `is_a?`, `instance_of?`, `inspect`, `instance_variable_get`, `send` and `map(&:get)` on untyped values, `case/when`, `===`); `testdata/errors/generics.txtar` (unbound parameter, wrong arity, invariance, argument mismatch, polymorphic recursion). `objects.txtar`'s `generic_struct_class` rejection is gone.
