# Decision 261

**Net::HTTP: the request path never names the host; connections are released** (#101; amends 27; 2026-10-14). *See also decision 335.*
- The path is MRI's request-target verbatim: `"@evil.com/x"` is sent as
 `GET @evil.com/x`, not folded into the URL where `host:port` would
 become userinfo. An empty path is `ArgumentError`
 ("HTTP request path is empty"). Paths starting with `/` keep their
 escaping and query handling.
- Each request closes its own transport's idle connections (no
 `Connection: close` header, which servers can see), so a request
 loop no longer leaks an fd and two goroutines per call.
- A timeout while reading the body is `Net::ReadTimeout`, as one
 classification (`rbHTTPFailure`) serves both the round trip and the
 body read.
