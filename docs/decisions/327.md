# Decision 327

**sqlite3 over Fiddle** (#32; amends 150, 155; 2026-10-20). *See also decision 329* (speed). *See also decision 328* (now a vendored gem, `gems/sqlite3-fiddle`, not a prelude file; the API, typing and differences below stand). `require "sqlite3"` loaded `prelude/sqlite3.rb`, a port of the sqlite3-ruby gem's API (2.10.1), and never looks the gem up (the lib table in `libs.go`, decision 155). The gem is a C extension, so it cannot be compiled from source; this is the prelude-copy exception to preferring real gems. Its Ruby layer (`Database`, `Statement`, `ResultSet`/`HashResultSet`, the `Pragmas` accessors, `Exception#message` with the SQL and a caret, `Blob`, `String#to_blob`) is ported; its C extension is `SQLite3::C`: one `Fiddle::Function` per `sqlite3_*` entry point (decision 326), bound at require time from `libsqlite3.dylib` on macOS or `libsqlite3.so.0` elsewhere, with typed wrappers (`C.int`, `C.float`, `C.str`, `C.ptr`) over `call`'s untyped result. The compiler's `extern` synthesis skips prelude files, hence `Function.new` directly. SQL text and bound Strings go through Fiddle's temporary C copies with `SQLITE_TRANSIENT` (−1), so sqlite copies them again before the call returns; `sqlite3_prepare_v2`'s tail pointer is turned into `Statement#remainder` by its offset into the copy. Column and value reads are typed by `sqlite3_column_type`: INTEGER → Integer (int64), FLOAT → Float, TEXT and BLOB → the bytes by `column_bytes` (so embedded NULs survive), NULL → nil.
- **Rows are `Array[untyped]`**, as `JSON.parse`'s result is untyped: `execute` returns `Array[untyped]` whose elements are Arrays, or Hashes under `results_as_hash`, so a typed caller indexes rows dynamically. An `Array[untyped] | Hash[String, untyped]` element type was tried and rejected: `row[0]` on it is a compile error for the Hash arm (decision 150's argument check), the common case. `Statement#step` and `#each` are typed `Array[untyped]`, `ResultSet#next_hash` is `Hash[String, untyped]?`.
- **Binding.** `execute(sql, bind_vars)` takes one value, an Array (positional `?`), or a Hash (`:name`, with or without the colon, String or Symbol keys); Integer → `bind_int64`, Float → `bind_double`, String → `bind_text`, `Blob` → `bind_blob`, nil → `bind_null`, anything else `RuntimeError: can't prepare Class`, as the gem.
- **Blob is a marker class, not a String subclass. Differs from MRI.** A `class Blob < String` compiled, but a `[name, Blob.new(data)]` literal is `Array[String]` (a subclass is absorbed by its superclass, decision 150), and a boxed String subclass unwraps to a plain String there, so the blob bound as text. As its own class the literal is `Array[String | Blob]` and the marker survives. It answers `to_s`, `to_str`, `bytesize`, `length`, `bytes`, `==` (against a Blob or a String), `hash`, `inspect`. Columns read back as plain Strings, as the gem's do. A blob String's `encoding` reports UTF-8 when its bytes happen to be valid UTF-8 (decision 136, #83); the tests compare bytes.
- **Functions.** `create_function(name, arity) { |fn, a, b, ...| fn.result = ... }` and `define_function(name) { |*args| ... }` register a purego callback (`Closure::BlockCaller`, never freed) through `sqlite3_create_function` (eight arguments, the `_v2` form's ninth would exceed decision 326's register-passed limit). A block cannot be typed `(FunctionProxy, *untyped)` (a fixed parameter before a splat yields one value plus an Array), so `create_function`'s block is typed with `fn` plus six `untyped` arguments, padded with nil; a block declares fewer (ponytail: raise past six). A Ruby exception inside the callback cannot unwind through C frames: it is parked on the Database, `sqlite3_result_error` is set, and the `step` that ran the function raises the parked exception, so `assert_raises(RuntimeError)` sees the block's own error, as under the gem.
- **Errors.** The result code's primary code picks the class (`SQLException`, `ConstraintException`, `ReadOnlyException`, `CantOpenException`, ...); `code`, `sql` (prepare errors only) and `sql_offset` (`sqlite3_error_offset`, when the library has it) are set as the gem sets them, and `message` appends the SQL with a caret under the offset, byte for byte MRI's text. Pragmas live on `Database` itself rather than in an included module: a module body's calls on `self` resolve dynamically and warned, and `table_info`'s `prepare` result had to be typed.
- **Differs from MRI, besides Blob:** `prepare`, `query` and `execute` with a block return the Statement, ResultSet or an empty Array rather than the block's value (one typed return per method); `Database#encoding` is from `PRAGMA encoding`; the system SQLite is used, not the gem's bundled one, so `SQLITE_VERSION` and `libversion` differ from the gem's (3.51 vs 3.54 on this macOS); Absent, so a call is a compile-time undefined-method error: `create_aggregate`, `define_aggregator`, `authorizer`, `busy_handler`, `trace`, `collation`, `load_extension`, `serialize`/`deserialize`, `execute_batch2`, `Backup`, UTF-16 database names, the `strict:`/`extensions:` options. `Dir.tmpdir` was added to `tmpdir.rb` for the example.
- **Proof:** example 122 (`examples/122_sqlite3`: binds by position, value and name, typed rows, blobs, `execute2`, `results_as_hash`, a reused prepared statement, a rolled-back transaction, `create_function`, `table_info`, a syntax error's message, a file database opened read-only), `testdata/test/sqlite3_test.rb` (142 assertions against the real gem: rows and types, every bind shape and rejection, `execute2`/`get_first_*`, `results_as_hash`, Statement and ResultSet stepping, error classes/codes/messages, transactions and `execute_batch`, functions including a raising one, pragmas and schema, a file database read-only/read-write); sig `sig/sqlite3.rbs` (the gem ships none).
