# Decision 328

**Rule:** Pure-Ruby vendored gems are `gems/<name>` submodules mirrored into `vendored/`, loaded as strict user code via `vendoredLibs` on a literal require.

**Vendored gems: sqlite3-fiddle** (#32; amends 155, 327; 2026-10-20). The sqlite3 port is a real gem in the repo, `gems/sqlite3-fiddle` (gemspec, README, one file `lib/sqlite3.rb`), that runs on MRI's own Fiddle unchanged, and `require "sqlite3"` under rugaroo loads that same file. `prelude/sqlite3.rb` is deleted. A prelude copy was the C-extension exception to preferring real gems; a pure-Ruby gem over Fiddle is what rugaroo claims to compile, so there is one source of truth and the oracle gets stronger: `TestVendoredGemsMRI` runs `testdata/test/sqlite3_test.rb` under `ruby -I gems/sqlite3-fiddle/lib` (the gem's lib first on the load path shadows the installed sqlite3 gem), `TestMinitest/sqlite3` runs it under MRI with the real sqlite3 gem and under rugaroo with the compiled vendored copy, and example 122 compares the compiled copy with the real gem.
- **Mechanism.** `gems/*/lib/*.rb` is embedded in the prelude FS (`rugaroo.go`), and `vendoredLibs` in `libs.go` maps a require name to its file. `builtinLib` (the prelude's `preludeLibs` or a vendored lib) is what the require scan, gem lookup (`gemRequires` never asks Bundler for it), `findRequire` (a vendored lib wins over an installed gem's copy, as a prelude lib does), the runtime require table and the traced entry consult. `loadVendored` (`compiler.go`) loads the file as **user code** (`originUser`): the `%x{}` escape stays closed, `extern`/`struct` literals are compiled (decision 326, which `isPrelude` skips), typing is strict and dynamic calls warn, so the gem must compile warning-free; it is appended to `userFiles` as a plain (not `required`) file, so its class-body statements (`extend Fiddle::Importer`, `dlload`, `extern`) run in a file block before main's, in load order; a `required` file's body only runs where its require_relative is spliced, and a vendored lib has no such site. Its own top-level `require "x"` lines are loaded first (`vendoredRequire`), since the require scan walks only the program's files. The stub generator and `RUGAROO_ALL_LIBS` load vendored libs too, so `TestPreludeWhole` checks them.
- **Portable Ruby.** Writing for both runtimes changed three things from the prelude version: `SQLite3::C` is an `Importer` module with 51 literal `extern`s (typed module methods under rugaroo; `const char *` returns are declared `void *` and read with `Pointer#to_s`, since cparser's `*` rule makes any pointer a `void*`), `sqlite3_error_offset` stays a guarded `Function.new` (an `extern` of a missing symbol raises at load); the SQL text is copied into `Pointer.malloc` memory and freed, because MRI's `Pointer[str]` aliases the String's own buffer; and TEXT columns `force_encoding(UTF_8)` the bytes `Pointer.read` returns (binary under MRI, a no-op here). The gem has no `frozen_string_literal` comment so that call is legal on its empty-string literal.
- **Differs from MRI** as decision 327 lists. The gem's README states them for users of the gem alone.
- **A submodule, with its own repo and CI** (2026-10-20, later the same day). `gems/sqlite3-fiddle` is the git submodule github.com/jtarchie/sqlite3-fiddle (gemspec, LICENSE, Rakefile, `test/sqlite3_test.rb`, which is the same file as `testdata/test/sqlite3_test.rb`). Its workflow runs the test on Ruby 3.3, 3.4, 4.0 and head on Linux and macOS, and a `rugaroo` job checks out this repo, copies the gem's checkout over `gems/sqlite3-fiddle` and runs `go run ./cmd/rugaroo test test/sqlite3_test.rb --seed 1`, so a gem change is compiled before it merges. **Mirror for the module proxy** (decided the same day): the embed reads `vendored/<name>/*.rb`, a committed copy that `scripts/vendor-gems` makes from each submodule's `lib`, because the Go module proxy ships no submodule contents and `go install github.com/jtarchie/rugaroo/cmd/rugaroo@latest` would fail on the embed. `TestVendoredMirror` fails when a mirror differs from its submodule, so a gem bump is: pull the submodule, run the script, commit both. A release-time copy was rejected (`@latest` from main would still break) and an optional embed too (an install would silently lack sqlite3). A fresh clone builds without the submodule; it needs it only for `TestVendoredGemsMRI` and `TestVendoredMirror`.
- **Adding a vendored gem:** a submodule under `gems/` with a gemspec, `lib/<require>.rb` (one file; `require_relative` inside it is not resolved against the embedded FS, ponytail) and `test/*_test.rb` (`TestVendoredGemsMRI` runs them), a `vendoredLibs` entry, and a `sig/<name>.rbs` for `rbs validate` of examples (the gem ships none).
- **Proof:** example 122 and `sqlite3_test.rb` unchanged from decision 327, now through the gem; `TestVendoredGemsMRI`.
