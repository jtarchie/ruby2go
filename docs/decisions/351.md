# Decision 351

**Rule:** When `weakref` is loaded, each root struct class gets a blank `*byte` field so a referent is never tiny-allocated.

**A WeakRef's referent is never tiny-allocated** (amends 110; 2026-10-23). *See also decision 110.* Go's allocator batches pointer-free objects of 16 bytes or less into one slot, and per package `weak` the weak pointer to an unreferenced object in such a slot "may never become nil" while a neighbour lives. A struct class whose ivars are all scalars (example 80's `Session`, one Integer) is such an object, so `WeakRef#weakref_alive?` after `GC.start` depended on what happened to be allocated next to it: decision 350's Hash layout moved a neighbour and example 80 started reporting the dropped Session alive, every run. When a program loads `weakref`, each root struct class (and the universal `Object` struct) gets a blank `*byte` field: a scanned object, which the tiny allocator never batches. Subclasses embed the root. Cost: 8 bytes an object, only in programs that require weakref. **Proof:** example 80 (fails on decision 350's layout without this), `TestWeakRefReferentsNotTiny` (the field appears with weakref and not without).
