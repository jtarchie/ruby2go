# Decision 215

**`IO.new(fd, autoclose: false)` and `IO#autoclose=` keep a borrowed
descriptor open.** An IO over a descriptor another IO owns (`IO.open(w.fileno, "w") { }`) closed
that descriptor when its block ended, and the owner's later close, or
MRI's finalizer, closed the same number again: by then a later test's
listening socket (`stdlib_test`'s WEBrick server answered
`ECONNREFUSED` under `--seed 1` on MRI itself). MRI's `autoclose:
false` and `autoclose=` mark the IO as not owning the descriptor:
`close` flushes and drops its buffers but leaves the fd (`noclose` on
the Go struct); `autoclose?` reads it (and raises `IOError` on a
closed stream, as MRI does, so the test reads it before closing).
- **Proof:** `testdata/test/stdlib_test.rb`
 (`test_io_open_block_and_read_length`), which now passes on MRI in
 every order.
