# Decision 372

**Rule:** `--int-overflow=raise|wrap|promote` (or a file's `# int_overflow: mode` line, which wins) picks what an Integer result past 64 bits does: `raise` (the default, decision 35, the same machine code as before), `wrap` (Integer `+`, `-`, `*`, `-@` wrap as Go's `int`), or `promote` (a `Bignum` class, loaded only in that mode, holds locals that grow in a loop, `**` results and literals past 64 bits, and MRI calls it Integer).

#113, after spinel's `--int-overflow` (docs/int-overflow.md). Amends decisions 35 and 361, which stay the default.

**Selecting the mode.** The CLI flag (`build`, `run`, `gen`, `test`) sets `RUGAROO_INT_OVERFLOW`, which the compiler reads per compile like the other `RUGAROO_*` settings (`envConfig`). A program's own `# int_overflow: promote` comment overrides both: it is what the program needs, so a test lane run in another mode does not break it, and it keeps the file runnable on MRI (example 126, `benchmarks/bignum.rb`). An unknown mode is a compile error.

**`wrap`.** `prelude/go/integer.go` declares `const rbIntWrap = false`; the compiler rewrites it to `true` in wrap mode. Integer `+`, `-`, `*` and `-@` start with `if rbIntWrap { return self + other }`. Go's inliner charges nothing for an `if` on a constant and SSA drops the dead branch, so the default build is the same machine code (64_observable: the same 3,252 functions at the same sizes), and the checked operators still inline. Only those four operators change, as in spinel; `/`, `**`, shifts, `succ`, ranges and `to_i` keep raising.

**`promote`.** The representation question from the issue: a separate type, not a small-int-or-big Integer everywhere. `Integer` stays a Go `int` in every slot, so the prelude, generic containers and every `%x{}` body are untouched; `Bignum` (`prelude/bignum.rb`, Go type `rbBigV{i Integer; b *big.Int}`, `b` set only past 64 bits) is a value type, so a small one costs two words and no allocation. Which slots are Bignum is decided at compile time:
- **Loop growth** (spinel's `analyze_pass.c` "Loop-growth bigint promotion", which spinel also runs in its default mode; rugaroo only under `promote`): inside a `while`/`until` or a `times`/`each`/`upto`/`downto`/`step`/`loop`/`each_with_index` block, a local rebuilt by `*`/`**` of something its own value flows into (`f = f * i`, `f *= i`), or by `+` of two such (`c = a + b; a = b; b = c`, `a, b = b, a + b`), is promoted (`growthLocals`).
- **Spread by type**: a promoted local is typed Bignum from its first write (`assignLocal` treats it as annotated); then `analyze` reruns pass 1 with every local some run typed Bignum promoted too, until none is added (at most 8 rounds), so `a = b` after `b = a + b` follows.
- **Values**: `Integer#**` returns a Bignum under promote (a power is where integers outgrow 64 bits most), except a power of two literals that fits, which folds to an Integer constant (`(1..10**12) % 2` stays an Integer range); an Integer literal past 64 bits is a Bignum (`rbBigLit`; a RangeError where it runs otherwise, decision 361).
- **Mixing** goes through the numeric tower (decision 142): Bignum sits between Integer and Rational, so `bignum + 1` and `2 * bignum` convert the Integer up (`Integer#__to_big`); `join` of Integer and Bignum is Bignum. Where an Integer is wanted (a typed parameter, an index), a Bignum converts with `rbBignumToInt`, MRI's `RangeError` when it does not fit; an Integer method Bignum leaves out (`times`, `chr`, ...) runs the same way (`bignumFallback`), and the tower then converts the argument down rather than the Integer receiver up (else the two would convert back and forth forever).
- **Being an Integer**: `.class` is `Integer`, `is_a?(Integer)` and `case x when Integer` hold, `to_s`, `inspect`, interpolation, `==` with an Integer or Float, `eql?`/`hash` (Hash keys match by value, rbEqlHash), `<=>` and Comparable, `Enumerable#sum` (a `case Bignum:` arm the pruner drops in other modes), `digits`, `bit_length`, `to_f`, `to_r`, `divmod` and the shifts answer as MRI's.

**Limits** (spinel's promote is marked experimental for the same reasons): an Integer that overflows without being a promoted local still raises, so overflow through a method's typed parameter or return, a block parameter, an ivar or a container element (`Array[Integer]`) is RangeError; untyped code (`rbNumOp`, dynamic `.class` on an untyped value) does not know Bignum; Float#to_i and friends past 64 bits still raise; a Bignum Hash key does not match the equal Integer key.

**Test lanes**, as spinel's Makefile: `RUGAROO_INT_OVERFLOW=wrap go test ./...` (or `promote`) runs the suite in that mode. `testdata/int-overflow/<mode>-skip.txt` (`raise` is the default lane) lists what pins another mode's answer: a go test name skips it, a name and a minitest method excludes the method on both the MRI and rugaroo side (`-e`). `NumberTests::IntOverflowTest` holds one test per mode.

**Measured** (2026-10-25):
- Default build: the same machine code (above); `TestCompileCost` the same 1,962 / 7,663 / 30,275 compiled functions; the benchmark rows within noise; ruby/spec `core` 8,916 and `library` 1,116 passing, as before.
- What the checks cost: `wrap` against `raise` on every `benchmarks/` workload is within run-to-run noise (BENCHMARKS.md), so `raise` stays the default at no measurable cost, and `wrap` is for code whose arithmetic is meant to wrap, not for speed.
- `promote`: spinel's `bm_bigint_fib.rb` and `bm_pidigits.rb` (also at 500 digits) print what MRI prints. `benchmarks/bignum.rb` (Fibonacci, 2000!, 1,200 digits of pi): rugaroo 0.059s, MRI 0.21s, spinel 0.12s, Crystal (GMP) 0.080s, Go (`math/big`) 0.038s.
- Lanes: `go test ./...` passes in all three modes with the skip lists as committed.
