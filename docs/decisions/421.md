# Decision 421

**Rule:** cmd/rubyspec checks a spec helper's matcher object as mspec's `should(matcher)` does, through its `matches?`, and stands in a no-op `SpecExpectation.matcher!`; a typed call with the wrong argument count stays a compile error in user and spec code, so an example that expects MRI's run-time ArgumentError for it is unsupported.

**Bundled-gem backfill, eleventh batch: classifying what is left** (2026-10-30). *See also decisions 21, 32, 141, 172, 183, 385, 416, 419, 420.*

A review of decision 420's closing list found buckets it had not classified (`library/matrix/scalar` at 0 of 9, one skip each in `lup_decomposition`, `eigenvalue_decomposition` and `vector`) and two limits that cited the wrong decision.

- **A spec helper's matcher was never checked.** rewrite.go turned `x.should be_close_to_matrix(m)` into `x.should.be_close_to_matrix(m)`, a method call whose value, matrix's spec_helper's `BeCloseToMatrixMatcher`, nothing asked. Those two examples errored only because the matcher class failed to compile; compiled, they would have passed asserting nothing. A `should <helper>` whose name SpecExpectation does not define (read from the embedded mspec.rb) is now `x.should.__matcher(helper(args))`, which asks `matches?` and fails with the matcher's `failure_message`, as mspec does. A Proc receiver (`complain`, `output`, ...) is unchanged. A helper the program does not define at all (`equal_element`, `match_yaml`, `be_positive_zero`) is now a compile-time unsupported skip instead of a run-time NoMethodError.
- **`SpecExpectation.matcher! rescue "..."`** (the first line of `BeCloseToMatrixMatcher#initialize`, for a mspec branch that has it): on mspec master, which MRI runs, the call raises NoMethodError and the modifier rescues it. Spec code compiles strictly, so the unknown method was a compile error that dropped `initialize` and with it `@expected`'s only write, hence "has no known type". mspec.rb now defines it as a no-op, the effect the rescued call has under MRI.
- **What the matcher hits now** is decision 172's user-code rule: `matches?(actual)` stores its untyped parameter in `@actual` and calls `@actual.row_size.times do ... end`, a block on an untyped receiver. Decision 420 attributed this pair to decision 183, whose rule makes an untyped ivar a warning, not an error: the attribution was wrong.
- **Wrong argument counts.** `-> { Prime.instance(1) }.should raise_error(ArgumentError)` and `-> { @v.each2(@v, @v) {} }.should raise_error(ArgumentError)` call a method whose arity rugaroo knows; it reports `Vector#each2: wrong number of arguments (given 2, expected 1)` when compiling, where MRI raises when the line runs. That is kept: a typed call is resolved when the program compiles, and a wrong count there is a bug the compiler can name, unlike decision 364's run-time answers, which have no static equivalent. A call on an untyped value checks arity at run time, as MRI's (decision 32).
- **Placeholders are not failures.** The 9 examples of `library/matrix/scalar` and one of `lup_decomposition` are ruby/spec's own `it "needs to be reviewed for spec completeness"`-style entries without a block. mspec (lib/mspec/runner/context.rb) stores such an example with a nil block and `process` skips its body (`if example`), so under MRI it raises nothing and fails nothing; cmd/rubyspec counts it as a skip.
- **Decision 420's `Matrix.rows(rows, false)`** cited decision 22; the copy is decisions 21 and 385 (an Array of one instantiation where another is expected is a converted copy, as Go's instantiations are invariant).
