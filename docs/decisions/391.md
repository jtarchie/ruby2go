# Decision 391

**Rule:** A `shift`/`pop` that is the first call a loop or branch body makes after an `empty?` check on the same local Array is its element, not `E?`, taken at the site; a one-element `push`/`<<` statement appends at the site and calls the method only for a frozen Array.

**Guarded takes and inline pushes** (#135; amends 387; 2026-10-26). *See also decisions 7, 15, 182, 384.* spinel's `bm_so_lists` ran 4,323M instructions against spinel's 282M. `li3 = Array.new` was filled only by `li3.push(li2.shift)`; an open Array is already typed from pushed `E?` values (`Array[Integer?]`, decisions 15 and 182), but the second loop's `li2.push(li3.pop)` then pushes an `Integer?` into `li2`'s `Array[Integer]`, so the typed run failed and `li3` stayed `Array[untyped]`.
- **The guard.** `while !a.empty?`, `while (not a.empty?)`, `until a.empty?`, `if !a.empty?`/`unless a.empty?` (and the else of `if a.empty?`) prove `a` not empty when the body starts. `markSureTake` (`internal/compiler/sure_take.go`) marks the body's first statement's `a.shift`/`a.pop` when it is the first call that statement evaluates (`firstCall`: receiver, then arguments in order, then the call, through local and ivar writes and `x, y = ...`; any other node gives up). Nothing runs between the check and the take, so no alias, callback or thread switch at a call can have emptied `a`. A body with `redo` (which reruns it without the check), a safe-navigation take, a second take in the same iteration, a receiver that is a call (`d(a, o).push(a.shift)`, which may clear `a` first), and a program's own `Array#shift`/`pop`/`empty?` are left alone.
- **The take.** On `Array[E]` with a concrete, non-optional `E`, a marked take is `a.rbCheckFrozen(); t := a.s[0]; a.s = a.s[1:]` at the site (pop: the last element) and its type is `E`, so `li3` is `Array[Integer]` and no `E?` is allocated. A helper function (`rbArrayShiftSure`) was tried first: its frozen check's call puts it at cost 95 (pop 104) over Go's inline budget of 80, and the call cost about 75M of the run. Hoisting the take above the statement is sound because `firstCall` proved only side-effect-free reads precede it.
- **Push.** With both loops typed, a non-inlined `Array_Push` was most of what was left: it is variadic (a one-element slice, then `append(s, xs...)` with a memmove), cost 87. `inlinePush` (`inline_idxset.go`, the Go-AST pass of decision 387's `inlineIdxSet`) rewrites a statement `Array_Push[T](a, v)` or `Array_Op_lshift[T](a, v)` to `if a, v := ...; !a.frozen.Load() { a.s = append(a.s, v) } else { Array_Push[T](a, v) }`, only when that function's body is the prelude's (frozen check, append, return: a program's own `def push` keeps its call).
- **Not done: unguarded takes still allocate.** `x = q.shift` / `while (x = q.shift)` return the prelude's `*E` (decision 7); Go would keep it on the stack where the caller only tests and reads it, but the shape function does not inline (any call in it, even the frozen check's, costs 57 of the 80). A site lowering like the guarded one, assigning `&v` of a local copy, would let escape analysis decide per site; no benchmark here shifts or pops an Array without a guard, so it waits for one. The `E?` representation (#133) is unchanged, and no pointer into Array storage is made.
- **Found on the way:** `inlineIdxSet` (decision 387) rewrites `a[i] = v` even when the program defines its own `Array#[]=`, so that method is not called for an in-bounds store (MRI calls it).
- **Measured** (instructions retired, GOMAXPROCS=1, paired, median of 5): `bm_so_lists` 4,323M to 1,407M with the guarded takes, to 684M with the inline push (spinel 282M); wall 0.20s to 0.083s (MRI 0.42s, spinel 0.029s). `benchmarks/*.rb` unchanged within noise (array 153M, collections 1,468M to 1,462M, kramdown ±1%).
- **Cost:** TestCompileCost compiled functions unchanged (05_word_count 2,032, 64_observable 7,948, 116_cuba_web 30,419).
- **Proof:** `array_test.rb` `ArraySureTakeTest` (each guard shape, a destructured pop, a frozen receiver's FrozenError, a second take that is nil, `redo`, a call that clears the Array before the take, an `Array[Integer?]`), against MRI; `TestSureTake` (the bm_so_lists shape is lowered with no dynamic call; a call first, `redo`, an own `Array#shift` are not); `TestInlinePush`.
