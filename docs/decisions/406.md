# Decision 406

**Rule:** `rugaroo build -gem dir` compiles a directory the program carries as an installed gem is (pruned to what the program reaches, leniently, its `sig/` beside a `lib/` read); the gem lookup finds a Bundler git or path gem through its loaded specs; the boot hook never resolves a constant through a pending autoload; and a resolved autoload under MRI's own library, or a dependency gem the prelude provides, is never a source or a gem dir.

**A carried library without `-trace`** (amends 131, 161, 169, 173, 175; 2026-10-27; #143). *See also decisions 296, 306, 404.* Example 135 compiled roundhouse's Blog only under `-trace`: its `runtime/` (a framework, not the program's code) had to compile as gem code, and the only way to make a directory gem code was for a traced run to find it on `$LOAD_PATH`. `-trace` executes the program and costs a second build; the ordinary `rugaroo build main.rb` path (decision 173: one `ruby` run to find gems, a boot of the load phase) then hit four bugs in turn. All are fixed, and the example builds as `rugaroo build -gem blog/runtime main.rb` in 13 s with no trace.

- **`-gem dir`** (`build`, `run`, `gen`; repeatable; `# gem: dir` in a test program): the directory joins the gem dirs ahead of what the gem lookup finds, so a `require` resolves there after `-I` and before the installed gems (decision 173's order), and its files get everything an installed gem's do: pruning (169), lenient typing (172), dropped warnings, `sig/` beside a `lib/` (306). `-I` keeps decision 131's meaning: the program's own code, compiled whole and strictly. A program's own `$LOAD_PATH.unshift` does not choose: that idiom is how a project adds its own `lib/` too, and silently compiling it leniently would take away the checking rugaroo exists for. The require scan that decides which names the gem lookup must answer sees the `-gem` dirs, so a library's `require "tep/url"` is answered there, not looked up.
- **A git or path gem.** `Gem::Specification.find_by_path` answers nil for a gem Bundler installs from git (`gem "x", github: ...`) or a path, and `find_gems.rb` then took `$LOAD_PATH.resolve_feature_path`'s answer as "standard library" and dropped it: the gem compiled to nothing and its classes were undefined. It now falls back to `Gem.loaded_specs`, where Bundler's setup lists such gems, by the require path their files answer.
- **The boot hook never autoloads.** Recording a block's captured locals (`held_by_constant`) resolved every constant of the lexical scope with `const_get`, and the dump's owner lookups did the same by name. A pending autoload resolved that way loads a file the program never did, under the hook: with `bundler/setup` in the program, Bundler's and Thor's autoloads loaded stdlib `cgi/escape` into roundhouse's `module CGI` (a TypeError that ended the boot) and the exit dump then spent the whole timeout loading Bundler. `held_by_constant` skips a constant whose `autoload?` is pending, and every name lookup in the dump goes through `const_at`, which walks `A::B::C` by `const_defined?` and refuses a pending autoload at any step. This is the bug that stopped the real-Rails `-trace` attempt (memory: `EventedFileUpdateChecker` loading `listen`), so that path may now get further.
- **Stdlib autoloads are not sources.** `bootSources` appended every resolved autoload's file as a source; `bundler/setup` resolves 35 of Bundler's (and Thor's, registered by absolute path), and the require scan then loaded the prelude's `erb` for Thor's `require "erb"`, clashing with roundhouse's `module ERB`. The manifest now carries MRI's `rubylibdir` and `archdir` (`std_dirs`), and a file under them is never a source, as decision 296 already drops them from a traced entry.
- **A dependency gem the prelude provides.** The lookup returns a gem's runtime dependencies (`base64`, `sqlite3` for roundhouse-rugaroo). Decision 173 let the prelude's lib answer their `require`, but their directories still became gem dirs, so their shipped `sig/` typed the prelude's classes (`base64`'s `urlsafe_encode64(bin, padding:)` against roundhouse's one-argument reopen) and a vendored lib's own `require "sqlite3/constants"` reached the real gem's file. A found dir whose gem name is a prelude or vendored lib is dropped, and a require whose first segment names one skips the gem dirs.
- **Boot's branch answers fold gem code only.** The top-level `if`/`unless` fold by boot's recorded arm (decision 201) applied to every file boot ran, the program's own included: a `serve.rb` whose `Tep.on_listen(...) if ENV["PORT"].nil?` ran at boot (no `PORT` then) compiled as always taken, and the binary stopped at once however it was started. `takenBranch` now asks boot only for a gem file, as decision 201's rule says; a program's own `if` is decided when it runs.
- **Proof.** Example 135's `main.rb` carries `# gem: blog/runtime` and no `# trace:`; the harness compiles it through `CompileWithGemDirs`, which `rugaroo build -gem` also calls. `TestRunGem` and examples 115/116 (gems through the lookup) and 123/124 (`-trace`) cover the lookup and boot changes.
