# Decision 290

**Brew batch 17: absolute RBS names, bangs on fresh strings, bound blocks passed to super, nil's freeze/dup,
`new` on a run-time subclass, mixed-in `initialize_dup` super, `ERB::Util.url_encode`** (#100; amends 136, 232;
2026-10-16).
- An RBS/Sorbet type written `::Pathname` resolves from the top level (`rbs.Name.Absolute`); the parser dropped
 the `::`, so inside Homebrew's `OS::Linux` it named `OS::Linux::Pathname`, the ClassMethods module.
- In gem code a bang method on a fresh String (`x.to_s` of a non-String, `dup`, `+s`) lowers like one on a local,
 without a write-back: no other reference sees the string, so only its value (nil when unchanged) matters
 (Homebrew's `basename.to_s.delete_prefix!(SONAME)`). Amends 136, which needed a local or ivar target.
- `super(..., &block)` from a method whose block binds a subclass (`T.proc.bind(Resource::Patch)`) to one that
 binds the superclass passes an adapter asserting self back down: Go func types are invariant, and the self
 the callee binds is this object.
- `freeze`, `frozen?` and `dup` on a `T?` answer nil's own (nil, true, nil) instead of NoMethodError, as
 NilClass has them (`@name.freeze` with `@name` nil).
- `klass.new(v)` where klass is a class object of unknown exact class and some subclass's `new` takes other Go
 parameter types is a type switch over those subclasses, each argument converted to its `new`'s parameter
 (through untyped where the subclass takes less); one interface assertion could not name them all
 (Homebrew's `Version::Token.create`).
- A module's `initialize_dup`/`initialize_clone` calling super with no class method above it reaches Object's
 no-op, as a static super already did (decision 232).
- `ERB::Util.url_encode` / `u`.
- Proof: testdata/boot (`DemoFreshBang`, `DemoBoundBlk`, `DemoTokNew`, `DemoDupSuper`), `object_test.rb`
 (`AbsoluteRbsNameTest`, `NilFreezeTest`), `erb_test.rb`, `internal/rbs` tests.
