# Decision 216

**A gem's or user file's method shares a dispatcher arm too; arms
come first** (#96, Homebrew; amends 85, 209). `dynShareable` admitted
only prelude and synthesized methods, so brew's `Object#blank?`,
`deep_dup`, `present?` (its `extend/` files) left a `DynBlankQ`
wrapper, `return Object_BlankQ(self)`, on each of its 1,629 classes;
so did every metaclass's `Module_ConstGet(self, ...)`, because
`ownerIface` excludes class objects. Now:
- Any method whose wrapper body is the same text for every class
 shares the class-ID arm, wherever it is defined. A class object's
 body that already calls its owner's plain func (decision 210) is
 shared with `self` asserted to the owner's interface: it is the
 same call it made per class, so the synth overrides decision 121
 protects are not bypassed.
- `_Call` (decision 79) reaches a shared member through the
 dispatcher, `rbDynX(rbFCall, self, args...)`, so minitest's
 `test_*` and predicate names no longer need a per-class wrapper.
- **The arms run before the `DynX` assertion.** Go promotes an
 embedded parent's methods, so a subclass served by an arm still
 answered `interface{ DynX }` with its parent's own wrapper, `self`
 the embedded parent: `B < A` inheriting `hi`, which calls `who`,
 got `A#who`. Arm class IDs are exact, so checking them first is
 right for every class.
- **Measured** (generated functions, `rb2go gen`): `64_observable`
 12,199 → 9,876; `116_cuba_web` 11,653 → 11,259.
- **Proof:** `dynamic_test.rb` `DynamicSharedArmTest`.
