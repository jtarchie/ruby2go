# Decision 307

**Rule:** Linked structures type statically: per-attribute writer keys, stored `&block`s typed by their calls, includer-only module methods copied per includer.

**Linked structures type statically: nil-initialized links, stored `&block`s, includer-only module calls** (amends 15, 146, 148, 183, 243, 305; 2026-10-18). The unmodified `pairing_heap` gem (example 120) compiled with 56 `rbDyn` calls in its own functions: every Node link (`@subheaps`, `@parent`, `@prev_sibling`, `@next_sibling`, set nil in `initialize` and a Node later through `attr_accessor` writers), the heap's `@root` and `@nodes = {}`, the comparator `@order = block || :<=.to_proc`, and `MergePairs#merge_pairs`, a module method shared by two heap classes with different Node classes, were untyped. Each fix is general (any linked list or tree has the shape) and applies to user code too.
- **Attr writers had one inference key.** `attr_accessor :elem, :priority, :parent` declares its writers at one position, each with a parameter named `v`, and decision 146's key is position + name: every writer of one call joined into one type (`Integer | String | Node`), which a gem then widened to untyped (244) and user code failed on (`possibly-nil LNode? where Integer is expected`). The writer's parameter is now named for the attribute (`collect_methods.go` `addModuleAttr`).
- **A round's untyped branch is not yet learned.** `@root = @root ? meld(@root, n) : n`: in a round meld's parameters are untyped, so its result is, and the join with `n`'s Node was untyped, so `@root` was, so nothing ever passed meld a Node. In an inference round (`c.round`), a branch value holding untyped drops out of an `if`/`case`/ternary's join when a typed branch remains (`lift`), as an untyped use already counts for nothing in `joinUses`. Rounds' output is discarded; the final compile joins as before, and by then meld returns a Node.
- **Discovery passes nil where a typed parameter is expected.** The same line, in ivar discovery, reads `@root` (no write typed it yet) as nil (decision 148) and passes it to meld's now-typed `a`: "nil where Node is expected" lost the statement, so the write that types `@root`, so meld's only typed use, and the rounds oscillated. In discovery, nil coerces to the zero value instead (`expr_coerce.go`); discovery's output is discarded and the emitting pass still reports a real nil.
- **A gem's lookup conversions do not veto a container ivar** (amends 15). `@nodes = {}` typed `Hash[String, Node]` from `@nodes[elem] = node`, then was dropped because the typing added conversions: `@nodes.delete(elem)` with `elem` untyped (`delete(elem)` is kept only by its name), and writer calls on the Node it returns. In gem code only conversions where something is stored veto: an argument of an element-adding Hash/Array call (`<<`, `push`, `[]=`, `store`, `concat`, ..., `storeNames`) or an ivar assignment. A demo gem's `@log << x` with x untyped still keeps `@log` untyped (else `Array[Symbol]` would reject the Integer at run time). User code keeps every conversion as a veto. A gem's lookup on a typed Hash or Array whose key is untyped or a union (Go `any`) converts it with a check (`rbConv[K]`) and takes MRI's miss when it does not convert, instead of raising TypeError: `nil` for `delete`/`dig`/`Array#index`, `false` for `key?`/`has_key?`/`include?`/`member?`, the Hash's `default` for `[]`, the default argument for `fetch(k, d)` (`lenientLookup`, `lookupMiss`). Not covered: `fetch(k)` (still TypeError where MRI raises KeyError), a lookup with a block, and a default-proc Hash's `[]` (its static default, not the proc's value). See also 314: `fetch(k)`, `fetch(k) { }` and the default-proc case.
- **A stored `&block` takes its calls' argument types** (amends 183). An unannotated def's `&block` was `{ (*untyped) -> untyped }`, so `@order[priority, node.priority]` boxed both Integers and `:<=.to_proc` sent `<=` through the dispatcher. The block's Proc type now carries a key (`blockSrcAt`: the `&block` parameter's position), and each call of that Proc (`.call`, `[]`, `.()`; also through the ivar it was stored in: `subst` keeps a TFunc's `Src`) records each argument by position and the argument count. When every call passed the same count (1 to 8, no splat), the next compile's block is `{ (T0, ..., Tn) -> untyped }` (`typeStoredBlock`, from `resolveMethod`): a caller's block literal is typed, and decision 305's `:<=.to_proc` compiles to `func(a, b Integer) any { a <= b }`. The result stays untyped (ponytail: infer it from the blocks passed). Counts that disagree keep the variadic block, since a Proc takes any.
- **Dyn wrappers pass an optional typed block as itself** (amends 243). A wrapper for a typed optional block boxed its adapter as a Proc, and passing that Proc wrapped it in a closure that is never nil, so `@hook = block` stored a non-nil func when the dynamic call gave no block (`DemoPool.new.report`: "undefined method for nil"). The adapter func is passed as the block itself, nil when none was given (`dynBlockArg`, `genClosure`); where the call is rewritten to another block shape (optparse's `on_tail` to `__on_tail_flag`'s `(bool)`), it is adapted as the Proc it was before (else brew lost `OptionParser#DynOnTail` and every `brew info` failed).
- **A module method calling what only its includers define is copied into each includer** (`copyIncluderTemplates`, after `applyPrepends`). `MergePairs#merge_pairs` calls `meld`, which each heap defines for its own Node: one shared free func had to take untyped heaps (the two Node classes do not join, 244) and call `meld` dynamically. An unannotated method of a non-prelude module, included only by struct classes and not extended, whose body calls on self a name the module, Object and the top level do not answer and every includer does, without a block, is copied into each includer that does not define it (`Owner` the includer, so its parameters infer per class), and removed from the module. Not copied: a method naming an ivar (the module's own state, decision 147), calling `super`, or passing a block to the includer-only call (concurrent-ruby's `synchronize { ... }` may compile as an iterator, which loses the value the dynamic call answered; seen in `TestBootAutoload`'s `DemoDeref#value_with`). MRI-visible difference: `instance_method(:merge_pairs).owner` would name the class (ponytail). *(See also decision 313: each generic instance is an includer of its own, and this is the one per-includer copy mechanism.)*
- **Also:** `x.nil?` in a condition generated its receiver twice when the receiver's type was neither optional nor untyped (a union from a type switch): the first, unused, value broke `go build` ("declared and not used") and ran a side-effecting receiver twice. The receiver is typed by a probe first (`genCondCall`). `include M` of a module with no type parameters no longer warns that it is untyped.
- **Measured** (example 120, decision 306's shipped sig in place): `rbDyn` in `PairingHeap*` functions 56 → 5 (`NodeVisitor.visit_node`'s `stack.pop` elements, whose `if node.subheaps; stack << node.subheaps` does not narrow a call, and `merge(other)`, which no call reaches), whole program 79 → 11, dynamic-call warnings 67 → 8, generated funcs 597 → 556. `benchmarks/pairing_heap.rb` (Dijkstra with decrease-key over a 150×150 grid, then a 100,000-element heapsort; `RUNS=9 scripts/benchmark pairing_heap`, load ~8): MRI 0.70 s, rb2go 0.49 → 0.17 s (1.4x → 4.1x). Its `x = heap.pop #: Integer` became `x && x >= prev`: `pop` now returns `Integer?`, which an annotation does not take unchecked. TestCompileCost unchanged (05_word_count 1,339, 64_observable 27,086, 116_cuba_web 28,233 compiled funcs).
- **Brew** (`overrides/brew/work/homebrew/bin/brew info wget`, macOS, traced with `info jq`, `info git`, `info --json=v2 wget` too, main 6a06774 vs this branch, behind the suite lock, load ~5-8): all four outputs equal MRI on both; compiled funcs 242,037 → 241,956 (archive 555.6 → 555.4 MB); gen 32.6 → 32.5 s, gen RSS 2.31 → 2.03 GB; traced build 122 → 113 s; main.go's go build 66.4 → 65.7 s, 11.4 → 11.0 GB RSS.
- **Left:** a `T?` of a struct class is `*TI`, so each link write boxes the interface (`Ref(left)`), an allocation the untyped `any` did not need; call-result narrowing (`if node.subheaps; ... node.subheaps`); the stored block's result type. *See also decision 345* (two later regressions of this decision, and the guard on the real gem).
- **Proof:** `TestBootAutoload`'s `DemoKeyed` (a gem `Hash[String, Integer]` and `Array[String]` probed with 1, :ab and "ab": every miss as MRI's), `TestNilLinksTyped` (rb2go_test.go: a nil-linked heap with a stored comparator and a two-includer merge module compiles with no dynamic call; it fails before this decision), `infer_test.rb` `LinkTest` (the same shapes against MRI: two includers with different node classes, a block and the `:<=` default), `TestBootAutoload` (DemoPool's optional block through a Dyn wrapper, DemoFallbackExec's untyped `@log << x`, DemoDeref's block-passing mixin), example 120.
