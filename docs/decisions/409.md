# Decision 409

**Rule:** `cmd/rubyspec` looks up the gems a spec requires through the repo Gemfile (`-gems dir`, default `.`) and compiles them as a program's installed gems, falling back to no gems when the bundle lacks one; the Gemfile pins the bundled gems the `library/` specs exercise; `net/protocol` is the only `net/*` the standard library answers, the rest are gems to look up.

**Bundled gems under ruby/spec** (2026-10-29). *See also decisions 127, 173, 328, 408.*

The `library/` suite was 40% of what ran, against 71% for `core`, and most of the gap was whole libraries answering `uninitialized constant`: the harness compiled specs in memory with no gem lookup at all, so `require "matrix"` loaded nothing, and `require "net/ftp"` was swallowed by `mriLibs`' `"net"` entry (first path segment), which marked every `net/*` as the standard library's.

- **Lock.** Upstream gems rugaroo tests against are pinned in the Gemfile and its lock (as rack, cuba, kramdown and liquid already were), not vendored: vendoring (decision 328) is for gems rugaroo authors, where the repo is the source of truth. The bundled gems the `library/` specs exercise (`matrix`, `prime`, `getoptlong`, `net-ftp`, `net-smtp`, `net-pop`, `net-imap`, `drb`, `rinda`, `pstore`, `mutex_m`, `resolv-replace`, `rss`) are listed at the versions Ruby 4.0.9 bundles. `docs/support.md`'s numbers name that one version.
- **Harness.** `CompileTestsSkippingWithGems` is `CompileTestsSkipping` with the CLI's gem lookup (`gemRequires` then `boot.FindGems` from `-gems`' Gemfile, decision 173) and the gems compiled as a program carries them (lenient, pruned to what the specs reach), with nothing booted: the sources are in memory. A gem the bundle lacks (`library/irb`, `library/rake`) fails the lookup; the program then compiles without gems, as every library spec did before, and `-v` lists the reason under `dropped gems`, so a missing gem is a skip, not a failed program.
- **`net/*`.** `mriLib(name)` matches a whole name before the first segment; `"net"` became `"net/protocol"`, so `net/ftp`, `net/smtp`, `net/pop` and `net/imap` reach the gem lookup while `net/http` stays the prelude's.
- **Proof:** `TestMRILib`; the `library/` directories below, before and after.

| directory | before | after |
|---|---|---|
| `library/getoptlong` | 27 examples, 0 pass, 24 error (`uninitialized constant GetoptLong`) | 27 examples, 5 pass, 1 fail, 2 error, 19 skipped |
| `library/net-ftp` | 460 examples, 0 pass, 384 error (`uninitialized constant Net::FTP`) | 451 examples compile against the gem; 375 error inside it (`NetFTPSpecs::DummyFTP` needs `TCPServer`), 5 files hit a codegen bug at `ftp.rb:812` (`(*result) is not used`) |
| `library/prime` | 59 examples, 0 pass, 51 error (`uninitialized constant Prime`) | the gem does not compile: `prime.rb:178: unsupported call in class << self: extend`, every file |
| `library/matrix` | 300 examples, 0 pass, 289 error (`uninitialized constant Matrix`) | the gem does not compile: `iterator blocks must yield at most 2 values`, every file |
| `library/drb` | 0 examples | 0 examples: the directory's specs are all under guards the rewrite drops |

The last three are the backfill's first items; the gaps they name are the compiler's, not the harness's. When a directory's program fails and its files are then run one at a time, three files in a row failing for one reason stop the isolation (`sameFatalLimit`): a gem that does not compile fails every file the same way, and compiling it seventy times (matrix, ten minutes) proves nothing more.
