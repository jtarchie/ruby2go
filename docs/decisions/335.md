# Decision 335

**Limits on what a program, a peer or a pattern can make the runtime allocate or wait for** (#109 phase 0; amends 27, 137, 261, 273; 2026-10-21). *See also decisions 27, 137, 261, 273.* A Go out-of-memory or a stack overflow is fatal and `rescue` cannot catch it, so each size or depth a caller controls is checked before it is used.
- **Array padding.** `a[n] = v`, `a[n, l] = v`, `a[range] = v` and `insert` with a far index pad with nils: `rbCheckPad` (prelude/go/alloc.go) raises `IndexError` "index N too big" at MRI's `ARY_MAX_SIZE` (2**60-1), and `NoMemoryError` between decision 273's 4 GiB and that, so `a[2**40] = 1` no longer exhausts memory. The untyped view's `*` raises `ArgumentError` "argument too big" (and no longer loops n times on `[]`); `combination`/`permutation`'s repeated forms raise `ArgumentError` "array size too big" for a huge k. MRI itself is OOM-killed between the two limits, so only the 2**62 cases are compared with it.
- **`flatten` of an Array holding itself** raises `ArgumentError` "tried to flatten recursive array", as MRI. Only an unbounded flatten tracks the Arrays on its current path (a per-call set, no global state); a shared, non-cyclic sub-array is fine. A non-cyclic but absurdly deep nesting can still overflow the stack (decision 128).
- **BigDecimal exponents** are saturated at 2**61: past it the value is Infinity (or 0.0 when negative), as MRI for an exponent that overflows 64 bits; a string whose exponent is out of `int` range is the same. Comparison decides by sign and then by `exponent10` before aligning, so it never builds 10**n for huge n; `rbBDPow10` itself goes through `rbCheckAlloc`, so an addition that needs 10**(2**28 or more) raises `NoMemoryError` where MRI would try for gigabytes. `Marshal.load` of a BigDecimal whose exponent is past the same bound is `rbMarshalBad` (decision 137).
- **Net::HTTP and WEBrick** (amend 27, 261). A `Net::HTTP` response body over 1 GiB (`rbAllocMax/4`) raises `NoMemoryError` "Net::HTTP response body too large". A WEBrick server answers 414 to a request line over 2083 bytes and 413 to line plus headers over 112 KiB (both webrick 1.9.2's `httprequest.rb` limits), and 413 to a body over 256 MiB, which WEBrick does not cap, without running the handler. `ReadTimeout` and `IdleTimeout` follow `config[:RequestTimeout]` (default 30 s); Go has no per-read server timeout, so a slow upload that takes longer than that in all is cut off (the connection is closed, no 408). `rbReadAllLimit` (prelude/go/net_limits.go) is the shared bounded read. `TestNetLimits` lowers the two caps in the generated source to test them; a minitest file cannot, since MRI has no such cap.
- **Compiler.** `reach.inherits` is bounded by the number of classes: it runs before `checkCycles`, so a cyclic class pair that does not contain the owner looped forever (reached through `CompileTraced` with a gem whose sig types a parameter as the cyclic class); the cycle now reaches `checkCycles`' "inherits from itself". `TracedEntry` and `mainRequires` write `require` names through `rubyQuote`, which escapes `#`, so a feature path with `#{...}` is not Ruby interpolation in `entry.rb`.
- **Files.** `File.chmod` keeps setuid, setgid and sticky; `FileUtils.cp_r` makes directories with the default mode and, with preserve (`mv` across devices), sets each directory's mode after its children, so a read-only source copies. `File.fnmatch`/`Dir.glob` keep one backtrack point per `*` and per `**/`, as MRI's `fnmatch_helper`, so `*a*a*a*b` against a long run of `a` is no longer exponential.
- **Left.** `BigDecimal("1e100000000") + 1` is under the cap but takes minutes (the mantissa is rendered as a decimal String); Net::HTTP's `read_timeout` still bounds the whole request (decision 27).
