# Decision 418

**Rule:** A gem method that begins `return x unless block_given?` (x not to_enum) gets a `__name_enum` twin whose body is x, which a call without a block takes (typed, a union's forward of an optional block, or an untyped receiver's `each`); a dynamic `method(:name)` keys by the def where the receiver's class aliases name; and an untyped `each` forward reaches a gem each whose block's value it reads, carrying that value back when the forwarded block is untyped.

**Bundled-gem backfill, eighth batch: prime's generators** (2026-10-30). *See also decisions 172, 233, 410, 411, 414, 416, 417.*

Decision 417 found prime's `#rewind` (3) and the `succ`/`next` alias failing only when `library/prime` compiles as one program; `library/prime` is now 46 of 68 (42).

- **The block-less form of a generator's `each`.** prime's `PseudoPrimeGenerator#each` begins `return self.dup unless block_given?`. Compiled as an iterator, block_given? is true and that branch is dead, so a call without a block got decision 411's Enumerator over the yields; `rewind` on it restarted the Enumerator and not the generator, whose position went on (`5`, not `2`). collect now gives such a def a `__each_enum` twin whose body is `self.dup`, the block-less overload a typed call already looks up (`blocklessOverload`, decision 219). A union receiver's `generator.each(&block)` as its method's value splits on the block: nil takes each member's block-less form, a block runs the loop (its value nil, decision 233). An untyped receiver's forward without a block calls the receiver's `Dyn__EachEnum` when it has one, else 411's lazy Enumerator, which a generator without the twin still needs. Not a to_enum guard: decision 414 compiles that one.
- **`p.method(:succ) == p.method(:next)` on an untyped p.** A typed Method's key is its def's position, so aliases compare equal (decision 414); a dynamic `method(:name)` keyed by name. Where some class aliases name, the key is now `rbMethodKey_<name>(recv)`, a type switch over those classes returning the def's key (compiled dispatch, no table).
- **An untyped `each` forward into a gem each that reads its block's value** (`last_value = yield i`): rbEachAny left out every each whose block was not void, so the call raised NoMethodError. It now passes a block valued nil; and when the forwarded block is untyped, `rbEachAnyV` gives the gem each the block's values and returns that each's own value (`break last_value`), not the receiver. rbEachAny also matched a seq-adapter class (decision 172's `Each_blk`) by the name `Each`, which it lacks; it uses the Go name.
- **Cost:** compiled functions unchanged (TestCompileCost 2065, 7949, 30379); the twin exists only for gem defs with the guard.

**Open gap left in `library/prime`:** `Prime.each(1) { :value }` is the generator, not nil (2). `PseudoPrimeGenerator#each` is reached only through Prime#each's forwarded `&block`, so its block types as void and the method compiles as a Go iterator, which has no value to carry `break last_value`. Fix shape: a gem def whose yield's value is read, or whose `break` carries a value, takes its block as a closure; it changes which gem methods are iterators, so it is measured on its own. Design limit: mspec's `should_receive` (2, decision 416).

**Proof:** `testdata/run/gem_lenient/primeish.rb`'s PrimeishGen, PrimeishOddGen, PrimeishLast, PrimeishFront and PrimeishBound, checked against MRI by `testdata/run/gem_lenient.rb`; `library/prime`.
