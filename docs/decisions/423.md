# Decision 423

**Rule:** In user code, a send whose name is wholly computed, on receivers of known classes, types each parameter with a default of the methods it may reach by its arguments, as a call does; parameters without a default keep their types, and gem code is unchanged.

**Bundled-gem backfill, thirteenth batch: net-ftp's fixture server** (2026-10-30). *See also decisions 4, 32, 141, 146, 241, 316, 353, 421, 422.*

Decision 422 listed net-ftp's two `no implicit conversion of String into Symbol` errors as a limit. A review asked for evidence that they were one; there was none, and the cause was an inference gap.

- **The cause.** net-ftp's spec fixture server dispatches each FTP command with `self.send(command.downcase.to_sym, argument)` (`argument` a String) to handlers such as `def help(param = :default)`. Decision 353 lets a computed send's arguments type the parameters it may reach only when the name has a literal prefix or suffix (`send("convert_#{x}", el)`); a wholly computed name added nothing, so `param` kept its default's type, Symbol, and the String raised TypeError where MRI passes it on.
- **The fix.** A wholly computed name on known classes (decision 316) may reach any of their methods taking that many arguments; its argument types now become uses (decision 146) of those methods' parameters that have a default. A default literal is the weakest evidence of a parameter's type, and the send is the only call that passes one. Parameters without a default are left alone, so an unrelated `def add(n)` the send never reaches is not widened by it. User code only: applied to gem code it widened kramdown's converter, a class with many defaulted methods and computed sends, and example 123 and the kramdown corpus raised TypeError (caught by the full suite); gem code's dynamic calls already type what they reach (decision 331). This adds evidence to inference; no check is relaxed (the user's rule on loosening user code, decision 422, is not engaged).
- **`library/net-ftp` 332 → 334 of 460** (`status` and `help` with a parameter); the one error left is `closed?`'s `should_receive` (decision 416's mocks).

- A block on an untyped receiver in user code: decision 32's Rule ("blocks cannot cross them"), with decision 172's user-code strictness.
