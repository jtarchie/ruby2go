# Decision 348

**Rule:** An expected `untyped` sets no return hint; each_slice/each_cons/zip carve windows from slabs; yield inlining is declined.

**An untyped slot binds no type parameter; each_slice, each_cons and zip allocate from slabs; yield inlining measured and declined** (amends 4; 2026-10-23). *See also decisions 4, 342, 384.* Crystal (whole-program inference like rugaroo's, LLVM) runs `benchmarks/blocks.rb` in a quarter of rugaroo's instructions; Crystal inlines every `yield` method, so inlining was the first suspect. A Linux profile said otherwise:
- **`puts xs.sum { ... }` summed through `any`.** `genCallValue` set the call's expected type as `retHint`, and `bindTypeParams` unified the method's return type with it before the block was probed. An argument slot typed `untyped` (`puts`, `p`, string interpolation, a gem's untyped parameter) bound `sum`'s `N` to `untyped`, so every element went through `rbSummer`'s boxed path (`convT64`, `rbNumOp`): `strings.rb`'s `puts words.sum { |w| w.length }` and three lines of `blocks.rb`. An expected `untyped` now sets no hint, so the block decides the type and the result converts at the slot.
- **Windows and pairs from slabs.** `rbSlices` (each_slice) and `rbCons` (each_cons) allocated one header and one backing array per window (and each_slice grew each slice from empty); `zip` allocated one `U?` per pair and grew its result from empty. They now carve windows from shared backing arrays, `max(1, 4096/n)` windows per allocation, each window capped at n (`slab[:n:n]`), so an append to one reallocates instead of writing into its neighbour; headers come from a slab too. Each window is still its own Array, a copy as MRI's: keeping, mutating or growing one leaves the others and the receiver alone. Above 4,096 elements each_slice grows as before (no `n` allocated up front for `each_slice(10**9)`). `zip` points each pair's `U?` into a slab of the other array's values and sizes its result by the other array's length.
- **Yield inlining, measured and not done.** After those two, the cost per element of rugaroo's block protocol (a generic `Each()` iterator called through the type parameter's dictionary, and the block as a closure) is ~1.3 ns over a plain loop (a Go micro-benchmark: 0.98 ms vs 0.58 ms for 300,000 elements); `blocks.rb` makes ~3M block calls, so inlining every yield would save ~4 ms of ~116 ms. Not worth a source-level inliner (body substitution, label rewriting for `break`/`next`/`return`, compile-size growth); decision 4's error for a non-local `return` from a closure block stands.
- **Measured** (instructions retired): blocks 1,433M to 815M (Crystal 329M, hand Go 100M), strings 477M to 413M. **Proof:** `enumerator_test.rb` `EnumSlabTest` (kept, mutated and grown windows, `each_slice(10**9)`, a `zip` padded with nil, against MRI), and the existing minitest suites for the hint.
