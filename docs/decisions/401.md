# Decision 401

**Rule:** stdout flushes per write and `IO#tty?` answers true only for a character device that is not `/dev/null`; a call on a class constant of its own singleton method is its free func; a prelude Float/Integer operator whose body is one Go operator is written as that operator at the call site unless both operands are Go constants or are the same code under a comparison or `-`.

**Float loops against spinel** (amends 398; 2026-10-27). *See also decisions 35, 86, 372, 390, 393, 398, 400.* Three spinel benchmarks trailed spinel about 3x in wall time: `bm_so_mandelbrot` (0.12s, spinel 0.034s), `bm_partial_sums` (0.074s, 0.025s), `bm_point_in_polygon` (0.17s, 0.060s). Measured as instructions retired (macOS arm64, `/usr/bin/time -l`, `GOGC=off GOMAXPROCS=1`, median of 5, old and new binaries alternating; with the default GOGC one binary's count swings up to ±10% between runs, so GC noise hides 1% effects), and read in the generated Go, spinel's C and `go tool objdump`:

- **`> /dev/null` flushed every write.** `stdoutTTY` was `os.ModeCharDevice`, and `/dev/null` is a character device, so `print byte_acc.chr` (45,000 calls in mandelbrot) was 45,000 `write(2)`s: 72% of mandelbrot's instructions, and of every benchmark that prints in a loop, since `scripts/benchmark` sends output to `/dev/null`. MRI asks `isatty(3)`, false there. `rbIsTTY` (stdout's flush rule and `IO#tty?`) now also rules out a file `os.SameFile` as `os.DevNull`. A real isatty needs per-OS ioctl constants that one `main.go` cannot carry, so other character devices (`/dev/zero`, a serial port) still count (`ponytail`). Proof: `stdlib_test.rb`'s `IO.new(File::NULL's fd).tty?` is false, as in MRI (tests see a pipe on stdout, so the flush itself has no MRI-visible test).
- **`Math.sqrt` went through `Math_MetaI`.** `goCalled` (dispatch.go) scans the prelude's Go text for `.Name(` selectors and finds `Sqrt`/`Exp` in `big.Int.Sqrt`/`big.Int.Exp`, so those two kept a Go method, and `methodExprType` wrote the call as an interface method expression Go cannot inline. A receiver that is exactly a class constant (`expr.classObj`) can only reach its own singleton method, so `exactMetaCall` sends such a call to the free func, as decision 398's leaf rule does for user modules. With `rbMathDomain`'s raise moved out of line (`rbMathDomainRaise`), `Math.sqrt`'s domain check inlines too. bm_partial_sums −15%.
- **Inlined operator calls leave NOPs.** Go inlines `Float.Op_mul(a, b)`, but each inlined call leaves an inline mark, emitted as a `NOP` when no instruction can carry it: mandelbrot's inner loop was 25 instructions, 8 of them NOPs, and is 17 now. `inlineOperator` writes the call as the method's own body when the prelude body is one of `self + other`, `self - other`, `self / other`, `Float(float64(self * other))` (the conversion keeps Go from fusing `a*b+c` into one FMA rounding) or `Boolean(self OP other)` for a comparison, and the receiver and parameter are the owner's own class. The body text is matched, not a table of names, so a changed prelude body falls back to the call. A bare `a + b` is parenthesized, since callers may append `.M()` to an expression's code. Arithmetic stays a call when both operands are Go constants (only literals and conversions; Ruby constants such as `Float::MAX` are Go vars): Go folds constant expressions exactly, so `0.1 + 0.2` would print `0.3`. bm_so_mandelbrot −22% more.
- **A returning overflow call costs spills.** Integer#+'s slow path called `rbIntOverflow`, which always panics, but Go cannot see that past a `go:noinline` call, so the path rejoins the loop and Go keeps the loop's values in stack slots around it. Decision 400 (landed in parallel) ends that path in a `panic` at the call site; this branch had the same change, measured here at −17% on bm_point_in_polygon under `--nil-check=runtime` (518M to 429M with this decision's other changes in). Integer#* kept `rbIntMul`, whose slow path returns a product, until #141 made it panic too (decision 400's `Integer#*` bullet).

Not changed, and why the rows still trail:

- **bm_partial_sums**: `math.Sin`/`math.Cos` are pure Go on arm64 (385M of 798M instructions; spinel calls libm) and `Float#**` is decision 390's correctly rounded pow (325M). Calling libm needs cgo.
- **bm_point_in_polygon** builds in the default nil mode: typing `@box`/`@pts` as `Array[Float]` makes `x >= @box[b]` a decision 20 error, so decision 15's dry run keeps them `Array[untyped]` (1.50 billion instructions; 0.43 billion with `--nil-check=runtime`, where the BENCHMARKS.md row lacks the † its siblings have). The rule change and the rest of the overflow cost are #141.
- **bm_so_mandelbrot**: the inner loop is now as tight as spinel's; the rest is Go's start-up (18M instructions), `print` through `...any` (20M), and Integer#<< out of line.

Wall time (`scripts/benchmark`, median of 5): mandelbrot 0.045s (spinel 0.036s), partial_sums 0.065s (0.029s), point_in_polygon 0.20s, or 0.072s with `--nil-check=runtime` (0.054s). The 18 `benchmarks/*.rb` move between −2.2% (objects) and +0.4% (exceptions). The overflow change costs mandelbrot +3.5%: its inner loop does not change, but Go's register allocator places one extra move at the back edge.
