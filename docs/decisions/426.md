# Decision 426

**Rule:** `--cgo` (or `RUGAROO_CGO=1`) on `build`, `run`, `gen` and `test` swaps Fiddle's purego backend for a cgo one: `prelude/go/fiddle_cgo.go` and its C in `fiddle_cgo.h` replace `fiddle_purego.go`, so purego is not linked; the default stays purego (decision 326).

Amends decisions 326 and 329, which stay the default. Asked for 2026-10-30: a cgo build of the Fiddle/FFI work, with purego not in the binary.

**Why cgo at all.** Per call it buys nothing on its own: both backends end in `runtime.cgocall` (arm64 Linux, measured: cgo `C.f()` ~33 ns, a C superset trampoline ~35 ns, purego's trampoline ~38 ns). What differs is around the call. purego off darwin reads errno with `runtime.LockOSThread` and a second C call to `__errno_location` (~78 ns a call in all); C reads it in the same frame (~33 ns). A cgo `//export` callback is ~85 ns, against ~300 ns for decision 329's path. And C itself makes the calls purego cannot: float/double-returning callbacks, variadic calls and stack arguments (below).

**Selecting the backend.** A flag only, with no per-file comment: the choice is a property of the build machine (it needs a C compiler), not of the program, whose behaviour is the same either way. prelude/go files carry `//go:build` lines; `loadPreludeGo` evaluates each with `go/build/constraint` against `rugaroo_prelude` and, under `--cgo`, `rugaroo_cgo`. `fiddle_purego.go` is `!rugaroo_cgo`, `fiddle_cgo.go` is `rugaroo_cgo`, and `fiddle.go` (memory, values, conversions) is shared. Every file's imports still join `stdImports`, which is merged once per process, so either lane can run first. This is a compile-time choice, not a Go build tag on the output: the output stays one `main.go` (a build tag can only pick between files that already exist), and the pruner sees one backend. `go.mod` still requires purego, as it requires regexp2 for a program without a regexp. Go only links what is imported, so `go version -m prog` lists no purego.

**`import "C"` in one file.** The comment above `fiddle_cgo.go`'s `import "C"` is its preamble; an `#include "x.h"` line in it is replaced by `prelude/go/x.h` (embedded with the `.go` files). The C lives in a header so it is real C to edit, and so a one-line Go comment includes it. `format.go` writes `import "C"` under the preamble, as line comments, only when a `C.` selector survives pruning. So a `--cgo` program that never reaches Fiddle builds without cgo. A `// rugaroo:if Name` ... `// rugaroo:end` section of the preamble is kept only when the pruned file still declares `Name`. The 4,000 callback trampolines (2,000 per result kind, from nested `#define`s) compile only for a program that keeps `rbFiddleCgoCallback`.

**The backend.** `dlopen`/`dlsym`/`dlclose`/`dlerror` from `<dlfcn.h>` (`-ldl` on Linux; `RTLD_DEFAULT` through a C function, since it is a pointer macro). The Linux `libm.so.6` load for `dlopen(nil)` is kept. `rb_fiddle_call` is decision 326's superset signature, `(8 × uintptr_t, 8 × double)` returning `uintptr_t` or `double`, with errno read before it returns. The argument block (`rb_fiddle_args`, no Go pointers) is still cached per C function: an address handed to C escapes, so a stack block would allocate on every call. A Closure gets the next trampoline of its result kind, which calls the `//export`ed `rbFiddleCgoCallback` or `rbFiddleCgoCallbackF` with its index and its saved registers. As with purego, there are at most 2,000 per kind and they are never freed. `rbFiddleCallback` names both exported functions, since only C calls them and the pruner would drop them.

**Varargs and stack arguments.** Under `--cgo` a Fiddle function may end in `TYPE_VARIADIC`. `Function#call` then takes type and value pairs, as MRI's does: a type is a `TYPE_*` Integer or its name as a Symbol or String (`rb_fiddle_type_ensure`'s table, `Fiddle::TYPE_NAMES`). An odd pair count, or `TYPE_VARIADIC` anywhere but last, raises MRI's `ArgumentError`. A variadic `float`, `bool`, `char` or `short` raises `RuntimeError: error creating CIF 3`, as MRI's libffi does: `ffi_prep_cif_var` refuses the types C would promote. A function may also take more than 8 integer or 8 floating arguments. `Fiddle::Importer#extern` of `"... (const char *, ...)"` and FFI's `attach_function` with `:varargs` last compile under `--cgo` to a method taking `*rest`. FFI's pairs go through `FFI.__varargs`, which turns each type to its Fiddle code and each pointer to its address. An `attach_function` past 8 arguments calls `Function#call` directly. Without `--cgo`, these stay the compile errors of decisions 326 and 375, worded to name the flag.

Such a call skips the register fast path. `rbFiddlePlace` does libffi's job for the three ABIs both Go and MRI's Fiddle run on. Integer arguments fill the integer registers (6 on x86-64, 8 on arm64) and floating ones the 8 vector registers; the rest go on the stack, a word each, in order. Apple arm64 is the exception: it packs named stack arguments at their own size and alignment, and puts every variadic argument on the stack, a word each. `rb_fiddle_call_spread` passes the registers plus 16 stack words, so stack arguments may take 128 bytes. On x86-64 it calls through a variadic prototype, so `%al` holds the vector-register count a variadic callee reads (a fixed callee ignores it). Checked against MRI (`testdata/cgo/fiddle_test.rb`: snprintf with 10 int or 10 double varargs, sqlite3's 9-argument `sqlite3_table_column_metadata`) on darwin/arm64. The same binary passes on Linux arm64 and, cross-built with `zig cc`, on Linux x86-64 (emulated). darwin/x86-64 is unchecked.

**Testing.** `RUGAROO_CGO=1 go test ...` is the lane. In it, `TestMinitest` also runs `testdata/cgo/*_test.rb` (as `cgo_<area>`), and `testdata/cgo/cgo-skip.txt` leaves out the error cases that pin purego's limits (decision 372's skip-file format). `TestPreludeGo` vets `prelude/go` under both tag sets. The default lane is unchanged.
