# Decision 426

**Rule:** `--cgo` (or `RUGAROO_CGO=1`) on `build`, `run`, `gen` and `test` swaps Fiddle's purego backend for a cgo one: `prelude/go/fiddle_cgo.go` and its C in `fiddle_cgo.h` replace `fiddle_purego.go`, so purego is not linked; the default stays purego (decision 326).

Amends decisions 326 and 329, which stay the default. Asked for 2026-10-30: a cgo build of the Fiddle/FFI work, with purego not in the binary.

**Why cgo at all.** Per call it buys nothing on its own: both backends end in `runtime.cgocall` (arm64 Linux, measured: cgo `C.f()` ~33 ns, a C superset trampoline ~35 ns, purego's trampoline ~38 ns). What differs is around the call. purego off darwin reads errno with `runtime.LockOSThread` and a second C call to `__errno_location` (~78 ns a call in all); C reads it in the same frame (~33 ns). A cgo `//export` callback is ~85 ns, against ~300 ns for decision 329's path. And C itself can make the calls purego cannot: float/double-returning callbacks now.

**Selecting the backend.** A flag only, with no per-file comment: the choice is a property of the build machine (it needs a C compiler), not of the program, whose behaviour is the same either way. prelude/go files carry `//go:build` lines; `loadPreludeGo` evaluates each with `go/build/constraint` against `rugaroo_prelude` and, under `--cgo`, `rugaroo_cgo`. `fiddle_purego.go` is `!rugaroo_cgo`, `fiddle_cgo.go` is `rugaroo_cgo`, and `fiddle.go` (memory, values, conversions) is shared. Every file's imports still join `stdImports`, which is merged once per process, so either lane can run first. This is a compile-time choice, not a Go build tag on the output: the output stays one `main.go` (a build tag can only pick between files that already exist), and the pruner sees one backend. `go.mod` still requires purego, as it requires regexp2 for a program without a regexp. Go only links what is imported, so `go version -m prog` lists no purego.

**`import "C"` in one file.** The comment above `fiddle_cgo.go`'s `import "C"` is its preamble; an `#include "x.h"` line in it is replaced by `prelude/go/x.h` (embedded with the `.go` files). The C lives in a header so it is real C to edit, and so a one-line Go comment includes it. `format.go` writes `import "C"` under the preamble, as line comments, only when a `C.` selector survives pruning. So a `--cgo` program that never reaches Fiddle builds without cgo. A `// rugaroo:if Name` ... `// rugaroo:end` section of the preamble is kept only when the pruned file still declares `Name`. The 4,000 callback trampolines (2,000 per result kind, from nested `#define`s) compile only for a program that keeps `rbFiddleCgoCallback`.

**The backend.** `dlopen`/`dlsym`/`dlclose`/`dlerror` from `<dlfcn.h>` (`-ldl` on Linux; `RTLD_DEFAULT` through a C function, since it is a pointer macro). The Linux `libm.so.6` load for `dlopen(nil)` is kept. `rb_fiddle_call` is decision 326's superset signature, `(8 × uintptr_t, 8 × double)` returning `uintptr_t` or `double`, with errno read before it returns. The argument block (`rb_fiddle_args`, no Go pointers) is still cached per C function: an address handed to C escapes, so a stack block would allocate on every call. A Closure gets the next trampoline of its result kind, which calls the `//export`ed `rbFiddleCgoCallback` or `rbFiddleCgoCallbackF` with its index and its saved registers. As with purego, there are at most 2,000 per kind and they are never freed. `rbFiddleCallback` names both exported functions, since only C calls them and the pruner would drop them.

**Testing.** `RUGAROO_CGO=1 go test ...` is the lane. `TestPreludeGo` vets `prelude/go` under both tag sets. The default lane is unchanged.
