# Decision 276

**Rule:** Compile-error locations are `srcPos` data on `compileError`; use `errorf`/`errorAt`/`warnAt`, never format `file:line` by hand.

**A compile error's location is data, not text** (#101; 2026-10-14).
- `srcPos{File, Line}` (`String()` is `name:line`) is embedded in
 `Class`, `Method`, `Const`, `Include`, `typeScope`, `gemNilIvar` and
 `verbatim`, and held by `compileError{pos, msg, untyped}`. `Error()`
 composes `pos: msg`, or just `msg` when no pos is set.
- `errorf(f, n, ...)` locates the error at n's line; `errorAt(pos,
 ...)` (and `warnAt`) at a declaration's pos, so no site formats
 `"%s:%d:"` by hand. Code that needs the bare message (`unionSwitch`
 wording an arm failure) reads `err.msg`; code that needs the full
 text (kept errors, poison reasons, warnings) calls `err.Error()`.
 Nothing strips a location back off a string, so a file name with
 `:` or whitespace is safe.
- Rendered text is unchanged (checked on 1422 inputs: examples,
 testdata/run, testdata/test and all 270 testdata/errors cases).
 Exception: the `restBlockAdapter` error (gem code only) now carries
 a `file:line:` prefix.
- Left: `ivarDecl` has only a line (its file is its class's);
 `sorbet.go`/`source.go` parse errors are plain `fmt.Errorf`.
