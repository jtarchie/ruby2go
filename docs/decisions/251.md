# Decision 251

**Brew batch: blocks passed to blockless methods, module slots through a superclass, last-resort lenient branches** (#100; 2026-10-13).
- A Dyn wrapper of a method that takes no block drops a block the
 dynamic call passed (`rbPopBlock`), as MRI ignores it.
 concurrent-ruby's `ns_initialize(opts, &block)` reaches
 `RubyThreadPoolExecutor#ns_initialize(opts)` and had raised
 ArgumentError (given 2, expected 1).
- Dynamic override slots (decision 249) are refused only for a module
 the overriding class includes itself. A module method seen through
 a superclass (concurrent-ruby's ExecutorService#post, included by
 AbstractExecutorService) is that superclass's interface slot, so
 RubyExecutorService and TimerSet answer it. A slot's typed block
 reaches the override's Dyn wrapper as an untyped rbBlockArg, each
 value asserted in. A class's own override takes the slot's untyped
 block as decision 250's module overrides do.
- A gem method that does not compile is retried, before it is
 poisoned (decision 205), with each if/else branch that does not
 compile raising NotImplementedError if reached
 (`fctx.branchLenient`). concurrent-ruby's
 `CachedThreadPool#ns_initialize` has an `if Concurrent.on_jruby?`
 body calling `java.util...`. Only as a retry, since a branch's error
 is what drives local retyping (`xs = ["a"] if flag`).
- ponytail: an unannotated gem override typed by its parent's return
 (decision 36's inherited signature) gives that type's zero value
 where its body gives nil (the `if` above, nil on MRI). Fix with a T?
 slot and an adapter.
- Brew harness: the entry folds `Concurrent.on_jruby?` and
 `on_truffleruby?` to false and `on_cruby?` to true (decision 246's
 method-body folds).
