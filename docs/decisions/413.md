# Decision 413

**Rule:** `go test` runs only on the exact MRI release `.mri-version` names; moving to another release is a commit that updates that file, the Gemfile's bundled-gem pins and the spec numbers together.

**Pinning the oracle's Ruby** (2026-10-29). *See also decisions 272, 409.*

MRI's output is the only expectation (`TestExamples`, `TestRun`, `TestMinitest`), and decision 409 pins the bundled gems ruby/spec's `library/` measures to what one Ruby release ships. A Homebrew patch upgrade (4.0.7 → 4.0.9) changed `encoding` output and broke example 135 mid-session with nothing naming the cause; the MRI cache (decision 272) keys on the Ruby description, so it only re-ran the new MRI and reported the difference as rugaroo's.

- **The check.** `toolchainErr` compares `RUBY_VERSION` with `.mri-version` exactly; a mismatch fails every test with one message, as a missing toolchain does. A patch release is a mismatch: patch releases are what moved the expectations.
- **Why not `.ruby-version` or a Gemfile `ruby` line.** Version managers read both (mise here has idiomatic files on for ruby) and would switch an activated shell to a Ruby they manage, or warn that it is not installed, in place of the one the suite was measured with. `.mri-version` is read only by the test.
- **Moving releases.** Install the new Ruby; set `.mri-version`; check the Gemfile's bundled-gem block against `gem list` of the new Ruby's bundled gems and run `bundle lock`; rerun `go -C scripts/gen-encoding-fixes run .` (decision 380); run the full suite and fix what MRI now answers differently; refresh the ruby/spec numbers (docs/support.md, README). One commit.
- **Scope.** Only the test suite. `rugaroo` itself needs no Ruby at run time, and `cmd/rubyspec` runs specs under rugaroo against the Gemfile's gems, not MRI.
