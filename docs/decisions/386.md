# Decision 386

**Rule:** `each_cons` and `each_slice` with a block run on `rbCons`/`rbSlices`, and hand the block one Array refilled per window (`__each_cons_view`, `__each_slice_view` and their `_enum` twins) when the compiler proves syntactically that the block cannot keep, mutate or hand on the window (`RUGAROO_NO_WINDOW_REUSE=1` turns it off).

**Reused windows for blocks that only read them** (amends 348; 2026-10-26; #120). *See also decisions 4, 348, 377.* MRI gives each window its own Array, because a block may keep it. Decision 348 carved those copies from slabs and 377 slid `each_cons` in place, but each window the block saw was still a fresh copy. Most blocks only read their window (`each_cons(3).count { |w| w.sum % 5 == 0 }`, `|a, b, c|`), so the copy is wasted work.
- **Block form on the slab path.** The block forms of `each_cons`/`each_slice` were Ruby (`win.shift` then `win.dup` per window; `shift` gave up capacity, so `<<` reallocated every few elements). They now run on `rbCons`/`rbSlices`, as the blockless `__*_enum` twins already did: a loop of 300,000 `each_cons(3) { |a, b, c| }` plus 75,000 `each_slice(4) { |a, b| }` went from 441M to 149M instructions.
- **The proof** (`windowSafe`, `internal/compiler/window_view.go`) is syntactic and conservative, no run-time ownership tracking. A block is safe when it has no parameters, or two or more plain required ones (`|a, b, c|`, `|(a, b), c|`: elements, which `rbSplatVal` copies out of the window instead of `rbSplatAt`'s pointer into it, so a kept `Integer?` does not see the next window), or exactly one, `|w|`, where `w` appears only as the receiver of a reader: one that neither mutates `w` nor returns it nor returns storage it shares (`sum size length count include? empty? any? all? none? join to_s inspect hash == != eql? index find_index map inject reduce sort reverse uniq min max dup`, and `first(n)`/`last(n)`). `first`, `last`, `[]` and `at` answer a pointer into the window, so they count only where that value is used at once: the receiver or operand of an operator or conversion (`w[0] + 1`, `w.first.to_i`), a condition, a dropped statement, or the block's value when the caller uses it at once. Anything else is an escape: `w` assigned, passed, interpolated, the block's value, named inside a nested block or lambda (a closure could keep it), or a call of `binding`/`eval`/`local_variables`.
- **Where.** A block call of the prelude's own `Enumerable#each_cons`/`#each_slice` with a safe block takes `__each_cons_view`/`__each_slice_view` (`iterTwin`). A chain `xs.each_cons(n).m { ... }` with `m` one of `each count sum any? all? none?` (the block's value used at once) or `map collect filter_map flat_map` (kept, so pointer readers do not count in tail position), whose block is safe, marks the inner call (`noteWindowChain`, before either call generates); that call takes `__each_cons_view_enum` when the Enumerator's `m` is the prelude's (`windowViewEnum`). An Enumerator held in a variable, or any other consumer (`select`, `find`, `to_a`, `min_by`: they keep elements), still gets copies.
- **zip not done.** Its pairs are `Tuple2` values, not Arrays, so there is no window to share; what `xs.zip(ys).sum { }` spends is materializing the pairs and their `U?` slab. Fusing a zip into its consumer is a different change (and a lazy pair would alias `ys`'s storage while the block runs); left for a follow-up.
- **Cost.** `TestCompileCost` compiled functions unchanged: 05_word_count 2,014, 64_observable 7,730, 116_cuba_web 30,289.
- **Measured** (instructions retired, GOMAXPROCS=1, median of 3): `benchmarks/blocks.rb` 576M to 442M; its `each_cons(3).count { |w| w.sum % 5 == 0 }` line alone 189M to 112M, `each_slice(4).sum { |s| s.first }` 127M to 111M.
- **Proof:** `enumerator_test.rb` `EnumWindowReuseTest` (reading blocks, destructured params kept in an Array and a Hash, blocks that keep, `dup`, mutate, capture in a lambda, or `map` their window, `break`, a nested `each_slice` on the window), and `EnumSlabTest` (kept, mutated and grown windows) against MRI.
