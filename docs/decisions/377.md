# Decision 377

**Rule:** After pruning, a module free func generic over Self that is called with a single-parameter container (`Enumerable_Sum[*Array[T], T]`) is copied with Self fixed to that container (`Enumerable_Sum_onArray[T]`), and the call goes to the copy; `RUGAROO_NO_SPECIALIZE=1` turns it off.

**Module funcs specialized per container** (2026-10-26). *See also decisions 86, 210, 342, 348.* Research against the hand-written Go ports showed that `1 + 1` already compiles to nothing (Go inlines `Integer#+` with its overflow check and folds it) and that the per-element cost in `benchmarks/` is the generic Enumerable protocol: in `func Enumerable_X[Self Enumerable_Self[Self, E], E ...](self Self)`, `self.Each()` is a call through the instantiation's dictionary (Go stencils by GC shape, so every pointer Self shares one body), its iterator closure escapes, and the loop body becomes a second escaping closure: three allocations per call and a closure call per element. A copy with the same body and `self *Array[E]` makes `Each()` a direct, inlinable call: `sum` of 3 Integers 83 ns to 11 ns, 0 allocations; of 300,000, 767 to 433 µs. Earlier guesses were measured and dropped: `any(x).(Integer)` does not allocate (an unsafe cast was no faster), and yield inlining stays declined (348).
- **Where.** `specializeSelf` (`internal/compiler/specialize.go`) runs on the Go AST in `formatGo`, after the pruner's sweep: every `IndexListExpr` naming a func whose first type parameter is `Self M_Self[Self, E, ...]` with `E` next, and whose first two type arguments are `*G[T]` and `T` for a one-parameter generic type `G` whose parameter has the same constraint as `E`, becomes `M_X_onG[T, rest...]`. The copy is the generic reprinted with its comments (so its `//line`s and frame label carry over: backtraces read `Enumerable#inject` as before), its `Self` parameter dropped and each `Self` replaced by `*G[E]`; copies are rewritten in turn, so module funcs calling each other specialize together. Forwarders (`(*Array[E]).Sum`) are rewritten too, so dynamic and interface calls reach the copy.
- **Not specialized.** A two-parameter container (`*Hash[K, V]` with `E = Tuple2[K, V]`) would need E substituted as well; a user class's Self is its interface, already one shape. A name that is already declared keeps the call generic.
- **Cost.** Go compiles a generic only where it is instantiated, so the generic left without callers is free; the copy takes the generic's place as one instantiation per element shape. `TestCompileCost` compiled functions: 05_word_count 2,011 to 2,013, 64_observable 7,723 to 7,729, 116_cuba_web 30,277 to 30,295.
- **Measured** (instructions retired, GOMAXPROCS=1, median of 3): blocks 981M to 586M, array 184M to 154M, collections 1,555M to 1,452M, objects 518M to 494M, format 3,311M to 3,182M, liquid 2,093M to 2,011M, kramdown 4,464M to 4,391M; the rest within 1%.
- **Proof:** `TestSpecializeSelf` (the rewrite, what it leaves alone, copies calling copies, the frame label); the existing minitest and run suites, whose output must still equal MRI's.
