# Decision 304

**Rule:** Element-level Array names on untyped receivers (`[]`, `push`, `fetch`, `grep`, ...) go through `rbViewCore`/`rbViewGrep`; Hash entry names do not.

**Element-level Array names on an untyped receiver go through the view too** (amends 236, 302; 2026-10-18). After 302, a generic Array's `_DynGen0` still held one case per remaining dynamic name for every element type, each calling that name's free func instantiated per type: brew info wget's ~370 Array shapes × ~47 names. Dropping every Array/Hash `_DynGen0` case (a measurement hack, not a fix) takes the build from 259k compiled funcs to 226k.
- **What:** `rbViewCore` (prelude/go/view.go) answers `length`, `size`, `empty?`, `frozen?`, `to_a`, `entries`, `deconstruct`, `itself`, `dup`, `clear`, `[]`, `slice`, `at`, `fetch`, `fetch_values`, `dig`, `last`, `[]=`, `<<`, `push`, `append`, `unshift`, `prepend`, `pop`, `shift`, `shuffle`, `shuffle!`, `sample`; `rbViewGrep` answers `grep`/`grep_v` (its own function, as `rbViewPredicate`, so `===`'s dispatcher stays only where used). Each mirrors the prelude body's arity, conversions and messages; arguments are converted to the element type before anything is written (`rbViewChecked`), as a typed call converts them.
- **Accessors:** `_trunc` became `_resize(n)`, which also grows with E's zero value (decision 7's padding for `[]=` past the end), and `_drop(n)` reslices from the front, so `shift` stays O(1). `rbFrozen` joins the interface (every Array has it).
- **Behaviour fixed on the way:** `fetch(i) { |i| ... }` and `grep(p) { |x| ... }` called dynamically ignored their block; `fetch(i, nil)` raised IndexError instead of returning nil; `slice(i)`/`slice(i, n)` took only a Range.
- **Wording:** a conversion's TypeError names "element" instead of "E" (decision 20: rb2go words it apart anyway).
- **Not changed:** names whose body is already a Go method on `Array[E]` (`==`, `eql?`, `hash`, `inspect`, `to_s`, `freeze`) keep their `_DynGen0` case, which instantiates nothing new; `pack` and `shelljoin` (lib-gated helpers) stay too. Names gem code adds to Array/Hash (Homebrew's `present?`, `blank?`, `compact_blank`, `second`..`fifth`, `deep_dup`, `deep_*_keys`) are the gem's Ruby bodies, so the view must not answer them; they are the next ~10k funcs. The Hash side's entry-level names (`[]`, `fetch`, `key?`, `delete`, `[]=`, `length`, `dig`, `dup`) were tried and reverted: a Hash `_DynGen0` case mostly calls a free func typed code instantiates anyway, while each view accessor costs a forwarder and a free func per instantiation, so brew info gained only 681 funcs (242,037 → 241,356) and 116_cuba_web, which calls all of them dynamically, lost 190 (28,233 → 28,423), even with one narrow helper per accessor. `testdata/boot`'s `hash_core` keeps them covered on the per-instantiation path.
- **Measured** (brew info wget): compiled funcs 259,271 → 242,037, package archive 1.25 GB → 936 MB; compile of main.go, interleaved pairs on the same loaded machine: 122/140 s → 81/103 s. `info wget`, `info jq`, `info git`, `info --json=v2 wget` equal MRI. TestCompileCost: 05_word_count 1,339 → 1,339, 64_observable 28,978 → 27,086, 116_cuba_web 28,641 → 28,233.
- **Proof:** `testdata/boot` (`Demo::Views.core`, `core_errors`: every name through `public_send` on Integer and `String?` arrays, writes, splices, frozen and index errors, seeded `random:`).
