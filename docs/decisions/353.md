# Decision 353

**Rule:** A computed `send` on a receiver of known classes whose name is interpolated between literal text types the parameters of each of those classes' methods the text matches, as an ordinary call would.

**A pattern-named `send` types what it can reach** (amends 146, 316, 331, 333; 2026-10-23). *See also decisions 146, 316, 331, 333.* `send("convert_#{el.type}", el, opts)` in kramdown's `Converter::Kramdown#convert` is the only caller of its forty `convert_*` methods. Decision 316 already scopes the call's dispatch to the receiver's classes, but decision 331 counts a dynamic call's arguments as uses of every gem method of the name, and a parameter only such uses reach stays untyped, because the name might be meant for another class's method. So every `convert_*` parameter was untyped, and each `el.type`, `el.children`, `opts[:indent]` in their bodies a dynamic call: the largest root in the 2026-10-23 census (memory `untyped-sources-2026-10-19`; "param: no typed caller", a third of every example's rooted dynamic calls).
- **The rule.** When the receiver's classes are known (316's `sendOnClasses`) and the name is an interpolated String or Symbol with literal text before or after the interpolation, the reachable names are those classes' and their subclasses' methods that start and end with that text. The send's positional arguments are recorded as ordinary uses of those methods' parameters (`noteSendUses`), so 146's rounds type them, in user code and gem code alike. A splat, keywords or a block argument records nothing; a candidate whose positional parameters the arguments overrun, or would fill a rest or keyword slot, is skipped. The emitted call is unchanged: `rbSendOn_C` still dispatches, and its wrapper casts the arguments once at the boundary.
- **Where the idea came from.** Spinel (matz/spinel) lowers a computed `send` to a static switch over candidate names, narrowed to the literals the name's local is assigned or its method's callers pass (`analyze_desugar.c`), so the arguments bind to each candidate's parameters. It does not narrow by an interpolation's literal text; that part is ours.
- **Not done (ponytail).** The send still goes through `rbSendOn_C` and each name's dispatcher, so dispatcher and wrapper counts do not fall. A typed Go `switch` over the matched names with direct calls would drop them for a site whose every matching name compiled and whose classes define no `method_missing`; add it when a program's dispatcher count, not its untyped count, is the target.
- **Kramdown sig (amends 333).** `sig/gems/kramdown` gains `Converter::Kramdown#convert` and `#inner`, `(Kramdown::Element el, ?Hash[Symbol, untyped] opts) -> String`: `inner` passes `children`'s elements (`Array[untyped]` by 333), so without them `el` is untyped at the send and nothing is learned.
- **Measured** (example 123, `RB2GO_GEM_WARNINGS=1 RB2GO_UNTYPED_WHY=1 rb2go gen -trace`): dynamic-call warnings 1,260 → 1,068, "param: no typed caller" 402 → 191; dispatchers 339 and wrappers 1,479 unchanged; `rbAs` sites 1,424 → 1,496 (the boundary casts into the now-typed parameters). TestCompileCost unchanged: 05_word_count 1,942, 64_observable 7,624, 116_cuba_web 29,782 compiled functions.
- **Proof:** `dynamic_test.rb` `SendPatternTest` (a prefix-matched public, private and subclass method, `NoMethodError` for an unmatched name; their eight parameters were untyped before); example 123. 333's bar for a kramdown sig: `testdata/corpus/kramdown.rb` with `to_kramdown` in place of `to_html`, traced over the gem's 216 testcases, matches MRI on the same 191 before and after (the other 25 are 24 NotImplementedErrors from decision 205's untypeable gem methods and `span/05_html/across_lines`, where an attribute keeps its newline, unchanged).
