# Decision 354

**Rule:** A pattern-named `send` on known classes is a Go `switch` on the name with a direct typed call per matching method every receiver class defines; other names fall to `rbSendOn_C`, or to `NoMethodError` when there are none and no class defines `method_missing`.

**Direct calls for a pattern-named send** (amends 316, 353; 2026-10-23). *See also decisions 316, 353.* Decision 353 typed the methods a `send("convert_#{el.type}", el, opts)` reaches, but the call still went name → `rbSendOn_C` → the name's dispatcher → the class's `Dyn` wrapper, boxing each argument into `any`, casting it back, and boxing the result. Now `genSend` (`sendSwitch` in `expr_untyped.go`) emits, at the site:

```go
t2_ := rbConstName(t1_)
var t3_ String
switch t2_ {
case "convert_p":
	t3_ = Kramdown_Converter_Kramdown_ConvertP(self, el, opts)
// ... one case per matching method
default:
	panic(rbNoMethod(t2_, self, false))
}
```

- **Arms.** The candidates are 353's: the receiver classes' and subclasses' method names that start and end with the name's literal text. A name gets an arm when every receiver class resolves it (`lookup`), so the call binds statically and a subclass override still runs through its interface method; and when the call compiles, probed with the site's arguments. Arms call as `send` does: private methods too (`implicitCall`). Their types join into the result (decision 150's `joinUnion`); an arm whose method returns `untyped` is still an arm, and the join is then `untyped`.
- **Default.** A name no arm covers (a subclass's own method behind the parent type, one whose call does not compile) goes to `rbSendOn_C`, as before, its result coerced to the join, and the site keeps its computed-send warning, which now names the pattern. When every matching name is an arm and no receiver class or subclass has a `method_missing` outside the prelude, the default is `rbNoMethod`'s `NoMethodError`, the same one `rbSendOn_C` raises, and the site notes no dispatcher at all.
- **Evaluation order.** The receiver, the name and each argument are evaluated once, in that order, before the switch (`pinArgs`), as Ruby does; a literal Array or Hash argument is built in the arm that runs.
- **Not covered:** `public_send` (it must refuse private methods: still `rbSendOn_C`), a block, a splat or keyword arguments, and a name whose literal text is not at the call (kramdown's HTML converter sends `@dispatcher[el.type]`, a Hash whose values are `"convert_#{k}"`; typing that needs the name's provenance, the half of spinel's computed-send narrowing 353 did not take).
- **Measured** (example 123, `rb2go gen -trace`): `rbSendOn_Kramdown_Converter_Kramdown` is gone, 9,618 → 9,607 functions, dispatchers 339 → 334, wrappers 1,479 → 1,474. The `rbDynConvert*` dispatchers stay, because the HTML converter's Hash-named send reaches the same names. Dynamic-call warnings 1,068 → 1,067.
- **Cost:** TestCompileCost unchanged (1,942, 7,624, 29,782 compiled functions).
- **Proof:** `dynamic_test.rb` `SendPatternTest`: public, private and subclass arms, `NoMethodError`, a `method_missing` class whose unmatched names reach it, String and Integer arms joined into `String | Integer`. Example 123 and 353's `to_kramdown` corpus run.
