# Decision 257

**Rule:** In gem code object-typed values are nil-tested at run time and `T?` passes as a nil interface; `reduce(nil) { }` binds the block's type as `T?`.

**Gem objects that hold nil their type does not say** (#100; 2026-10-14).
- In gem code, a condition on a struct-class or pointer-typed value
 tests it against nil at run time, where it was always true: an
 ivar typed by an attr_writer's sig (`sig { params(x: IO) }`) is nil
 until set, and `rbAsSlow` (decision 253) passes nil into object
 types. Homebrew's `if (inheritance = @sandbox_inheritance)` had
 merged nil under an Integer key on every spawn.
- A gem local rebound to a Hash of untyped keys from a typed-key Hash
 takes that type (`hashKeysWider`), as a param does (decision 256).
- A gem method that names its block (`def post(*args, &task)`) keeps
 it `(*untyped) -> untyped` rather than borrowing an override's
 yield shape (`overrideYieldShape`): concurrent-ruby's
 RubyExecutorService#post took ImmediateExecutor's one-value block,
 so a posted `|args, task|` saw task nil and every brew download
 failed with "undefined method 'call' for nil". A splat of an
 Array whose element type Go spells `any` (a union) passes `.s`
 directly.
- `reduce(nil) { |acc, x| ... }`: a type variable bound only by a
 nil argument takes what the block returns, made optional (`A` =
 `T?`), with the block's params re-substituted. It had stayed nil,
 so the block and a method ending in it compiled as void (user
 code too: `def f(xs) = xs.reduce(nil) { ... }` returned nothing).
- In gem code, a `T?` where object type `T` is wanted passes nil on
 as a nil interface (`rbDerefOrNil`) instead of raising: MRI's
 variable holds nil, and gem truthiness already tests `!= nil`.
 Non-object `T` still raises (`rbMust`).
- `Thread#raise` raises when called on the current thread;
 on another thread it does nothing (ponytail: an async interrupt
 needs a per-thread pending-exception check, which only
 Timeout-style code relies on).
