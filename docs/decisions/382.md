# Decision 382

**Rule:** User code may `s << x` and `s.concat(a, ...)` on a String local the compiler proves unaliased: every write of it is a fresh String, it is not a parameter, and nothing stores, passes or returns it, or calls a method that may keep it, before its last append (counted to the end of the outermost loop or block around that append); the append rebinds the local through `rbStrAppend` into a buffer only that local owns, and anything outside the proof stays a compile error that says why.

**In-place appends on an unaliased local** (amends 58; 2026-10-26; #125). *See also decisions 136, 172, 330, 332, 377, 396 (`setbyte` under a stricter form of this proof).* Decision 58 kept Strings immutable, so `s << x` was a compile error in user code, though it is the idiomatic way to build output: 6 of spinel's 74 benchmark programs failed on it alone. The reason for immutability is aliasing: if two names hold one String, MRI's mutation through one shows through the other, which a Go string value cannot do. When nothing else holds the String, `s = s + x` is indistinguishable from MRI's in-place append, and that is what gem code already does (330) without the proof.

- **The proof** (`appendWhy`, `internal/compiler/expr_strappend.go`) is a syntactic walk of the local's Ruby scope (the method or program body, or the block that owns a block local), not entering nested `def`/`class`, cached per local per body. It holds when:
  - every write of the local is fresh: a literal (unless the file says `frozen_string_literal: true`), an interpolation, `+"lit"`, `String.new`, `format`/`sprintf`, or a call that always returns a new String (`dup`, `+`, `*`, `%`, `join`, `gsub`, `upcase`, `center`, ...); `s += x` counts. A parameter, a block parameter, a multiple-assignment or rescue target, `x = y`, `+y` (which returns y itself when unfrozen) or any other call's result fails;
  - no read of it may alias it before the **seal**: the end of the outermost loop (`while`/`until`/`for`) or block enclosing the last append, or that append itself. A read is harmless as the receiver of a method that neither keeps, returns nor changes it (`size`, `bytesize`, `getbyte`, `[]`, `==`, `start_with?`, `dup`, `+`, `gsub`, ...: `readOnlyStrMethods`), as an argument of `puts`/`print`/`+`/`==`/`include?`/... (`strArgCalls`), inside an interpolation (a copy), as a condition, as a statement whose value is dropped, as the value of a block whose iterator ignores it (`each`, `times`, `each_with_index`, `loop`, ...), and as the method's value or `return` (nothing in this call appends after that). Anything else is a leak at its position: an assignment's value, an Array or Hash element, any other call's argument (`keep(s)`, `rows << s`, `yield s`), any other method on it (`s.freeze`, `s.to_s`, `s.itself`), the value of another block (`map { s }`), and the value of the append itself used other than as the next append's receiver (`t = (s << x)`);
  - no append sits inside a block that may run after its call returns: `lambda`/`proc`/`->`, `Thread.new`/`Fiber.new`/`Enumerator.new`/`define_method`/`at_exit`/`trap`, ..., or a user method that takes an explicit `&block`, which it may keep. Any read of the local there is a leak too, even `puts s`: another thread, or a later call, would read it while it grows. Ponytail: the list is by method name, so a block that runs later through a lazy chain (`arr.lazy.map { s << w }`, run at `force`) or a finalizer is not caught; a per-call-site table of which prelude methods run their block before returning is the upgrade.
  
  Loops are why the seal is the loop's end and not the last append's text: `3.times { keep(s); s << "b" }` passes s before the next iteration's append. A `begin` whose `rescue` can `retry` counts as a loop. The proof is flow-insensitive within that, so `line = +""` re-initialized at the top of a method-level `while` and stored at its bottom is rejected although it would be safe; a block-local `line` (the usual `rows.each { |r| line = +""; ...; out << line }`) is proven per block run.
- **Error.** A local outside the proof keeps decision 58's error with the reason: `undefined method << for String: Strings are immutable in rugaroo, and `s` is passed to keep on line 8 before its last append (decision 382)`; likewise "`line` is a parameter, so the caller's String would see the append", "is assigned a String that something else may hold", "`s.freeze` may keep, return or change the String", "is appended to inside a block that may run after its call returns". A receiver that is not exactly `String` (a `String?`, a union, untyped) is not proven and gets the old error; a reopened `String#<<` is called as written.
- **Code.** `s << a << b` compiles to `s = rbStrAppend(&rbBuf_s, s, a)` then the same for b, in order, so `s << "ab" << s.size.to_s` reads the size after the first append, as MRI does; `s.concat(a, b)` evaluates both arguments first, as MRI does. A `String?` argument goes through `rbMustStr` (MRI's TypeError for nil). An Integer argument (MRI appends that codepoint) is a compile error pointing at `i.chr(Encoding::UTF_8)`. `rbBuf_s` is a `[]byte` declared by `hoistLocals` at the top of the local's Go scope, so each method call, block run and thread has its own.
- **`rbStrAppend`** writes x past the end of the buffer when s is exactly the buffer (same data pointer, same length), else copies s into a new buffer of twice the needed size. The invariant is decision 332's: every String made over the buffer is at most as long as the buffer was then, and bytes are only ever written past the end, so no other String, even a Go-level one sharing the bytes (`s[0, 3]`, `"#{s}"`, `s.dup` where that does not copy), sees an append. That makes the run time memory-safe whatever the proof says; the proof is only about MRI's semantics. Unlike `rbStrCat`'s 16 shared slots, the buffer belongs to one local, so there is no threshold (rbStrCat copies below 64 bytes), no atomic swap, and no eviction by another builder: in bm_threaded_render 32 threads build four nested Strings each, and through `String#+` the slots were evicted on most appends and each miss copied the String so far.
- **Not proven (follow-up).** spinel's bm_csv_build, bm_handle_read_loop and bm_template_render mutate a String through a parameter (`add_field(line, ...)`, `grow(s)`, `render_item(buf, ...)`), an Array element (`rows.each { |r| r << "\n" }`) or an attribute (`pg.out << ...`): the caller's String must see the callee's append, which needs a String that is a reference, not a value. An ivar built only by `<<` inside its own object would need the same proof over every method of the class (no reader, never passed or returned), and would not unlock bm_template_render, whose `render_list(page.out, items)` passes the ivar's String to an appending method. Gem code still treats `s << x` as `s = s + x` without the proof (330).
- **Measured** (M-series, other jobs on the machine). bm_threaded_render, now compiling and equal to MRI: through the existing `String.Op_plus` path 2.43 s wall (8.8 s CPU), through `rbStrAppend` 1.05 s (4.0 s CPU); MRI 8.06 s. bm_str_concat: equal to MRI, start-up bound (~20M instructions, as an empty program). scripts/benchmark, median of 5 (load ~10): bm_str_concat MRI 0.062 s, rugaroo 0.006 s, spinel 0.005 s; bm_threaded_render MRI 5.67 s, rugaroo 0.69 s, spinel 0.74 s in the same run (the table's 0.58 s spinel is from a quieter one). bm_huffman gets past `<<` and stops at `freq[bv] = freq[bv] + 1` (`Array#[]` is `Integer?`), a separate typing matter.
- **Cost.** No example's generated Go changes (every example that generates without extra flags is byte-identical before and after), so TestCompileCost is unchanged; `rbStrAppend` is pruned unless used.
- **Proof:** `StringAppendTest` in `testdata/test/string_test.rb` (loop build and return, chain order, `concat` argument order, snapshots taken before an append keep their bytes, appends in an `each` block, a block-local builder in `map`, fresh reassignment, a nil argument's TypeError), against MRI with the trace oracle; `testdata/errors/strings.txtar` `shovel*` cases for each failure reason.

*See also decision 405*: a String parameter appended to is an out-parameter (`*String`, copied in and back out).
