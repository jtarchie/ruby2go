# Decision 316

**Rule:** A computed `send`/`respond_to?` on a receiver of known class, module or class object switches only over that type's names (`rbSendOn_C`).

**A computed `send`/`respond_to?` on a receiver of known class switches over that class's names only** (amends 32, 235; 2026-10-19). `rbSendByName` and `rbRespondsByName` switch over every method name in the program, and `genSend` boxed the receiver to `any` even when its static type was a struct class: one `x.send(m)` on a typed `x` kept a dispatcher for every name and a Dyn wrapper on every class (`64_observable`, 40 lines: 741 dispatchers + 2,487 wrappers, 30% of its functions, from one `send`). Now a receiver typed as a struct class `C` (or `Self` in `C`'s body, or a union of struct classes) compiles to `rbSendOn_C(recv, name, how, args...)` / `rbRespondsOn_C(recv, name, priv)` (`noteSendOn`, `emitSendOn` in `dynamic.go`): a switch over what `C` and its subclasses answer (`sendOnNames`: their method sets, filtered as `allMethodNames` is), each case the name's ordinary dispatcher, then the same `method_missing` / `respond_to_missing?` fallbacks and `NoMethodError`. Only those names are noted (`noteDyn`/`noteRespond`), so the every-name set (`dynAll`) is not raised by such a site; the dispatcher's `how` keeps `public_send` off private methods. The receiver stays `any` in the Go signature: the static type narrows the names, and a subclass held behind the parent type still reaches its own methods through the dispatcher. Not scoped (the every-name switch stays): an untyped, `T?` (nil answers only Kernel's names) or universal receiver, and a union holding one of those. *Amended the same day:* a class object (`Formula.public_send(m)`: the metaclass and its subclasses' metaclasses), a module or `Self` in a module body (the module and everything that includes it, `moduleIncluders`) and a `@go_type` class (`"abc".send(m)`, `Locale | String`) scope too; they were 20 of brew's 22 every-name sites. The warning for a site that keeps the every-name switch now says `on <type>` and, under `RB2GO_UNTYPED_WHY`, the root.
- **Why:** the user's 2026-10-19 research (memory `untyped-sources-2026-10-19`): across the 121 examples, 90% of dispatchers and 53% of `rbAs` casts come from two computed sends; brew has 145 computed sends on receivers of known class against ~10 untyped ones (decision 235). Decision 235 measured that scoping by receiver "does not help" because one untyped site flips `dynAll`, and that still holds: this is the half that makes typing those remaining sites pay off, and what a prelude param inferred from its callers (the Observable `observer` follow-up) lands on.
- **Measured:** the two example sends are on `Array[untyped]` elements and an `untyped` prelude parameter, so they are unchanged by design; TestCompileCost 05_word_count 1,339, 64_observable 27,087, 116_cuba_web 28,239 → 28,245 compiled functions (rack's typed computed sends now carry their own switch).
- **Measured on brew** (`info wget`, macOS gen, 2026-10-19): 22 every-name sites → 2 (`install_steps.rb` `context_value`/`context_config_value`: `@context` declared `Object`, `config` returned `T.nilable(Object)`), 14 → 23 scoped switches. Counts unchanged (63,572 → 64,091 functions, 3,867 → 3,991 dispatchers, 12,105 → 12,172 wrappers, 7,842 → 7,860 casts) because those two sites, and `SimpleDelegator#respond_to_missing?` (`__getobj__.respond_to?(name)` on the prelude's untyped object, reached from every `rbResponds*` fallback), still keep `rbSendByName`/`rbRespondsByName`, which decision 235 narrows but keeps whole. The payoff needs all three gone: brew patch 0024 types `context` as `T.any(Formula, Cask::Cask)` and `config` as `Cask::Config?`; decision 319 takes the delegator's `respond_to?` off the dispatcher path. With both: 63,572 → 59,859 functions, 3,867 → 2,565 dispatchers, 12,105 → 10,342 wrappers, 7,842 → 6,366 casts, no `rbSendByName` call left.
- **Proof:** `dynamic_test.rb` `SendOnTypedReceiverTest` (private via `send`, `public_send` refused, `NoMethodError` for an unknown name, a subclass's own method and `method_missing` behind the parent type, `respond_to?` with and without `true`, a union receiver); `TestErrors/dynamic` keeps the computed-send warning.
