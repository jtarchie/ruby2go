# Decision 300

**ruby/spec bugs that reach into codegen: a Hash subclass's `default`, `$~` in `grep`, Struct is Enumerable** (#102; amends 165, 171; 2026-10-17).
- A `class X < Hash` that defines `default(key)` and not `[]` gets a generated
 `def [](key) = key?(key) ? super : default(key)` (`addHashDefaultIdx`), as MRI's `rb_hash_aref` reaches an
 overridden `default` through the method table. Hash#[] itself still reads the stored default, so plain Hash
 pays nothing. The generated `[]` is `(untyped) -> untyped`: the override's answer need not be a `V`
 (ponytail: type it from `default`'s signature when that names `V`).
- `xs.grep(re) { ... }` / `grep_v` on an Array, with a Regexp pattern, in a frame that reads `$~` (decision
 171) compiles to `rbGrepLM`, which sets the frame's last match before each test's block, nil for a failed
 test, as MRI's `grep_iter_i`. Without a block, or on a non-Array receiver, `$~` is untouched (MRI's
 blockless grep does not set it).
- Each `Struct.new` class includes `Enumerable[untyped]` over its values (its generated `each`). Not the
 `Struct` base: there the generated `to_h` (`Hash[Symbol, untyped]`) would fail the override check against
 `Enumerable#to_h`, so `Struct.include?(Enumerable)` is still false. Cost: 116_cuba_web +44 functions (+0.5%,
 rack's structs join untyped `map`/`each_*` dispatchers); 05_word_count unchanged.
- Proof: `hash_test.rb` `HashDefaultOverrideTest`, `regexp_extended_test.rb` `RegexpGrepLastMatchTest`,
 `object_test.rb` `ObjectStructEnumerableTest`.
