# Decision 410

**Rule:** Gem code compiles more of what Ruby's bundled gems write: a constant's value initializes the constants it assigns, a container ivar reset to nil is optional, a nil in a multiple assignment types its target by later writes, a block parameter forwarded without a block yields nothing, `break v` out of an iterator nothing reads breaks, a void value assigned is nil, and a `method_added` hook that `def_delegator`s each instance method to `instance` makes those class methods at compile time.

**Bundled-gem backfill, first batch** (2026-10-29). *See also decisions 4, 173, 183, 233, 244, 409.*

Measured with decision 409's harness: `library/getoptlong` went from 0 to 24 of 27 passing, `library/prime` from 0 to 21 of 68 (a program before: the gem did not compile). Each item is gem code only (`lenient`); a program's own code keeps its stricter rule.

- **Lifted constants are live with their value.** `ORDERINGS = [REQUIRE_ORDER = 0, PERMUTE = 1, RETURN_IN_ORDER = 2]` (getoptlong): decision 244 lifts the inner writes out, and the pruner dropped an inner constant nothing named by itself (`RETURN_IN_ORDER`), so `ORDERINGS` read a missing constant at run time. A reached constant write (`reach.nestedWrites`) now marks the constants its value assigns.
- **A container ivar reset to nil** (`@canonical_names = nil` in getoptlong's `terminate`, after `Hash.new` in `initialize`) widens to `T?` during discovery, and `refineContainer` keeps the `?` when it types the elements. A program's own ivar still needs its `# @rbs @x: T?`.
- **`name, arg = nil, ""`**: a literal nil element with no target type is written as `name = nil` is (the target typed by its later writes), not "cannot infer a type from nil".
- **Forwarding an optional block** (`generator.each(&block)` called without one, prime's `Prime.each(20)`): the typed iterator path skips the loop when `blk` is nil, and the dynamic path (`dynEachForward`) calls `each` without a block, as MRI's `x.each(&nil)` does.
- **`break v` out of an iterator** whose value nothing reads (prime's `PseudoPrimeGenerator#each`, a Go iterator because the gem's sig makes its block void) evaluates `v` and breaks; a gem's `loop do ... break v ... end` in value position takes `v`, as a valued `while` does (decision 364). A program's own `break v` is still decision 4's error.
- **A void value assigned** (`last_value = yield x` into a void block) is nil.
- **Iterator adapters** pass a value-optional's zero, not `nil`, for a dropped nil-defaulted parameter, and an `each` whose defaults the callee runs (`rbArgc`) drops every trailing optional parameter: prime's `each(ubound = nil, generator = EratosthenesGenerator.new)` answers Enumerable's `each()`.
- **Prime's delegator hook.** `class << self; extend Forwardable; def method_added(m) = (class << self; self; end).def_delegator(:instance, m)`: the `extend` is a no-op in gem code (only the hook calls `def_delegator`), and the hook makes `def self.m(<m's parameters>) = instance.m(<each passed on>)` for each public instance method defined after it, its parameter list copied so the gem's shipped `sig/` types the class method. A copied default resolves its constants as the gem file does (`sameSource`).
- **`Array#compact!`**, which the prelude lacked (prime's sieve).
- **mspec's `argv`** in `cmd/rubyspec/mspec.rb`: ARGV holds the given words while the block runs.
- **Left for the next batch:** prime's sieve writes nil into an `Array[Integer]` local from `.to_a` (`segment[i] = nil`), which gem code cannot yet widen; getoptlong's `UnboundMethod` equality for an alias and mspec's `should.terminated?` predicate.
- **Proof:** `testdata/run/gem_lenient.rb` (lifted constants, ivar reset, nil in a multiple assignment) fails without the fixes; `ArrayTests#test_compact_bang_in_place`; the two spec directories above.
