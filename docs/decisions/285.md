# Decision 285

**concurrent-ruby's Promises internals get vendored sigs; sig ivars resolve in their class's nesting;
`Array.new(n, nil)` is an open literal** (#100; amends 160, 182; 2026-10-15).
- concurrent-ruby has no annotations, and 241 of brew's untyped receivers sat in it, mostly promises.rb: the
 state from `attr_atomic(:internal_state)` (a string `class_eval`, so nothing to infer from), the
 promise ↔ future links (`@Promise`, `@Future`), `new_blocked_by*`, and the `send`-reached callbacks.
 `sig/gems/concurrent-ruby/` now types that graph. ruby/gem_rbs_collection's concurrent-ruby sigs were
 checked and not used: they type only the public API, as generic classes (`Future[T, E]`) with bounded
 method generics rb2go's RBS grammar does not read, while the untyped sites are internal. A future's value
 stays untyped (it is whatever the task returned).
- A sig file's `@x: T` resolves `T` in the class's nesting (`module M; class F; @p: P` finds `M::P`), as its
 defs do. Before, the type resolved at top level and, in a gem, failed silently to untyped.
- `Array.new(n, nil)` (and `::X.new` for any of decision 182's forms) is an open literal, for an ivar as
 for a local, typed by what is stored over its nils: `@a = ::Array.new(n, nil); @a[i] = s` is
 `Array[S?]`. Before, an ivar stayed `Array[untyped]` and a typed `[]=` into it did not compile.
- Effect on `brew info wget`'s program: untyped receivers of dynamic calls 1,702 → 1,589 (concurrent-ruby
 241 → 128), dynamic call sites 2,339 → 2,268, two fewer methods that fail Go type-checking
 (`delay_on`, `schedule_on`).
- Proof: `TestRBSIvarNestedType` (rb2go_test.go), `array_test.rb` (`ArrayNewNilTest`).
