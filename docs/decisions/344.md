# Decision 344

**`Hash.new(default)`, `h[k] op= v`, and a memo literal are open literals** (amends 182, 192; 2026-10-23). *See also decisions 5, 182, 192, 350* (`h[k] op= v` fused). Decision 182 typed an empty `{}`/`Hash.new` local from what `h[k] = v` stores, but three common shapes still fell to decision 192's untyped K, and every hash operation in them went through `any` keys (`rbKeyIndex`, boxing): `blocks.rb`'s `each_with_object(Hash.new(0)) { |n, h| h[n % 13] += 1 }` spent 39% of its run there.
- **`Hash.new(default)`** (one positional argument, no block) is open like `Hash.new`: V is the default's type when that is concrete (decision 5), K is what is stored. `refineContainer` now refines only a container's `untyped` arguments and keeps the typed ones; it still needs at least one.
- **`h[k] op= v` and `h[k] ||= v`/`&&= v`** on an open local or ivar record k as key evidence (`noteIndexWrite`), as `h[k] = v` does; `||=` also records v. An op-write's value reads `h[k]` itself, so it says nothing about V.
- **A literal passed as a block's memo** (`each_with_object(x)`'s second block param, `inject(x)`/`reduce(x)`'s first) is open through that param: pass 1 marks the param an open local (`openMemo`) and records which argument fed it (`fctx.openArgs`, by source offset, shared across analyze's re-runs); the argument is then generated with the param's refined type (`openArgType`), so the literal, the type argument and the block agree.
- Not done: `h[k] = (h[k] || 0) + 1` on an open `{}` still gives no V evidence, as the value reads the still-untyped hash; `Hash.new(0)` or an annotation types it. `h[k] += 1` still warns "possibly-nil" (decision 5's `V?`).
Measured: `blocks` 1,700M to 1,500M instructions. **Proof:** `open_memo_test.go` (the generated type arguments, and no untyped warning), `hash_test.rb` `test_open_default_and_memo_typed_from_use`.
