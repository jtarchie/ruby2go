# Decision 314

**Rule:** A gem's mistyped-key `fetch(k)` raises MRI's `KeyError`, `fetch(k) { }` yields the key untyped, and a default-proc Hash raises `TypeError`.

**A gem's mistyped-key `fetch` misses as MRI's, and a default proc refuses it** (amends 307; 2026-10-18). Decision 307 left three lookups raising rb2go's `TypeError` where a gem's untyped key of another class reaches a typed Hash. Now (`lenientLookup`):
- `fetch(k)`: `KeyError` with MRI's message (`key not found: <inspect>`), `key` and `receiver`, via `KeyError.__for`.
- `fetch(k) { |x| ... }`: the block is compiled a second time with `x` untyped and called with the key, as MRI yields it; a hit calls the typed block.
- `h[k]` where `h` has a default proc: the proc is typed `(Hash[K, V], K)`, so it cannot be handed the key, and MRI would store a key the Hash cannot hold. It raises `TypeError` naming the key class and the file:line instead of returning the static default (nil), which hid the miss. A Hash without a proc still returns its default. Only this branch differs from MRI; the fixture cannot check it against MRI.
- **Proof:** `testdata/boot` `DemoKeyed#probe_fetches` (Integer, Symbol and String keys into `Hash[String, Integer]`). Decision 307's `on_tail` adaptation now has a check too: `DemoTailCli` (an untyped parser's `on_tail { |v| }`, rewritten to `__on_tail_flag`'s `(bool)`); with `funcBlockArg` passing the func as itself the build fails.
