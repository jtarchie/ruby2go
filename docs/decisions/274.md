# Decision 274

**Small compiler fixes** (#101; amends 169, 209, 241, 242; 2026-10-14).
- A tuple's `first`/`last` with arguments, and `<=>`/`==` with the
 wrong argument count, fall through to the Array of its fields
 (decision 241) instead of reading `.F0`/`args[0]` unchecked.
- The Data/Struct keyword paths share `kwMap` and report the first
 unknown keyword in source order (they ranged over a map).
- "condition of type X is always true" and "cannot be called
 dynamically" warnings go through the deduping `warn` path (pass 2
 only for `fctx`).
- `analyze` truncates `retTypes` to its entry length on every re-run,
 so the untyped first run's `Array[untyped]` cannot join a refined
 `Array[Integer]` ("method f returns both ..."). `fctx.try`'s own
 rewind is not done yet.
- `_DynGen` keys a private method with a NUL prefix (`dynPrivKey`), so
 a public `_foo` no longer collides with a private `foo`.
- A string-literal name in `send`/`public_send`/`method`/
 `respond_to?` reaches the method as a symbol literal does.
- Struct/Data member names must be plain identifiers: a compile
 error, not an internal error. (MRI accepts `:a?`; supporting it
 needs ivar-name mangling in `valueClassSource`.)
- `Regexp.new/compile/union` noting covers `::Regexp` and decides via
 `rxPrepare`.
