# Decision 313

**Rule:** A module method needing per-instance types is copied into each generic instance by `copyIncluderTemplates`; rounds missing an instance drop uses.

**A module method a generic instance needs typed its own way is copied per includer** (#104 phase 6; amends 307, 308; 2026-10-18). A module body is one free function generic over `Self` (decision 9), and its unannotated parameters join every includer's arguments (decision 146), so generic includers mixed their instances' types: `Twice#twice(x)` called from `Doubler[Integer]` and `Doubler[String]` became `x: String` and failed at the Integer call.
- **One mechanism: decision 307's.** `copyIncluderTemplates` (decision 307) copies a module method that calls on self what only its includers define into each includer. Instances are ordinary classes in `classList` by link, each including the module (its includes are cloned from the template's), so each instance gets its own copy, whose pending keys carry the instance's Go name and so infer apart. A separate clone-at-instantiation pass (`cloneModuleMethods`, built in parallel with 307) covered the same proofs and was dropped at the merge: 307's narrower rule (an includer-only self call) is what makes a per-includer type necessary, and it also removes the module's own copy, so no stray untyped-parameter warning is left behind.
- **Merge fix.** An inference round that named an instance it lacked (decision 308's restart) still recorded its argument types, the template standing in for the instance: a `Node` with no instance (`PairingHeap::PairingHeap::NodeI`, undeclared) then typed 307's nil-initialized `@root` and `meld`'s parameters in the final compile, which failed `go build`. Such a round's uses are now discarded (`updateInference` is skipped when `instMissing`); the round after the restart records them on the instance.

Generic instances add no dynamic call over 307's typing: pairing_heap's main program uses one element/priority shape per heap class, which 307 already typed by joining.
