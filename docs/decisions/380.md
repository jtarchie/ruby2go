# Decision 380

**Rule:** Case mapping, normalization and 50 legacy encodings come from `golang.org/x/text` (v0.41.0, Unicode 17 as MRI 4.0's), with MRI's own mapping, byte rules and messages layered on top where x/text's differ; a program links an encoding family's tables only where it names one.

**x/text for Unicode and encodings** (2026-10-26; user decision: "switch to x/text wherever we can"). *See also decisions 136, 324, 379.* Go's standard library has simple case mapping only and neither normalization nor legacy encodings, so rugaroo carried a special-casing table, 88 KB of normalization tables generated from MRI's, and hand shims for `:turkic` and `:fold`, and transcoded only ten encodings. `golang.org/x/text` is the fourth Go module generated programs may import (after regexp2, purego and go-yaml), pinned in `GoMod`/`GoSum` like them. v0.41.0 is the last release that builds with the generated module's `go 1.25`; its tables are Unicode 17.0.0, the same as MRI 4.0.7's, and as of this decision case mapping no longer depends on the Go toolchain's `unicode` tables.
- **Normalization.** `unicode_normalize`/`unicode_normalized?` are `norm.NFC`/`NFD`/`NFKC`/`NFKD`. The generated tables and `scripts/gen-unicode-normalize` are gone. Checked: all four forms of every code point that normalizes (17,101 lines with the sequences) equal MRI's.
- **Case mapping.** `upcase`, `downcase`, `capitalize`, `swapcase`, their `:turkic` and `:fold` forms and `casecmp?` go through pooled x/text casers (`rbCaseX`; a caser keeps state while it runs, so one per call), driven with `Span` (no allocation when nothing changes) and `Transform`, behind the ASCII and binary-String paths, which never reach x/text. Where x/text's mapping differs from MRI's, MRI's wins: no final-sigma rule (`"ΣΑΣ".downcase` is `σασ`), `:turkic` lowering without Turkish's context rule (MRI keeps `ı` and the dot of `"İ"`), a Georgian Mtavruli first letter lowered by `capitalize`, Cherokee folded to its capitals as CaseFolding.txt has it, and decision 379's titlecase table for `swapcase`. `swapcase` runs through each caser once per run of characters that go one way. This fixed `casecmp?`, which used Go's simple folding (`"ß".casecmp?("SS")` was false), `downcase(:fold)` (upcase then downcase before) and `swapcase(:turkic)` (one rune at a time). Checked: the ten case maps and four `casecmp?` checks of every code point to 0x10FFFF (1,112,075 lines) equal MRI's. Cost: an unchanged non-ASCII String allocates nothing; `upcase` of `"straße"` is 172 ns (the standard library's `strings.ToUpper`, which gets it wrong, 68 ns), `downcase` of Greek 137 ns (152 ns); a non-ASCII-heavy loop of all of them is 26% over main, which printed the wrong `casecmp?` count.
- **Single-byte encodings.** ISO-8859-2 to -16, TIS-620, Windows-1250 to -1257 and -874, KOI8-R, KOI8-U, IBM437, CP850, IBM852, CP852, IBM855, CP855, IBM860, IBM862, IBM863, IBM865, IBM866, macRoman and macCyrillic (ISO-8859-11 and TIS-620 on x/text's Windows-874 table, CP852 and CP855 on IBM852's and IBM855's) decode and encode through x/text's `charmap` tables in the existing per-character transcoder (`rbXDecode1`/`rbXEncode1` under `rbDecode1`/`rbEncode1`), so MRI's errors, options and conversion paths carry over. `scripts/gen-encoding-fixes` (its own module, as `scripts/census`) asks MRI for every byte and every BMP character of each and writes `prelude/go/encoding_xtext_fixes.go`: MRI's mapping where x/text's differs (ISO-8859's C1 controls, which MRI maps to themselves; KOI8-U's two box characters; macRoman's Ohm sign, currency sign and Apple logo; Windows-1255's presentation forms, which MRI writes as letter and point), and the converter names MRI's errors give (`WINDOWS-1252`, `MACROMAN`: `U+0100 to WINDOWS-1252 in conversion from UTF-8 to WINDOWS-1252`). It also writes `prelude/encoding.rb`'s constants (`Encoding::Windows_1252`, `CP1252`, ...), `Encoding.list` and `Encoding.name_list` in MRI's order, the alias table, and `internal/compiler/encoding_names.go`, so a literal naming one of them compiles. Windows-1258 is left out: MRI has no converter for it. Checked: decode of all 256 bytes and encode of every BMP character, messages included, equal MRI's for all 39. `Integer#chr` takes them; `File.read(path, encoding: "ext:int")` now transcodes (it ignored `encoding:` before, ISO-8859-1 included).
- **Multibyte encodings.** Shift_JIS, Windows-31J (SJIS, CP932), EUC-JP, CP51932, EUC-KR, CP949, GBK (CP936), GB2312, GB18030, Big5 and CP950 decode through `rbMBEnc` (`prelude/go/encoding_xtext.go`), MRI's transcoder walk in miniature: bytes that stand alone, bytes that lead, the trail bytes a lead takes, EUC-JP's 0x8F and two more, GB18030's four-byte form; a byte that cannot continue makes the bytes before it invalid and is read again (`"\x81" followed by " " on Shift_JIS`), input ending inside a character is incomplete, a whole character with no mapping undefined. The generator derives those byte sets from MRI's answers and checks the model against every input it asked about (33,024 per encoding, 98,560 for EUC-JP, 1,624,404 for GB18030) before it writes anything. A character is x/text's (a pooled decoder per encoding), or MRI's correction: x/text follows the WHATWG tables, MRI the vendors' (`"\x81\x60"` in Shift_JIS is WAVE DASH, U+301C; Windows-31J's user-defined area is U+E000 onward; Big5's HKSCS rows are undefined in MRI). Encoding takes x/text's bytes only where they decode back to the same character in this encoding's structure and table, which removes the characters only x/text's superset tables have (CP949's for EUC-KR, GBK's for GB2312, JIS X 0212 for CP51932); what is left are corrections. All are runs (`SEQ=CP*N` in structural order), expanded on first use: 34 KB of source for the eleven; Windows-31J's 1,880 decode corrections are one run. Checked: every 1- and 2-byte input and every BMP character, messages included (96,512 lines per encoding), EUC-JP's 65,536 three-byte inputs, and 200,000 GB18030 four-byte inputs and every seventh supplementary character, through the compiled runtime: equal MRI's.
- **Linking.** Importing an x/text encoding package runs an init that builds all of its tables, so the families (single-byte, Japanese, Korean, simplified and traditional Chinese) are linked by `rbUseEnc<Family>()` calls the compiler emits where a program names one of their encodings: a literal, an `Encoding::Shift_JIS` constant, a `File.open` mode or an `encoding:` keyword; a name it cannot see (a variable, a run-time mode string) links `rbUseEncAll()`. Kept code reaches single-byte tables through an interface, not charmap's type, for the same reason. Binary sizes (bytes): a program without `encode` is unchanged (2,717,186); one encoding to UTF-16 only 2,804,034 to 2,874,530; to Windows-1252 2,999,842; to Shift_JIS 2,995,090.
- **Not supported.** 34 encodings MRI converts, listed with their reasons in `docs/support.md#encodings`: the ISO-2022-JP family (state across characters), Big5-HKSCS (some characters decode to two code points), the carrier emoji encodings, UTF8-MAC and CESU-8, and the code pages x/text has no table for (IBM720, IBM737, macGreek, eucJP-ms, GB12345, ...). A literal naming one is a compile error; a run-time name raises `Encoding::ConverterNotFoundError`.
- **Not changed.** Strings still carry no encoding tag (136): `force_encoding("Windows-1252").encode("UTF-8")` keeps the bytes; `encode("UTF-8", "Windows-1252")` converts.
- **Proof:** `SingleByteEncodingTest`, `MultiByteEncodingTest` and `XTextUnicodeTest` in `testdata/test/encoding_test.rb`; `testdata/errors/encoding.txtar` for the unsupported ones; the exhaustive checks above, run against MRI 4.0.7.
