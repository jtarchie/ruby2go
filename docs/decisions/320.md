# Decision 320

**A delegation through a nilable accessor is typed** (amends 99, 118; 2026-10-19). `def_delegators :@dsl, ...` with `@dsl` typed `DSL?` (Homebrew's `Cask::Cask`: `@dsl = T.let(DSL.new(self), T.nilable(DSL))`, 29 delegated names from `DSL_METHODS` that boot read, decision 204) was "cannot delegate to @dsl of type DSL?" in user code and, in gem code, an untyped forwarder: every `cask.version`, `url`, `depends_on`, `staged_path` call and everything built on their results dispatched at run time (130 of brew's 2,113 dynamic-call roots). The forwarder now reads the accessor into `target`, raises `NoMethodError` ("undefined method 'x' for nil") when it is nil, as MRI's forwarder does calling the method on nil, and makes the typed call (`delegation.nilable`, `nilGuard`); the same for the keyword `(...)` form.
- The accessor's annotation may sit in any method, not only `initialize` (`delegateTarget`: Cask's `@dsl` is set in `refresh`); the first annotated write wins.
- Typing those delegators exposed `SoftwareSpec#owner=`: `@name = owner.name` with `owner: Formula | Cask::Cask` is `Array[String] | String` into `@name: String?`, which was a decision 205 stub and crashed `info wget` (MRI stores whatever comes; a Cask's `name` is its names Array). In gem code a union value that does not fit the ivar now converts where it lands, as an untyped one does (decision 225): the fitting member is stored, another raises `TypeError` at run time, where the untyped path raised the same. User code keeps the compile error.
- **Measured:** brew `info wget`: dynamic-call warnings 2,128 → 2,002, stubs 141 → 140, functions 59,859 → 59,851; output equals MRI. The 40 DSL roots left are delegated names whose `DSL` method has no return type.
- **Proof:** `object_test.rb` `ForwardableTest#test_nilable_accessor`; `testdata/boot` `DemoOwnerSpec` (Sorbet `T.let` nilable accessor set outside `initialize`, `NoMethodError` on nil, the union owner's `name` into `@name`).
