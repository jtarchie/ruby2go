# Decision 311

**A helper class nested in a generic class takes its parameters** (#104 phase 4; amends 308, 146; 2026-10-18). A linked-list or heap node (`Chain::Link`, pairing_heap's `PairingHeap::Node`) is usually an unannotated class whose ivars hold the outer class's `T`: one shared class would join every instance's uses (`Integer | String`, decision 146) or go untyped.
- **Which classes.** A plain struct class declared directly in a template's body (its constant is `Outer::Name`), with no superclass, no type parameters, no `def self.`, no sig and no method with a `#:` signature (`markHelpers`), becomes a template over the outer template's parameter names (`helperOf`). Inference decides its types per instance, so the parameters need not appear in any signature; an annotated helper is the author's, and keeps its declared types.
- **Where it is named.** `Link` (a constant in `Link.new`, or a type in an annotation such as `# @rbs @head: Link?`) inside the code of an instance of the outer template, or of the helper itself, along the class's superclasses (`helperArgs`, so a subclass instance's inherited bodies find it too), is the helper's instance at that instance's arguments: `Chain[Integer]`'s `push` builds `Chain::Link[Integer]`. In the template's own (never compiled) code it is the helper at its type variables.
- **Inference per instance.** A pending parameter's key already carries its owner's Go name (decision 253), so `Link[Integer]#initialize(val, rest)` and `Link[String]#initialize` infer apart. Two fixes on the way: an inferred type naming an instance carries over to the next compile by instance key (`rehome`, which went by Ruby name and found the template), and a template's own pending parameters, which no call reaches, are untyped without decision 183's warning.
- **Also fixed:** a class body's `# @rbs @x: T` scan (`collectIvarDecls`) took the annotations of every nested class too (an annotation before a nested `def` is keyed to that line), so a module around `Chain` failed to resolve `Chain`'s `@head: Link?`. A nested class's lines but its first are now left to it; Date's `@jd` keys to its nested `class Error` line and stays Date's.
- **Not done:** a helper reached from outside the outer class's code (`Chain::Link.new(1)` in main) cannot bind its parameters and is decision 308's "cannot infer" error; only direct nesting counts (a helper's own helpers stay plain).
- **Proof:** `generic_class_test.rb` `test_nested_helper_takes_outer_params` (`Chain[Integer]` and `Chain[String]` over an unannotated `Link` with `attr_accessor`s, inferred `initialize`, and an ivar annotated with the helper's bare name).
