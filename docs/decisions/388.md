# Decision 388

**Rule:** A Hash past 8 entries indexes its entry array with open-addressed `slots []int32` (linear probing, entry index + 1, -1 for a deleted entry's slot), not a Go map.

**Hash's key index is open-addressed slots** (amends 350, 342; #124; 2026-10-26). *See also decisions 350* (the entry array, tombstones, the map-free small Hash), *342*. Decision 350's `pos map[K]int32` meant a lookup on a large Hash went through Go's map and then the entry array: two structures, two cache misses, and the map's own groups and control bytes. Crystal and MRI 3.x use the shape adopted here.
- **Layout.** `slots []int32`, a power of two at least twice the entry count, so at most half full. A slot holds an entry's index + 1; 0 is empty and ends a probe; -1 is a deleted entry's slot, which a probe walks past and an insertion of a key already known to be absent reuses. Ordering, tombstones in `ents`, `live`/`head`, iteration and the no-compaction-while-iterating rule are decision 350's, unchanged. Up to 8 entries there are still no slots (the scan); the 9th entry builds them.
- **Lookups** (`rbHashFind`) hash the canonical key (by-value keys go through `idx.find` first, as before), probe from `hash & mask`, and compare with Go `==` only against live slots. `[]=` keeps the hash from its miss probe, appends the entry and records it in one more probe (`rbHashIndex`); past half full it rebuilds (`rbHashRehash`, live entries only, the storage reused when big enough). `delete` turns its slot into -1 (`rbHashDropAt`); compaction rebuilds the slots from the renumbered entries, which also clears the -1s; `clear` zeroes them; `dup`'s straight copy clones them.
- **Hashing** (`rbHashOf`) agrees with Go `==`: an Integer is mixed inline (`bits.Mul64` of the value xor a per-process seed by the golden-ratio constant, high and low halves folded, so every bit of the key reaches the low bits a probe starts from; `k * 7`, multiples of 1024 and `x << 32 | y` all spread); `rbHashOfAny` handles String and Symbol (`maphash.String`), Float (bits, -0.0 as 0.0, which `==` treats as one key) and Boolean, and every other key with `maphash.Comparable`. Both seeds are per process, as Go's map seed and MRI's hash seed are. A NaN key still never matches (decision 350).
- **Kept escape behaviour.** `maphash.Comparable` makes a key holding non-string pointers escape (a Go map lookup does not), so for `Hash[untyped, ...]` and object keys a lookup key's pointee leaks to the heap. Measured below on an untyped Hash: no new allocation shows, since such keys' data is already on the heap; a `uintptr` round-trip that hides it from escape analysis fails `go vet` on the generated code, so it was not used.
- **Measured** (instructions retired, M, `GOMAXPROCS=1`, paired, median of 7; collections and kramdown median of 15, as they move ±5% between runs with GC timing; hello world is 18): hash 96 to 85 (−11.5%, −14% past the floor); json 1,999 to 1,989; kramdown 4,363 to 4,367; liquid 1,950 to 1,956; collections 1,509 to 1,463 in one 15-run set and 1,464 to 1,515 in another (noise: its Hashes are 5–60 keys and a 100k-key Set); spinel's bm_wordfreq 51 to 51 (20 distinct words, 10k lookups: it barely uses a large Hash) and bm_csv_process 5,610 to 5,653 (+0.8%, inside its run spread; its Hashes are small); bm_histogram does not compile (`bm_histogram.rb:19` possibly-nil Integer?, unrelated). Targeted programs: a 60-key `Hash[untyped, untyped]` of mixed Integer/String/Symbol keys, 400k lookups, 255 to 236 (−7%); five 400k-key Integer Hashes kept live plus 200k 3-key Hashes and a 100k-key String Hash, 2,450 to 1,870 (−24%) and max RSS 175 MB to 147 MB; a 100k-name Set and String-keyed tally, 1,722 to 1,600, RSS 27 to 23 MB.
- **Compile cost** (TestCompileCost, compiled functions): 05_word_count 2,014 to 2,029, 64_observable 7,916 to 7,943, 116_cuba_web 30,366 to 30,426 (+0.2–0.7%): `rbHashFind`, `rbHashIndex`, `rbHashRehash` and `rbHashOfAny` compile per key shape that uses them, where the map's code was the runtime's, compiled once.
- **Proof:** `hash_test.rb` `HashIndexTest` (lookups probing past deleted slots and re-inserted keys, 5,000 delete/insert cycles at constant size, `clear` during `each` then reuse, `0.0`/`-0.0` and Float keys, Array (eql?) keys past 8 with deletes, Symbol and String keys) plus decision 350's `HashLayoutTest` and `HashFusedTest`, against MRI.
