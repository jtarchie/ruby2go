# Decision 245

**Rule:** OptionParser is the extended prelude copy (argument-kind constants, `make_switch`, `Switch`, `summary_indent=`), not MRI's optparse.rb.

**Extend the prelude OptionParser for Homebrew's CLI parser, instead of compiling optparse.rb** (#99; 2026-10-13). This was the user's choice: 244's path through MRI's file needed too many dynamic features for what brew uses.
- `OptionParser::NO_ARGUMENT`/`REQUIRED_ARGUMENT`/`OPTIONAL_ARGUMENT`
 (`:NONE`/`:REQUIRED`/`:OPTIONAL`). A literal constant in `on` types
 the block like a `--x X` string (decision 101). At run time,
 `rbOptBuild` reads the Symbol and an `Array` class argument, so a
 runtime-decided switch coerces too.
- `on` with switch strings that are not literals (`*names`, a local)
 stays the untyped `on`. A String first argument no longer selects
 the class twin `__on_string`: OptionParser's on-methods overload by
 switch kind, never by argument class (`optOn`).
- `summary_indent=`, `base.long.delete(name)` (removing the officious
 `--help`/`--version`, recorded in the parser's `off` set),
 `make_switch(opts) -> [Switch]` and `OptionParser::Switch` with
 `short`/`long`/`desc`/`arg` and `summarize` in MRI's layout: what
 Homebrew::CLI::Parser reads to build its help.
- Not covered: completion lists, patterns, `OptionParser::Switch`
 subclasses, and `on` returning the parser for chaining with a switch
 object.
- Build cost: `05_word_count` unchanged (OptionParser loads only on `require "optparse"`).
*See also decision 293:* run-time OPTIONAL_ARGUMENT switches: true when omitted, placed arguments, unboxed values.
