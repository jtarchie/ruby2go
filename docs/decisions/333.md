# Decision 333

**Rule:** Vendored `sig/gems/kramdown` types Element and the HTML converter; each type is what MRI allows across the gem's full testcase corpus.

**Vendored signatures for kramdown** (amends 160, 330; 2026-10-21). `sig/gems/kramdown/kramdown.rbs` types `Kramdown::Element` (`type` a Symbol, `attr` a String-keyed Hash, `options` a Symbol-keyed one, `value` untyped) and `Converter::Html`'s element methods (`convert_*(el, indent)`, `inner`, `format_as_*_html`). The gem ships none, so every `el.type`/`el.attr` was a dynamic call: 1,214 dynamic call sites in a traced kramdown build, 1,009 with the file.
- **What MRI allows decides each type.** `children` is `Array[untyped]`, not `Array[Element]`: `Parser::Kramdown#update_tree` maps children to Arrays and then `flatten!`s them. `format_as_*_html` take `untyped` name and attr: a name is a String or an element's type (a Symbol), and `footnote_content` passes a Symbol-keyed literal where elements pass their String-keyed `attr`. Each wrong guess compiled and then raised TypeError at run time on the path that broke it, so a signature here needs a run over the gem's whole behaviour, not one document.
- **Proof:** kramdown 2.5's own 216 testcases (`test/testcases/**/*.text`, default options), converted by a traced binary with and without the file, match MRI's HTML on the same 126; example 123 and `benchmarks/kramdown.rb` unchanged.
- **Cost and gain:** the benchmark moves 0.459 s → 0.452 s (MRI 0.453 s). Dispatch through the dynamic wrappers was ~5% of the run; the rest is the parser's own work (much of it `send("parse_#{name}")`, which stays a dispatch by name) and the regex engines (decision 332).
- **Found on the way, not fixed here:** the 90 testcases that differ from MRI do so without the file too: `String#scan` with groups on a non-literal Regexp (47), `StringScanner#[]=` missing on `Kramdown::Utils::StringScanner` (30), a dynamic `String#<<` (7), Rouge not installed (3, as under MRI without the gem), and one Range index.

*See also decision 353: a computed send whose name is interpolated between literal text types the parameters of the matching methods.*
