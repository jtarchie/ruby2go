# Decision 385

**Rule:** An Array or Hash of one instantiation passed where a wider one of the same class is expected is a converted copy, and a pattern on a union whose one member answers `deconstruct`/`deconstruct_keys` matches that member statically.

**Decision 150's follow-ups, rechecked** (#123; amends 150; 2026-10-26). Each listed gap was reproduced against main first.
- **`Array[Integer]` into an `Array[Numeric]` parameter** failed `go build` ("cannot use ints (variable of type *Array[Integer]) as *Array[any]"): `fits` is covariant, Go generics are not, and the coercion passed the value as it was. Same class, a fitting element type and another Go type is now `rbAs`'s converted copy, as `Array[Integer]` into `Array[untyped]` already was (decision 22): `Array[Dog]` into `Array[Animal]`, `Hash[String, Integer]` into `Hash[String, Numeric]`. Like that copy, writes the callee makes to it are not seen by the caller's Array (MRI shares it); a parameter the callee mutates should be typed as the caller's instantiation.
- **`case`/`in` on a union** tested the value as untyped: `in [a, b]` on `[Integer, Integer] | String | Hash[Symbol, Integer]` deconstructed through `respond_to?` and made `a + b` a dynamic call. When exactly one member answers the pattern's method (a tuple or Array for `deconstruct`, a class defining it, `deconstruct_keys` likewise), the pattern is a Go type assertion to that member and runs typed on it (`unionShapeMember`). Several answering members (a Struct member also answers `deconstruct`), or a member whose subclass might, stay untyped; so does a union no member of which answers, so the pattern's locals are still declared. `in Integer => n` was already typed by decision 150's `when`-style narrowing.
- **Compile time of nested union arguments** no longer reproduces: decision 150's review pinned the arguments (`pinArgs`), and a 16-deep `x * (y + ...)` of `Integer | Float` values, or the same under a failing `String#+`, compiles in under a second. Nothing changed.
- **Literal mixed elements**: `{a: 1, b: "x"}` then `h[:c] = 1.5` runs as MRI (`Hash[Symbol, untyped]`, and decision 366 widens a written local). Tuples' `nil?`/`size`/`frozen?` answer as MRI's (decisions 227, 241). Nothing changed.
- **Limit kept: a module member** (`Comparable | String`) stays a compile error (`testdata/errors/union.txtar` `module_member`). A type switch cannot test a module, and expanding the module into the closed world's includers would make each call on the union a switch over every includer (Comparable: Integer, Float, String, Time, ... and every user class), each arm compiled; a module type alone is already Go `any`. Annotate the concrete classes (`Integer | String`) instead.
- **Cost:** TestCompileCost compiled functions unchanged (see the report numbers below).
- **Proof:** `union_test.rb` `UnionFollowUpTest` (against MRI: the wider-element arguments, patterns on a union including a find pattern and the NoMatchingPatternError message, 16-deep nested union arithmetic, the mixed literals).
