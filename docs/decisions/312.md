# Decision 312

**Rule:** Template parameter bounds (`generic P < Comparable`) are checked per instance in user code; a gem sig's generic struct class is a template.

**Type-parameter bounds, and gem sigs' generic classes** (#104 phase 5; amends 306, 160, 308, 310; 2026-10-18).
- **Bounds.** `# @rbs generic P < Comparable` and a sig's `class C[P < Comparable[P]]` (`ClassDecl.Bounds`, read by `typeBounds` in `internal/rbs`: the bound's class name, its arguments dropped) bound a template's parameter. Every instance is checked in link, once supers and includes are linked (`checkInstanceBounds`; before link `isSubclassOf` has no ancestors yet): an argument whose class is not a subclass of the bound (modules count through includes, a union through each member, nil and untyped pass) is the compile error "Best[Object]: Object is not a Comparable, the bound of Best's P", at the place the instance was first named (`instAt`, kept across restarts). Gem code is not checked: MRI never checks an RBS bound, and a gem's sig may bound what its callers pass loosely.
- **Gem sigs.** Decision 306's shim (`eraseGemGenerics`) dropped a shipped sig's class type params and every member naming them. A sig-generic struct class is now a template like any (decision 160 already gave it the sig's `TypeParams`), so the shim is kept only for a class whose superclass is a core `@go_type` (a generic Hash subclass is generic over `V` alone, decision 165). Class methods on a generic gem class compile, their sigs seeing the type params as untyped (user code keeps the error).
- **pairing_heap** (example 120, with the gem's shipped `sig/pairing_heap.rbs` loaded): `MinPriorityQueue.new` is open (decision 310) and typed `[String, Integer]` by the later `push(source, 0)`; `MinPriorityQueue[String, Integer]` and `MaxPriorityQueue[String, Integer]` share one `PairingHeap[String, Integer]` parent instance, `SimplePairingHeap.new { |l, r| ... }` (a block is no evidence; the open check now admits it) is typed by `words.push(w)` alone, and `PairingHeap::Node` and `SimplePairingHeap::Node` are helpers (decision 311) instantiated with them.
- **Two fixes it needed.** An omitted argument whose default is an earlier parameter (`def push(elem, priority = elem)`) is evidence for that parameter's type too (`noteTemplateArgs`), so `push(w)` binds `Priority = String`. In gem code, a default that does not fit its parameter in one instance (`priority = elem` in `PairingHeap[String, Integer]`, where Elem is not Priority) is converted at run time (`rbAs`) when it runs, instead of poisoning the method (decision 205).
- **The example changed** where the sig changed its types: `pop_with_priority` is `[Elem, Priority] | [nil, nil]`, so `top = queue.pop_with_priority #: [String, Integer]` is decision 150's "narrow it first" error; it is now `node, d = queue.pop_with_priority` plus `next unless node && d`, MRI's output unchanged.
- **Measured** (example 120): `rbDyn` references 84 → 76, generated funcs 597 → 583; output equals MRI. What stays dynamic is `merge_pairs`' parameter (decision 313) and the `nil`/`{}`-initialized `@root` and `@nodes` (decision 307's nil-initialized ivars).
- **Proof:** example 120; `generic_class_test.rb` `test_bounded_parameter`; `generics.txtar` `bound`; `internal/rbs` `TestParseFileNestedBoundAndMethodAlias` (bounds).
