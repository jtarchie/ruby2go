# Decision 378

**Rule:** A user or gem struct class that is not a leaf (it has subclasses, type parameters or a user module) keeps its values as its Go interface `CI`, and its `C?` is that same `CI` with Go's nil as Ruby's nil: no box, as decision 360 does for a leaf's `*C`.

**Non-leaf `C?` is a nil interface** (amends 360; 2026-10-26; #118). *See also decisions 20, 359, 360, 377.* After decision 360 only a leaf's `C?` was its own Go type; every other struct class's `C?` was `*CI`, a pointer to an interface, so each write of a `C` into a `C?` slot heap-allocated a box (`Ref`) and each read went through it. The pairing_heap gem's `Node[K, V]` is generic, so not a leaf (decision 360 tried making generic instances leaves and hit inference trouble), and its `meld`/`merge_pairs` box a `Node?` on every local and ivar write.
- **Representation.** `leafOpt` now holds for `nilObj` classes: a leaf (`*C`) or `ifaceObj`, a user or gem struct class that is not a leaf and not universal. Its `C?` is `CI` itself, so everything decision 360 routes through `leafOpt` applies unchanged: narrowing, `&.`, `||`, patterns and `derefOpt` take the value as it is, a `C` into a `C?` slot is the value (`coerceToOpt`), an ivar written from untyped is `rbIvarAssignPtr`, a narrowed local stays narrowed (`narrowLeafAssign`). An interface's nil is already a nil `any`, so boxing to untyped is `any(x)` and needs no `rbUnbox` case. The prelude's own classes keep the box, as they are not leaves either: their `%x{}` Go is written against `*CI` (`Module`'s `return &k`).
- **Typed nil.** A leaf's nil `*C` stored in an interface is a non-nil interface. The one place a leaf value meets a superclass's `C?` is a leaf `C?` coerced to its parent's `C?`, which goes through `rbIfaceOf[PI](p)`: nil stays nil. A non-optional leaf value is non-nil in sound code, so its conversion stays implicit (it was a box holding the same typed nil before).
- **Generic boundaries.** The leaf helpers became generic over the nil-holding type, so one path serves `*C` and `CI`: `rbBoxNil[T comparable]` (was `rbBoxPtr`) boxes a `C?` where generic code takes `V?` as Go `*V`, `rbFlatNil` (was `rbFlat` at these sites) opens one, `rbFlatArray`/`rbFlatPair` open `Array[E?]` and `[E?, F?]`, `rbOptNil[T]` (was `rbOptPtr`) converts untyped to `C?`. The nested-optional flatten (`E?` with `E = T?`) uses `rbFlatNil` too, whatever `T?`'s form.
- **`compact` on `Array[C?]`.** The prelude's `@self Array[U?]` overload (`__compact_opt`) wants a box per element (`*Array[*U]`), which a nil-holding `C?` does not have; this already failed to build for a leaf class on main. `xs.compact` of such an array compiles to `rbCompactNil(xs)`, which drops the zero values and returns the `Array[C]` the elements already are. `Lazy#compact`, the other `@self ...[U?]` method, is not covered (ponytail).
- **Measured** (instructions retired, GOMAXPROCS=1, median of 3, against main at 1a50580): pairing_heap 3,206M to 981M (-69%, output == MRI); the other 17 benchmarks within noise (objects, whose `Shape` classes have subclasses, 496M on both in paired runs of 7; collections swings 1.4-1.9G on both). `TestCompileCost` compiled functions 2,014 / 7,730 / 30,296 to 2,014 / 7,730 / 30,289.
- **Proof:** `NilableObjectTest` in `testdata/test/generic_class_test.rb` (a generic class's `C?` through `nil?`, `&.`, `||=`, a `while n` walk and untyped; a subclassed class's `C?` through `&.`, `||=`, a ternary, `Array[C?]#compact` and `count(&:nil?)`; a nil leaf `C?` into its parent's `C?`, and `Hash#[]` of a non-leaf value), against MRI; `TestPairingHeapGemTyped`; the full suite.
