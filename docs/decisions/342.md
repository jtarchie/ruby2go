# Decision 342

**Rule:** `Hash#[]` inlines (miss path in `rbHashLookup`); `Array#map` presizes; `sort_by`/`min_by`/`max_by` resolve the comparator once (`rbCmpFunc`).

**Hot-path costs a hand-written Go port of `benchmarks/` exposed** (amends 151, 5; 2026-10-23). *See also decisions 151, 332, 349* (the String#[] family, the same pattern), *350* (Hash's layout; `[]=` probes the index again), *388* (the index is open-addressed slots). Each benchmark was ported to idiomatic Go by hand (same loops and allocations, output byte-equal to MRI), and rugaroo's binary compared to it by instructions retired. Typed arithmetic and calls were already within 1.1-1.4x (fib, math, regexp, json); the gaps were runtime helpers:
- **`Hash#[]` inlines again.** Its default-value branches had grown it to cost 160 (budget 80), so the `V?` it returns (`&v`) was heap-allocated on every lookup. The miss path moved into the out-of-line `rbHashLookup` (the value, else the default proc's result or default value, else false); `[]` is one call and a nil return, and once inlined the pointer stays on the caller's stack. A default value is now returned as a copy, not `&self.defVal`; codegen only dereferences it.
- **`Hash#[]=` is one map operation.** It probed the map for the key, then assigned. Now it assigns and treats a changed `len` as a new key (recording insertion order, the eql? index, and the during-iteration RuntimeError, which first deletes the key it just added).
- **`Array#map` and `Range#map` size their result** (overrides of Enumerable's, which stays as it was): the Array's length, or an Integer range's count capped at 2^20 so a block that breaks early does not allocate a huge range. `select` is not sized: a guess over-allocates for selective filters. A generic size-hint helper in Enumerable's `map` was tried and cost more compiled functions (a method on every Array/Hash/Range instantiation, or a free function per element type) than the two overrides.
- **Key comparisons in `sort_by`, `sort_by!`, `min_by` and `max_by` resolve the comparator once** (`rbCmpFunc[K]`). A tuple key (`sort_by { [age, name] }`) reached its `Op_cmp` in `rbCmp` only through an interface assertion, which copied the tuple to the heap per comparison; each `TupleN` now has an `rbCmpPair(a, b)` method whose method value takes both by value. `sort`, `min`, `max` keep `rbCmp`: elements are rarely tuples, and using it there cost 166 compiled functions on 116_cuba_web. `rbCmp`'s static fast path gained `Float`. `sort_by!` keeps its keys in a slice, not a `map[int]K`.
Measured (instructions retired, M): hash 274 to 174, array 245 to 200, collections 2,784 to 1,904. Compile cost (TestCompileCost, compiled functions): 05_word_count 1,907 to 1,934, 64_observable 7,589 to 7,592, 116_cuba_web 29,462 to 29,645; the rest is `rbHashLookup` per Hash instantiation that indexes, `rbCmpFunc` per key type, and `rbCmpPair` per tuple instantiation.
