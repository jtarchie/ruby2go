# Decision 332

**Run-time costs the new benchmarks found** (amends 104, 242; 2026-10-21). `benchmarks/` gained eight workloads for features the first seven did not reach: classes with inheritance and Comparable (`objects`), yield/procs/lambdas and enumerator chains (`blocks`), raise/rescue/ensure/retry and catch/throw (`exceptions`), regexp matching, gsub with a block, tr and StringScanner (`regexp`), sort_by/group_by/tally/Set/Struct (`collections`), format/StringIO/case mapping (`format`), JSON generate and parse (`json`) and the liquid gem (`liquid`). Each fix below is in the runtime, not keyed to a benchmark; profiles came from linux/arm64 builds in a container, since darwin's SIGPROF sampling missed most of the main goroutine's time.
- **Goroutine identity without a stack walk (amends 104).** `rbGoID` formatted the whole goroutine stack (`runtime.Stack` writes every frame before it truncates), so its cost grew with depth; `catch`/`throw` paid it twice per pair and Monitor once per `synchronize` (kramdown's block parser throws out of every block). `rbSpawned` is set before the first goroutine that can run Ruby code starts (Thread, Fiber, Ractor, Timeout's worker, a WEBrick handler, a trap hook); until then every caller is main and `rbGoID` returns `rbMainGoID`, read once at package init. An `iter.Pull` coroutine (Enumerator#next) does not set it: it already shared main's registries, since its id had no entry. Once one has started, each goroutine carries its id in its profiler-label slot (`rbGoTag`), which the runtime gives every goroutine, copies into those it starts, and lets linkname users read and write (`runtime/pprof.runtime_getProfLabel`/`runtime_setProfLabel`, kept for them by go.dev/issue/67401). Main tags itself in `rbTrapSignals`; each goroutine that runs Ruby (the ones above, and net/http's connection goroutine per request) tags itself first, with one stack walk; an untagged goroutine inherits its starter's tag, and one with no tag at all (a C thread's callback) still walks the stack. The tag starts with an empty slice of label pairs, the layout of runtime/pprof's label map, so a CPU profile reads it as no labels. A Mutex lock/unlock in a threaded program (`examples/42_queues`) went from a stack walk each to a pointer load: 210M instructions to 23M.
- **regexp2 subjects converted once (amends 242).** The adapter converted the whole subject to runes, plus a rune-to-byte table, on every match: a StringScanner scan over the rest of a document was quadratic. `runesOf` reuses the last conversion when the subject is a suffix of it starting on a rune boundary (the scanner's rest), checked against this pattern's last subject and then any pattern's; an ASCII subject has no byte table (offsets are equal).
- **Compiled patterns shared by text.** `rbRegexpNew` and `rbRegexpLenient` (interpolated and gem patterns built at run time) go through `rbRxCache`, 256 direct-mapped slots by FNV hash of the final pattern: a hit reuses the compiled program and its StringScanner `\A` twin; each call still makes its own Regexp object. Bounded and lock-free; a collision recompiles. A gem pattern (`rbRegexpLenient`, which already raised a failure at first use, decision 176) that RE2 rejects is compiled on regexp2 at its first match (`rxAltLazy`): a gem defines many it never runs, and regexp2's compile of a large Unicode class is the expensive part (two thirds of `examples/123_kramdown`'s run). A strict caller never reuses a lazily compiled cache entry.
- **JSON.** `JSON.parse` first tries a byte-level parser for well-formed input; on anything else (a syntax error, a container past `max_nesting`, a surrogate `\u` escape, invalid UTF-8) it gives up and the `json.Decoder` path reparses, so every error and its message is that path's. The generator's string escaper returns `"` + s + `"` when s has nothing to escape, and a nested container no longer allocates a state it then discards.
- **Sorting.** `sort`, `sort!`, `sort_by`, `sort_by!` and the untyped views' sorts call `rbSortStable`: up to 20 elements `slices.SortStableFunc` itself (an insertion sort, so the same pairs are compared in the same order and a failure names the same pair), beyond that pdqsort with ties broken by position, the same order in O(n log n) instead of SymMerge's O(n log² n). `rbCmp` calls `Op_cmp` statically for Integer and String before the interface assertion, which cost an itab lookup per comparison.
- **Smaller.** `String#to_i` and `Integer()` parse plain decimal digits without a regexp or a map; `upcase`/`downcase`/`capitalize` map ASCII bytes directly and return the receiver's bytes when nothing changes; `tr` looks ASCII up in a table; `File#read` (and `read(nil)`) reads into a `strings.Builder` grown to the file's size, so a large file is one allocation and no `[]byte`-to-String copy; `File.join` of two plain Strings skips the flattening Array; `String#hash` runs FNV-1a inline instead of copying the String into `hash/fnv`; `OpenSSL::PKey::RSA#verify_pss` hashes its input in 32 KB pieces instead of copying it whole (brew verifies its multi-megabyte API payload so). None of these write `unsafe` conversions: gosec reports G103 at main.go's real lines, which a prelude `//nolint` (placed by `//line`) does not reliably cover.
- **Results** (`scripts/benchmark`, median of 5, M-series, MRI 4.0): kramdown 1.49 s → 0.60 s (MRI 0.45), exceptions 0.79 → 0.19 (0.28), json 0.27 → 0.19 (0.14, a C extension in MRI), collections 0.29 → 0.19, regexp 0.57 → 0.40; the rest unchanged within noise. `brew info wget`'s compiled binary, against the same brew built before this decision: ~820M → ~571M instructions retired (−30%; −33% without its `mdfind` and `xcode-select` children, which are the same in MRI), peak RSS 112 → 81 MB, wall 0.204 → 0.187 s median of 18 (MRI's Ruby takes ~0.8 s); what is left is mostly those children and the SHA-512 check of the API payload. The examples, each run under `/usr/bin/time -l` (median of 3): `42_queues` 187M → 24M, `123_kramdown` 698M → 436M, `122_sqlite3` −10%, `116_cuba_web` −7%, `115_rack_server` −4%; all 125 but `61_timeout` (a deliberate two-second busy wait) 4,108M → 3,656M (−11%). About a hundred examples sit at ~20M, which is a bare Go program's start-up on this machine.
- **Third round: allocation, and lookaheads on RE2.** kramdown's allocations fell from 454 MB to ~210 MB a run (30 documents).
   - **Appends.** A gem's `s << x` is `s = s + x` on immutable Strings (136, 330), which copied all of `s` each time: kramdown's converter builds every element's HTML so, quadratically. `String#+` (`rbStrCat`) now writes `x` past the end of `s` when `s` is the whole of a buffer it made: no String over that buffer is longer than `s`, so none sees the new bytes, and none changes. A miss copies into an exactly sized buffer, a second append doubles it, so a build loop is amortized linear. The buffers sit in 16 lock-free slots by address (taken with an atomic swap, so goroutines never share one), which keeps a nested builder (a recursive call's own result) from evicting its caller's. Strings under 64 bytes keep Go's concatenation. Ponytail: a slot keeps its last buffer alive until reused.
   - **Reflection by name.** `_Consts` and `_Ivars` built the whole table, a slice literal of every constant or ivar, on each `const_get` (`self.class::X`, 330) and gem ivar read by name (`rbIvarGet`, 330). Each now takes a name: `""` is the whole table, any other name one entry from a `switch`; no new functions are emitted.
   - **Smaller.** `String#[start, len]` walks to the byte offsets instead of converting the String to runes; a Hash makes its Go map at its first insert (`{}` costs none); `rbArity`'s failure is out of line, so the check inlines into each Dyn wrapper.
   - **Lookaheads on RE2.** A pattern that is one lookahead, `(?=X)`, finds its first match with RE2 on X (`rxAhead`): that is X's leftmost-first start, with X's groups; a lookahead ending one of X's branches becomes a plain group (it is atomic and nothing follows it, so consuming it changes nothing). Every-match uses (`gsub`, `scan`) stay on regexp2. kramdown's span-start pattern had been 13% of its run.
   - **Long anchored matches** (*see also decision 347*: the threshold is now 8,192 bytes). A StringScanner anchored match on 256 bytes or more goes through RE2's reader interface (NFA or one-pass, cost by the match) instead of its backtracker, which clears a bitmap of program size × input length on every call. regexp2's subject cache keeps four recent long subjects, not one: kramdown runs a scanner per paragraph inside the one over the document.
   - kramdown: 0.61 s → 0.47 s, level with MRI (0.47 s).
- **Cost.** TestCompileCost: 05_word_count +26 compiled functions (1.8%: the static `Op_cmp` arms and `rbSortStable`), 64_observable +14, 116_cuba_web +70 (0.2%).
- **Proof:** the suite unchanged (minitest, run, errors, examples); JSON error messages for 20 malformed inputs identical before and after; compiled `brew info wget`, `info --json=v2 wget` and `info jq` equal MRI.
- **Left.** pairing_heap's cost is gem module methods with untyped parameters (`MergePairs#meld(left, right)` shared by two Node classes), so every attribute read goes through a dispatcher and boxes; that is inference work. json's generator builds a String per nested value, as the `to_json` protocol does. *(See also decision 346: it no longer does for core values.)*
